# 一、今天到底要学会什么

“会背技术栈”不等于“理解架构”。

> 项目使用 Vue、Spring Boot、MySQL、Redis、Nginx 和 Cloudflare。

真正理解，至少要对每个组件回答四个问题：

1. 它是什么？
2. 它在 OrangeVC 的哪个位置？
3. 它解决了什么问题？
4. 如果不用它，系统会发生什么变化？

# 二、访问一个网站时，最基础的概念是什么

## 2.1 客户端和服务器

### 客户端是什么

客户端是主动发起请求的一方。

在 OrangeVC 中，最常见的客户端是：

- Chrome、Edge 等浏览器；
- Vue 页面中的 Axios；
- Agent 设备；
- 管理后台；
- 支付平台回调程序。

### 服务器是什么

服务器是持续运行、等待请求并返回结果的计算机或程序。

“服务器”可能指两件事：

1. 一台 Linux 主机；
2. 主机上运行的 Spring Boot、Nginx、MySQL 等服务进程。

OrangeVC 的后端程序运行在 Linux 服务器上，由 Spring Boot 接收业务请求。

## 2.2 域名、IP 地址和 DNS

### IP 地址是什么

IP 地址可以理解为一台网络主机的地址，例如：

```text
47.xxx.xxx.xxx
```

浏览器最终需要知道把数据发到哪个 IP。

### 域名是什么

域名是方便人记忆的名称。OrangeVC 的规范域名是：

```text
orangevf.com
```

### DNS 是什么

DNS 可以类比为互联网电话簿，它负责把：

```text
orangevf.com
```

转换为可访问的网络地址。

OrangeVC 将域名接入 Cloudflare。开启 Cloudflare 代理后，普通访问者通常先得到 Cloudflare 的边缘地址，由 Cloudflare 再代理到源站服务器。

注意：Cloudflare 代理能减少源站直接暴露，但不能仅凭“开启代理”就保证源站绝对不会通过其他渠道泄露。

## 2.3 端口是什么

一台服务器可以同时运行很多服务。端口用于区分请求应该交给哪个程序。

常见端口如下：

| 端口 | 常见用途 | OrangeVC 中的含义 |
|---:|---|---|
| 80 | HTTP | Nginx 接收后跳转 HTTPS |
| 443 | HTTPS | Nginx 的公开加密入口 |
| 8080 | Web 应用 | Spring Boot 业务端口，只监听本机 |
| 8081 | 管理端口 | Actuator 等管理能力，只监听本机 |
| 3306 | MySQL | 数据库端口，只监听本机 |
| 6379 | Redis 常用端口 | Redis 内部服务端口，不应公开暴露 |

为什么 Spring Boot 不直接暴露 8080 给用户？

因为公开入口统一交给 Nginx，可以集中处理 HTTPS、域名、限流、静态资源和代理规则。Spring Boot 只在本机监听，减少了直接暴露面。

## 2.4 HTTP 是什么

HTTP 是浏览器和服务器交换数据的一套规则，也就是协议。

一次 HTTP 请求通常包含：

```text
请求方法：GET / POST / PUT / DELETE
请求地址：/api/app/trend/analyze-v2
请求头：Token、Content-Type、Request-Id 等
请求体：用户输入的 JSON 数据
```

服务器返回：

```text
状态码：200、400、401、500 等
响应头：Content-Type、X-Request-Id 等
响应体：JSON、HTML、图片或其他数据
```

### 常见请求方法

- `GET`：读取数据；
- `POST`：创建资源或执行操作；
- `PUT/PATCH`：更新数据；
- `DELETE`：删除数据。

方法名表达语义，但系统是否安全不能只依赖方法名，仍需要鉴权、参数校验和业务校验。

## 2.5 HTTPS 是什么

HTTPS 可以简单理解为：

```text
HTTP + TLS 加密和身份校验
```

它主要解决：

1. 机密性：中间人不容易直接看到密码、Token 和请求内容；
2. 完整性：传输内容不容易被无声篡改；
3. 身份校验：证书帮助浏览器确认正在访问目标域名。

OrangeVC 的外部链路是：

```text
浏览器 ←HTTPS→ Cloudflare ←HTTPS→ Nginx
```

Cloudflare 使用 `Full (strict)` 模式，表示 Cloudflare 到源站 Nginx 的连接也要加密并校验证书。

## 2.6 API 和 JSON 是什么

### API

API 是程序对外提供的调用接口。

例如：

```text
POST /api/app/trend/analyze-v2
```

含义可以理解为：让用户端请求平台执行一次 V2 趋势与项目分析。

### JSON

JSON 是前后端交换结构化数据的常见格式：

```json
{
  "topics": ["AI Agent"],
  "purpose": "求职",
  "languages": ["Java", "Python"],
  "useRag": true
}
```

Vue 把表单数据组织为 JSON，Spring Boot 将 JSON 转换为 Java 对象；返回时再把 Java 结果转换成 JSON。

# 三、Cloudflare 是什么，为什么使用

## 3.1 Cloudflare 是什么

Cloudflare 是位于用户和源站服务器之间的网络平台，可以提供 DNS、代理、TLS、安全防护等能力。

它不是 OrangeVC 的业务后端，也不负责执行 Java 业务代码。

位置是：

```text
用户浏览器 → Cloudflare → OrangeVC 源站 Nginx
```

## 3.2 OrangeVC 中 Cloudflare 的主要作用

### 作用一：DNS 管理

Cloudflare 管理 `orangevf.com` 应该被解析和代理到哪里。

### 作用二：反向代理源站

开启橙色云代理后，浏览器先连接 Cloudflare，再由 Cloudflare 连接 OrangeVC 源站。

### 作用三：边缘 HTTPS

Cloudflare 向浏览器提供 HTTPS 入口，源站 Nginx 同样部署源站证书。

### 作用四：边缘安全能力

Cloudflare 可以提供流量过滤、基础攻击防护等能力。OrangeVC 还使用 Cloudflare Turnstile 处理注册等场景的人机验证。

## 3.3 为什么不只使用 Nginx

只使用 Nginx 也能提供网站，但域名解析、边缘代理和边缘安全仍需另外解决。

Cloudflare 和 Nginx 分工如下：

| 组件 | 所在位置 | 主要职责 |
|---|---|---|
| Cloudflare | 公网边缘 | DNS、代理、边缘 TLS、安全能力 |
| Nginx | OrangeVC 源站 | 静态资源、应用路由、反向代理、源站限流 |

它们不是重复关系，而是边缘层和源站接入层的关系。

## 3.4 如果没有 Cloudflare

网站仍可通过“域名直接解析到服务器 + Nginx”运行，但需要自己更多地处理：

- DNS 与证书管理；
- 源站直接暴露；
- 边缘安全；
- 全球或跨地区访问优化。

因此 Cloudflare 是增强项，不是 Java 业务运行的必要条件。

# 四、Nginx 是什么，为什么使用

## 4.1 Nginx 是什么

Nginx 是高性能 Web 服务器和反向代理服务器。

“Web 服务器”表示它能直接返回 HTML、JavaScript、CSS、图片等文件。

“反向代理”表示用户请求 Nginx，Nginx 再把请求转发给内部 Spring Boot，用户不需要知道真实内部端口。

## 4.2 正向代理和反向代理的区别

### 正向代理

代理代表客户端去访问外部网络：

```text
客户端 → 代理 → 外部网站
```

外部网站不一定知道真实客户端。

### 反向代理

代理代表服务端接收外部请求：

```text
用户 → Nginx → 内部 Spring Boot
```

用户不需要知道内部服务结构。

OrangeVC 使用的是反向代理。

## 4.3 OrangeVC 中 Nginx 的职责

### 返回用户端静态资源

访问：

```text
https://orangevf.com/
```

Nginx 从下面的目录返回用户端资源：

```text
/data/orangejd/web-dist/
```

### 返回管理端静态资源

访问：

```text
https://orangevf.com/admin/
```

Nginx 返回：

```text
/data/orangejd/web-dist/admin/
```

### 转发 API

浏览器请求：

```text
/api/app/trend/analyze-v2
```

Nginx 转发到本机：

```text
http://127.0.0.1:8080/app/trend/analyze-v2
```

因为 `proxy_pass` 以 `/` 结尾，这里的通用 `/api/` 前缀会被去掉。

### 转发 WebSocket

访问 `/ws/` 时，Nginx保留协议升级请求头，把普通 HTTP 连接升级为 WebSocket 长连接。

### 入口限流

Nginx 对普通 API 和登录接口设置不同限流。例如登录接口应比普通读取接口更严格，以降低暴力尝试风险。

### 静态资源缓存

Vite 构建后的资源文件名包含内容哈希，例如：

```text
index-a81f3c.js
```

内容变化时文件名也变化，因此这类资源可以设置较长缓存；HTML 不能简单长期缓存，否则可能仍引用旧资源。

## 4.4 为什么不让 Spring Boot 返回所有前端文件

Spring Boot 也可以返回静态资源，但 Nginx 更适合：

- 高效传输静态文件；
- 配置缓存；
- 处理域名和证书；
- 统一反向代理；
- 处理 WebSocket；
- 在应用前做入口限流。

这样 Spring Boot 可以集中处理业务逻辑。

## 4.5 OrangeVC 的真实配置入口

Nginx 模板见：

`D:\Orangejd\nginx.conf`

重点位置：

- 管理端路由：第 53 行附近；
- 用户端路由：第 98 行附近；
- `/api/` 代理：第 104 行附近；
- `/ws/` 代理：第 145 行附近；
- 健康接口限制：第 163 行附近。

# 五、Vue、SPA、Vite、Pinia 和 Element Plus 是什么

## 5.1 Vue 是什么

Vue 是构建浏览器界面的 JavaScript 框架。

它帮助开发者把页面拆成组件，并根据状态自动更新页面。例如：

```text
用户修改技术方向
→ Vue状态变化
→ 页面自动显示新的选择
```

Vue 不直接访问数据库。它通过 HTTP API 调用 Spring Boot。

## 5.2 SPA 是什么

SPA 是 Single Page Application，即单页应用。

传统网站可能每切换一个页面都由服务器重新返回完整 HTML；SPA 首次加载一个 HTML 和 JavaScript 应用，之后很多页面切换由浏览器中的路由和组件完成。

优点：

- 页面切换流畅；
- 前后端职责清晰；
- 组件容易复用。

代价：

- 首次需要加载应用脚本；
- Nginx 需要配置路由回退；
- 前端状态、权限和缓存管理更复杂。

## 5.3 为什么是双 SPA

OrangeVC 有：

- `orange-web`：普通用户端；
- `orange-admin`：管理后台。

分开的原因是用户、权限、页面、构建和发布风险不同。生产上仍可由同一个 Nginx 提供，不等于必须使用两台服务器。

## 5.4 Vite 是什么

Vite 是前端开发和构建工具。

开发阶段，它提供快速启动与热更新；发布阶段，它把 Vue、JavaScript、CSS 等内容构建成浏览器可加载的静态文件。

所以生产服务器上不是让 Vite 开发服务长期运行，而是让 Nginx 返回 Vite 构建结果。

## 5.5 Pinia 是什么

Pinia 是 Vue 的状态管理工具。

“状态”指页面需要记住的数据，例如：

- 当前用户；
- 登录状态；
- 跨页面共享的画像信息；
- 全局展示状态。

如果数据只在一个组件内部使用，可以放在组件中；多个页面共同需要时，放在 Pinia Store 更合适。

Pinia 状态主要存在浏览器中，不能代替 MySQL 持久化。

## 5.6 Element Plus 是什么

Element Plus 是 Vue 组件库，提供按钮、表格、表单、对话框、分页等通用 UI 组件。

使用它的原因是减少重复编写基础交互，并保持界面一致性。它不负责业务逻辑和后端处理。

# 六、Spring Boot 是什么，为什么使用

## 6.1 先理解 Java、JVM 和 Spring

### Java

Java 是编程语言。OrangeVC 后端业务主要使用 Java 编写。

### JVM

JVM 是 Java Virtual Machine，即 Java 虚拟机。Java 编译后的程序运行在 JVM 上。

启动命令中的：

```text
java -jar orange-server.jar
```

表示启动 JVM 并运行这个 JAR 应用。

### Spring

Spring 是 Java 生态中的应用框架，核心能力包括：

- 依赖注入；
- Web 请求处理；
- 数据库事务；
- 配置管理；
- 组件生命周期；
- 与各种中间件集成。

## 6.2 Spring Boot 是什么

Spring Boot 是基于 Spring 的快速应用构建方式。

它帮助开发者：

- 使用合理的默认配置；
- 自动配置常用组件；
- 通过 Starter 引入能力；
- 把应用打包成可直接运行的 JAR；
- 使用内嵌 Web 服务器接收请求；
- 使用不同 profile 管理开发和生产配置。

OrangeVC 生产启动时使用：

```text
--spring.profiles.active=prod
```

表示加载生产环境配置。

## 6.3 依赖注入是什么

假设 `TrendAnalysisService` 需要调用 `AiToolRouter`。

不使用依赖注入时，它可能自己创建对象：

```text
new AiToolRouter(...)
```

这样对象依赖、配置和测试会变得混乱。

使用 Spring 后，组件声明自己需要什么，Spring 容器统一创建对象并注入依赖。

好处是：

- 降低组件耦合；
- 配置集中；
- 更容易替换实现；
- 单元测试可注入模拟对象。

## 6.4 Controller、Service、Mapper 分别是什么

### Controller：HTTP 接入层

职责：

- 接收路径和参数；
- 获取当前登录上下文；
- 调用 Service；
- 返回统一响应。

Controller 不应堆积复杂业务规则。

### Service：业务层

职责：

- 执行业务规则；
- 组织多个步骤；
- 确定事务边界；
- 调用 Mapper、Redis 和外部服务。

例如项目推荐不是 Controller 直接访问模型，而是由多个 Service 和基础设施组件协作完成。

### Mapper：数据访问层

Mapper 负责执行数据库查询和写入。

OrangeVC 使用 MyBatis 将 Java 方法和 SQL 数据访问关联起来。

### 为什么要分层

如果 Controller 同时负责参数、SQL、缓存和模型重试：

- 类会越来越大；
- 测试困难；
- 业务复用困难；
- 事务边界不清晰；
- 更换接口形式会影响所有逻辑。

分层让每一层只承担相对稳定的职责。

## 6.5 模块化单体是什么

### 单体

OrangeVC 的业务后端最终部署成一个 JAR，因此物理上是单体应用。

### 模块化

代码没有全部混在一起，而是按照用户、内容、知识库、AI任务、项目推荐和 Agent 等领域拆分。

Maven 层面主要包括：

```text
orange-server：业务实现和应用启动
orange-common：Result、JWT、上下文、公共工具
orange-pojo：Entity、DTO、VO
```

### 为什么当前不用微服务

微服务会增加：

- 服务注册与发现；
- 服务间网络调用；
- 分布式日志；
- 分布式事务；
- 多服务部署；
- 故障排查复杂度。

对于当前个人开发和业务规模，模块化单体更容易保证事务一致性、开发效率和部署可靠性。

正确表述：

> 当前选择模块化单体，不是因为不知道微服务，而是因为现阶段独立部署和分布式治理成本大于收益；代码已经按领域划分，未来可以根据独立扩缩容需求拆分。

# 七、MyBatis 是什么

MyBatis 是 Java 数据访问框架。

它主要帮助完成：

```text
Java方法调用
    ↓
执行SQL
    ↓
把查询结果转换为Java对象
```

例如：

```text
根据用户ID查询历史记录
根据状态查询已发布项目
插入一次任务执行记录
更新订单状态
```

为什么使用 MyBatis：

- SQL 可控，适合复杂查询；
- Java 对象映射清晰；
- 易于结合现有数据库表；
- 与 Spring 事务集成。

MyBatis 不是数据库，真正保存数据的是 MySQL；MyBatis 是 Java 访问 MySQL 的工具。

# 八、MySQL 是什么，为什么使用

## 8.1 MySQL 是什么

MySQL 是关系型数据库管理系统。

它将数据组织成表。例如：

```text
account 用户表
work 作品表
order 订单表
trend_history 趋势分析历史表
beginner_project 新手项目表
career_project 职业项目表
system_task 系统任务表
```

表通过主键、外键或业务字段建立关系。

## 8.2 什么是关系型

假设：

- 用户表中有用户；
- 订单表中有订单；
- 订单通过 `account_id` 与用户关联。

这种结构化的表和关系适合：

- 精确查询；
- 排序和分页；
- 聚合统计；
- 约束数据一致性；
- 多表关联。

## 8.3 事务是什么

事务是一组要么全部成功、要么全部失败的操作。

例如购买服务时：

```text
创建订单
扣减余额
记录余额流水
改变业务状态
```

如果只扣余额但订单创建失败，数据就不一致。事务能够在中途失败时回滚已经执行的数据库修改。

常见 ACID 含义：

- 原子性：全部成功或全部失败；
- 一致性：操作前后遵守数据规则；
- 隔离性：并发事务互相影响受控；
- 持久性：提交后数据不会因普通进程重启消失。

## 8.4 索引是什么

索引类似书的目录，帮助数据库快速定位数据。

例如按：

- 用户 ID；
- 订单号；
- 任务状态；
- GitHub 项目业务键；

进行高频查询时，可以建立适当索引。

索引不是越多越好，因为索引也占空间，并增加写入和更新成本。

## 8.5 OrangeVC 为什么使用 MySQL

OrangeVC 中大量数据具有明确结构，并需要事务、一致性和长期保存，例如：

- 用户账号；
- 作品、需求和投稿；
- 订单和支付状态；
- 配额账本；
- 项目评分和发布状态；
- 任务执行记录；
- 知识库文档元数据；
- AI 历史结果。

这些数据不能只放在浏览器或 Redis 中。

## 8.6 为什么 MySQL 只监听本机

当前 Spring Boot 与 MySQL 在同一主机，外部用户不需要访问 3306。

因此 MySQL 只监听：

```text
127.0.0.1:3306
```

这意味着只有服务器本机程序可以直接访问数据库，减少公网攻击面。

## 8.7 MySQL 的当前边界

应用、MySQL 和部分基础设施仍集中在同一服务器，部署简单但存在主机级单点风险。

正确理解：

- 适合当前成本和规模；
- 必须做好备份和恢复演练；
- 访问量和可靠性要求提升后，可迁移到独立或托管数据库。

# 九、Redis 和 Redis Stack 是什么，为什么使用

## 9.1 Redis 是什么

Redis 是高性能内存数据存储系统。

“内存”表示主要数据访问发生在 RAM 中，因此读写通常很快。

Redis 不只是简单字符串，还支持：

- String；
- Hash；
- List；
- Set；
- Sorted Set；
- 带过期时间的 Key；
- Lua 原子脚本等。

## 9.2 Redis 和 MySQL 的根本区别

| 对比 | MySQL | Redis |
|---|---|---|
| 主要定位 | 业务事实数据库 | 高速状态与数据结构服务 |
| 典型存储 | 表和行 | Key-Value及多种数据结构 |
| 事务与关系 | 强 | 不以复杂关系查询为主要目标 |
| 访问速度 | 快，但通常需要磁盘与SQL处理 | 内存访问通常更快 |
| 典型用途 | 用户、订单、账本、任务 | 缓存、限流、租约、短期状态 |

不能简单地说“Redis 比 MySQL 快，所以把所有数据放 Redis”。

业务事实仍应以 MySQL 等持久化数据库为准；Redis 更适合辅助加速和协调。

## 9.3 缓存是什么

缓存是将常用或计算成本高的数据临时保存在更快的位置。

例如：

```text
第一次：查询MySQL → 放入Redis
后续：直接读取Redis
```

这样可以减少数据库压力和响应时间。

缓存必须考虑：

- 过期时间；
- 数据更新后的失效；
- 缓存不存在时如何回源；
- Redis 故障时如何降级。

## 9.4 TTL 是什么

TTL 是 Time To Live，即一个 Key 的剩余生存时间。

例如租约设置 60 秒 TTL：

```text
任务异常退出
→ 没有主动释放租约
→ 60秒后Key自动过期
```

TTL 可以降低永久死锁和垃圾状态风险，但长任务需要续租，避免任务仍在执行时租约提前失效。

## 9.5 限流是什么

限流控制一段时间内允许多少请求。

目的包括：

- 防止恶意刷接口；
- 避免模型费用失控；
- 保护数据库和线程池；
- 让系统在高负载时有明确边界。

OrangeVC 同时有：

- Nginx 的 IP 入口限流；
- 应用层基于 Redis 的用户或业务限流。

## 9.6 租约是什么

租约可以理解为“带有效期的使用权”。

例如 AI 任务开始前获取一个并发名额：

```text
获得租约 → 执行任务 → 定期续租 → 完成后释放
```

如果进程异常退出，租约最终会因 TTL 过期，避免名额永久被占用。

## 9.7 Redis Stack 和 RediSearch 是什么

Redis Stack 在 Redis 基础上增加搜索、JSON、向量检索等扩展能力。OrangeVC 使用 Redis 与 RediSearch 承载向量索引。

普通 Redis Key 更适合精确访问：

```text
已知 key → 读取 value
```

向量检索更适合：

```text
给定一个问题向量 → 找到语义最相近的文档向量
```

这里先记住 Redis Stack 同时承担两类职责：

1. 运行治理：缓存、限流、租约、动态配置；
2. 知识检索：文档向量和检索 metadata。

RAG 的向量、Embedding 和 HNSW 原理属于后续学习内容，第 1 天不展开。

## 9.8 为什么使用 Redis

如果所有临时状态和高频协调都写 MySQL：

- 限流计数会产生大量数据库写入；
- TTL 过期处理更麻烦；
- 分布式并发名额竞争成本更高；
- 缓存无法有效降低数据库压力；
- 向量检索还需要其他专用能力。

Redis 的数据结构、TTL、Lua 和 RediSearch 正好适合这些场景。

## 9.9 当前使用 Redis 的风险

Redis 同时承担缓存、限流、租约、动态配置和向量检索，部署简单，但故障影响面较大。

未来可以根据容量和可靠性需求拆成：

- 运行状态 Redis；
- 向量检索 Redis；
- 独立备份与监控策略。

# 十、WebSocket 是什么

## 10.1 普通 HTTP

普通 HTTP 的典型过程：

```text
客户端发一次请求
服务器返回一次响应
本次交互完成
```

如果前端想知道任务有没有更新，只能再次请求，也就是轮询。

## 10.2 WebSocket

WebSocket 在最初通过 HTTP 建立连接，协议升级后保持长连接，客户端和服务器都可以主动发送消息。

适合：

- 私信或即时消息；
- AI 长任务进度；
- Agent 设备状态；
- 实时任务反馈。

## 10.3 为什么 Nginx 要特殊配置

WebSocket 不是普通的一问一答。Nginx需要转发：

```text
Upgrade: websocket
Connection: upgrade
```

并设置较长读取超时，否则长连接可能被提前断开。

# 十一、鉴权、CORS、限流和 Request ID 是什么

## 11.1 鉴权

鉴权回答：

> 这个请求是谁发出的，它是否有权执行当前操作？

OrangeVC 有三类通道：

| 请求路径 | 凭证 |
|---|---|
| `/app/**` | `App-Token` |
| `/admin/**` | `Admin-Token` |
| `/agent/**` | Bearer Device Token |

不能因为前端隐藏了按钮，就认为用户没有权限。攻击者可以绕过页面直接构造 HTTP 请求，所以后端必须校验。

## 11.2 CORS

CORS 是浏览器的跨源访问控制机制。

“源”通常由协议、域名和端口组成。生产后端应该只允许明确的 HTTPS 前端来源，而不是任意来源。

CORS 主要约束浏览器，并不能代替 Token 鉴权。

## 11.3 限流

限流不是为了让正常用户变慢，而是为了让有限资源在异常流量下仍保持可控。

例如：

- 登录接口防止密码爆破；
- AI 接口防止额度失控；
- 上传接口防止资源耗尽。

## 11.4 Request ID

Request ID 是一次请求的唯一追踪标识。

流程可以是：

```text
请求进入
→ RequestIdInterceptor生成ID
→ ID写入MDC日志上下文
→ 后续日志自动携带ID
→ X-Request-Id响应给前端
```

当用户报告错误时，可以按 Request ID 定位整条调用日志。

## 11.5 全局异常处理

后端可能发生：

- 参数错误；
- 未登录；
- 业务条件不满足；
- 数据库异常；
- 外部模型超时；
- 未知程序错误。

全局异常处理器把这些异常转换为稳定的响应结构，避免每个 Controller 重复写异常处理，也避免直接把内部堆栈暴露给用户。

# 十二、一次普通 API 请求的完整链路

假设用户查询自己的趋势分析历史。

## 12.1 浏览器发起请求

Vue 页面通过 Axios 发出 HTTPS 请求，携带用户 Token。

```text
GET https://orangevf.com/api/app/trend/history
```

## 12.2 Cloudflare 接收

Cloudflare 根据域名配置接收请求，并通过加密连接转发到源站服务器。

## 12.3 Nginx 路由

Nginx发现路径以 `/api/` 开头，于是：

- 执行入口限流；
- 添加真实 IP、协议等代理头；
- 将请求转发到 `127.0.0.1:8080`；
- 通用代理会去掉 `/api` 前缀。

Spring Boot 收到：

```text
GET /app/trend/history
```

## 12.4 Spring 拦截器链

请求依次经过：

```text
CORS
→ RequestIdInterceptor
→ RateLimitInterceptor
→ App鉴权拦截器
```

如果 Token 无效，请求在进入业务 Controller 前就被拒绝。

## 12.5 Controller

`AppTrendController` 接收参数，获得当前用户上下文，调用对应 Service。

## 12.6 Service

Service 检查业务条件并调用 Mapper。

## 12.7 Mapper 与 MySQL

MyBatis Mapper 执行 SQL，从趋势历史表中查询当前用户的记录。

## 12.8 返回

结果按下面方向返回：

```text
MySQL
→ Mapper
→ Service
→ Controller
→ Result<T>
→ Spring Boot
→ Nginx
→ Cloudflare
→ Axios
→ Vue页面
```

Vue 将 JSON 转换成列表并显示给用户。

# 十四、systemd 是什么，为什么使用

## 14.1 进程是什么

运行中的 Java 应用是一个操作系统进程。

如果只在 SSH 终端手工执行：

```text
java -jar orange-server.jar
```

会遇到：

- 终端断开后的生命周期问题；
- 服务器重启后不会自动启动；
- 崩溃后不会自动恢复；
- 日志和权限管理不统一。

## 14.2 systemd 是什么

systemd 是 Linux 常见的系统与服务管理器。

OrangeVC 使用：

```text
orangejd.service
```

管理 Spring Boot。

它负责：

- 开机启动；
- 启动和停止；
- 失败重启；
- 服务状态查看；
- 日志接入 Journal；
- 加载环境变量；
- 限制进程权限和可写目录。

## 14.3 为什么不用 root 运行

如果应用存在漏洞，以 root 运行可能让漏洞获得过大的系统权限。

生产服务使用受限用户运行，并启用：

- `NoNewPrivileges`；
- `PrivateTmp`；
- 受限写目录。

这属于最小权限原则：程序只获得完成任务所需的权限。

## 14.4 JVM 内存参数

当前启动参数大致包括：

```text
-Xms512m
-Xmx2048m
-XX:MaxMetaspaceSize=384m
```

可以初步理解为：

- `Xms`：初始堆内存；
- `Xmx`：最大堆内存；
- `MaxMetaspaceSize`：类元数据空间上限。

设置上限可以防止 Java 无限制使用内存，但参数需要根据真实运行指标调整，不能只凭经验永久固定。

# 十五、环境变量和密钥管理是什么

生产环境需要：

- MySQL 密码；
- Redis 密码；
- AI API Key；
- OSS 密钥；
- 邮件配置；
- 加密密钥。

这些内容不能直接写进 Git 仓库。

OrangeVC 将生产环境变量放在：

```text
/etc/orangejd/orangejd.env
```

由 systemd 启动服务时读取。

代码仓库可以保存配置名称和占位符，但不能保存真实密钥。

这样做的意义：

- 避免 Git 历史泄露密钥；
- 开发、测试、生产可以使用不同配置；
- 更换密钥时不需要修改业务代码。

# 十六、构建、部署、发布和回滚分别是什么

## 16.1 构建

构建是把源代码转换为可运行制品。

OrangeVC 构建包括：

- Maven 编译和测试后端；
- 打包 Spring Boot JAR；
- 构建用户端 Vue；
- 构建管理端 Vue；
- 合并两个前端产物；
- 校验 HTML 引用的 JS/CSS 是否存在；
- 生成 Git SHA 和文件哈希。

## 16.2 部署

部署是把构建好的制品放到生产服务器正确位置，并配置运行环境。

主要制品：

```text
/data/orangejd/orange-server.jar
/data/orangejd/web-dist/
/data/orangejd/web-dist/admin/
Nginx配置
```

## 16.3 发布

发布强调让新版本开始对用户提供服务，包括：

- 切换制品；
- 重启后端；
- 重新加载 Nginx；
- 检查健康状态；
- 验证页面和 API。

## 16.4 回滚

回滚是在新版本失败时恢复旧版本。

OrangeVC 安装脚本会先备份：

- 旧 JAR；
- 旧前端；
- 旧 Nginx 配置。

然后校验候选 Nginx 配置，再切换文件和重启服务。如果健康检查或关键验收失败，就恢复备份。

## 16.5 为什么不能手工只复制一个 dist

双 SPA 共享 Web 根目录。如果只覆盖某个目录，可能出现：

- 用户端覆盖管理端；

- 旧 HTML 与新 JS 不匹配；
- 部分文件来自新版本，部分来自旧版本。

所以需要统一发布包和安装脚本。

真实脚本：

- `D:\Orangejd\scripts\build-release.sh`
- `D:\Orangejd\scripts\install-release.sh`

# 十七、健康检查和可观测性是什么

## 17.1 进程活着不等于业务正常

Java 进程存在，只能说明进程没有退出，不能证明：

- MySQL 能查询；
- Redis 能访问；
- 向量库正常；
- 外部模型正常；
- 定时任务持续成功。

因此需要分层健康信号。

## 17.2 OrangeVC 的健康入口

主要包括：

```text
/health
/health/detail
/actuator/health
/actuator/prometheus
systemd Journal
```

详细接口应限制在本机，避免暴露内部依赖和配置状态。

## 17.3 日志

日志用于记录：

- 请求入口；
- 业务结果；
- 外部调用；
- 错误类型；
- 任务状态；
- Request ID。

排障时不能只看一句“失败”，应沿请求 ID 判断故障发生在：

```text
Cloudflare/Nginx
→ 鉴权与限流
→ Controller/Service
→ MySQL/Redis
→ 外部供应商
```

## 17.4 健康检查与监控的区别

- 健康检查：当前是否可以工作；
- 监控指标：一段时间内工作得怎么样；
- 日志：具体发生了什么；
- 告警：达到异常条件时通知维护者。

完整运维不能只依赖其中一个。

# 十八、为什么平台采用当前架构

## 18.1 双 SPA

原因：用户端与管理端权限、路由和功能不同；分开构建可以降低互相影响。

## 18.2 Cloudflare + Nginx

原因：Cloudflare处理公网边缘，Nginx处理源站接入；两层职责不同。

## 18.3 Spring Boot 模块化单体

原因：适合当前团队和业务规模，部署简单，事务清晰，同时通过领域拆分保持代码边界。

## 18.4 MySQL

原因：业务数据结构明确，需要事务、约束、查询和长期持久化。

## 18.5 Redis Stack

原因：缓存、TTL、限流、租约和向量检索需要高性能数据结构和搜索能力。

## 18.6 Nginx提供静态文件

原因：静态资源传输、缓存、HTTPS和反向代理更适合统一放在 Nginx。

## 18.7 systemd

原因：应用需要开机启动、失败恢复、日志、权限和统一生命周期管理。

这套选择的总体原则是：

> 在当前规模下优先保证可理解、可部署、可恢复和事务清晰，同时为未来扩展保留明确边界。

# 十九、当前架构的真实不足

面试中主动说明边界，比把项目说成完美系统更可信。

## 19.1 单机故障域

应用、MySQL 和部分基础设施仍集中在同一服务器。服务器整体故障时，多个组件可能同时不可用。

改进方向：

- 定期恢复演练；
- 独立或托管 MySQL；
- 多实例 Spring Boot；
- Nginx upstream 和负载均衡。

## 19.2 Redis 职责较多

Redis 同时承担缓存、限流、租约、动态配置和向量检索，故障影响面较大。

改进方向：按运行状态与向量检索拆实例，分别监控容量和延迟。

## 19.3 应用仍未完全无状态化

多实例部署前，需要确认本地文件、内存状态、调度任务和 WebSocket 会话如何处理。

## 19.4 管理端测试相对较少

当前管理端自动化测试数量低于用户端，应继续补登录、分页、审核和配置流程测试。

## 19.5 容量数字需要谨慎

代码允许的并发上限不等于经过真实长耗时请求验证的稳定吞吐。生产容量需要持续压测并观察：

- 成功率；
- P95/P99 延迟；
- 429；
- 超时；
- 数据库连接；
- Redis 延迟；
- 外部模型速率；
- 结果保存率。

# 二十、两分钟不看稿口述版本

不要一开始逐字背诵。先记忆七个锚点：

```text
双SPA → Cloudflare → Nginx → Spring拦截器
→ Controller/Service → MySQL/Redis → systemd发布
```

完整口述稿：

> OrangeVC 整体采用前后端分离的模块化单体架构。前端分为用户端和管理端两个 Vue 3 SPA，用户端部署在根路径，管理端部署在 `/admin/`。两者分别构建后组合到同一个 Web 根目录，既隔离用户和管理功能，也保持部署简单。
>
> 生产流量首先经过 Cloudflare，负责域名代理和边缘 HTTPS，然后进入源站 Nginx。Nginx 负责源站 TLS、静态资源、入口限流和反向代理：普通页面直接返回 Vue 构建文件，`/api/` 请求转发到本机 8080 端口的 Spring Boot，`/ws/` 请求升级为 WebSocket。
>
> 后端物理上部署为一个 Spring Boot JAR，代码内部按照用户、内容、知识库、AI任务、项目推荐和 Agent 等领域拆分。请求进入 Spring 后，依次经过 CORS、请求 ID、Redis 限流和对应身份鉴权，再进入 Controller。Controller 负责接收参数和调用 Service，业务规则与事务放在 Service 中，数据访问通过 MyBatis Mapper 完成；需要时还会调用 Redis、向量库和外部模型服务。结果通过统一的 Result 结构返回，异常由全局异常处理器转换，请求 ID 用于串联日志。
>
> 数据层中，MySQL 保存用户、订单、项目、任务和配额等需要事务与长期持久化的业务事实；Redis Stack 负责缓存、限流、带 TTL 的任务租约、动态配置和向量检索；媒体文件存放在 OSS。生产上的 Spring Boot 由 systemd 管理，密钥通过服务器环境文件注入，MySQL 只监听本机。发布时统一构建后端和两个前端，安装脚本会备份旧版本、校验 Nginx、切换制品并执行健康检查，关键步骤失败时恢复旧版本。

# 二十一、高频追问与回答

## 21.1 Cloudflare 和 Nginx 是否功能重复

不完全重复。Cloudflare位于公网边缘，负责 DNS、代理、边缘 TLS 和边缘安全；Nginx 位于源站，负责静态资源、应用路由、WebSocket和到 Spring Boot 的反向代理。

## 21.2 为什么不让 Spring Boot 直接监听 443

Spring Boot 可以配置 HTTPS，但 Nginx 更适合统一处理证书、静态资源、域名跳转、限流和多个路径的代理。Spring Boot 只监听本机 8080，业务层更专注，也减少直接暴露。

## 21.3 为什么前后端分离

Vue负责页面状态和交互，Spring Boot负责业务规则、权限和数据。双方通过 API 协作，可以分别开发、测试和构建，也能让 Nginx 高效提供静态资源。

## 21.4 为什么管理端单独一个 SPA

管理端与用户端的权限、布局、页面和发布风险不同。单独构建能减少代码混杂，但仍可部署在同一 Nginx 下，不增加一套后端。

## 21.5 为什么不用微服务

当前个人开发和业务规模下，微服务会增加部署、网络调用、分布式事务和排障成本。模块化单体已经按照领域划分，等 AI、采集或实时连接出现独立扩缩容需求时再拆更合理。

## 21.6 Redis 能否代替 MySQL

不能简单代替。MySQL 是订单、账本、项目和任务等业务事实的持久化来源，适合事务和关系查询；Redis主要承载缓存、限流、租约、高频状态和向量检索。

## 21.7 MySQL 为什么不开放公网

外部用户只需要访问 Nginx，不需要直接连接数据库。MySQL只监听 `127.0.0.1` 可以降低扫描、爆破和误配置暴露风险。

## 21.8 Nginx 限流和 Redis 限流有什么区别

Nginx位于最外层，适合按 IP 快速拦截；Redis应用限流可以结合用户、接口和业务类型进行更细粒度、跨实例协调。两者形成分层保护。

## 21.9 systemd 和 Docker 是一回事吗

不是。systemd 管理 Linux 服务进程；Docker提供容器隔离和镜像环境。OrangeVC 当前生产后端是由 systemd 直接管理 JAR，不要把它说成 Docker 容器部署。

## 21.10 如何保证发布失败后能恢复

安装前备份 JAR、前端和 Nginx 配置；候选配置先通过 Nginx 检查；切换后验证进程、健康接口、页面和静态资源；关键步骤失败时恢复旧制品和旧配置。

## 21.11 进程是 UP，为什么网站仍可能不可用

因为进程存在不代表 MySQL、Redis、向量库和外部服务正常，也不代表 Nginx 路由和前端资源完整，所以要使用依赖健康、业务指标、日志和页面验收共同判断。

## 21.12 一次 AI 请求和普通请求的区别

前半段入口链相同，都是 Cloudflare、Nginx、Spring 拦截器、Controller 和 Service；进入业务层后，AI 请求还会经过调用治理、知识检索和外部模型，因此耗时、成本、失败类型和并发控制更复杂。

# 二十二、小白最容易混淆的概念

| 容易混淆 | 正确区别 |
|---|---|
| Cloudflare 与 Nginx | 前者是公网边缘平台，后者是源站 Web 服务器和反向代理 |
| Nginx 与 Spring Boot | 前者负责接入和静态资源，后者执行业务代码 |
| Vue 与 Spring Boot | 前者运行在浏览器，后者运行在服务器 |
| MyBatis 与 MySQL | 前者是 Java 数据访问框架，后者是真正保存数据的数据库 |
| MySQL 与 Redis | 前者是业务事实数据库，后者擅长缓存、状态和高性能数据结构 |
| Redis 与 Redis Stack | Redis Stack 在 Redis 基础上增加搜索和向量等能力 |
| HTTP 与 WebSocket | 前者通常一问一答，后者升级后保持双向长连接 |
| 构建与部署 | 构建生成制品，部署把制品放入目标环境 |
| 发布与部署 | 发布还包括切流、检查和让新版本正式服务用户 |
| 健康检查与日志 | 前者回答当前是否健康，后者说明具体发生了什么 |
| 单体与“代码混乱” | 单体指部署单元，仍然可以有清晰模块和分层 |
| Token 与用户身份 Token | LLM Token 是模型文本计量单位；App-Token 是登录身份凭证 |

10. 为什么使用 systemd 管理 JAR？
11. 为什么密钥不能提交 Git？
12. 为什么发布前要备份旧 JAR、前端和 Nginx？
13. 为什么应用进程存活不等于系统健康？
14. 模块化单体和微服务的主要区别是什么？
15. 当前 OrangeVC 架构最主要的两个故障域是什么？

## 答案要点

1. DNS 将域名解析到 Cloudflare，Cloudflare再代理到源站。
2. Cloudflare在公网边缘，Nginx在源站服务器。
3. Nginx 的通用 `/api/` 代理配置去掉该前缀后转发到 8080。
4. SPA 路由存在浏览器中，服务器找不到对应真实文件，需要回退到 `index.html`。
5. 分层可以保持职责、事务、测试和复用边界清晰。
6. Spring Boot 是应用框架，MyBatis 是数据访问框架，MySQL 是保存数据的数据库。
7. Redis提供内存速度、计数、TTL、Sorted Set 和 Lua 原子操作。
8. MySQL更适合事务、关系、约束和业务事实持久化。
9. WebSocket需要从HTTP升级为长连接协议。
10. 为了开机启动、失败重启、日志、权限和统一生命周期管理。
11. Git历史长期存在且可能被复制，泄露后难以完全清除。
12. 新版本或配置失败时可以恢复完整旧版本。
13. 数据库、Redis、向量库或业务链仍可能失败。
14. 单体是一个部署单元；微服务是多个独立部署和网络协作的服务。
15. 同机部署带来的主机级单点，以及 Redis 同时承担多种职责带来的影响面。
