使用独立的 `bigorange-v3-merge-mysql` MySQL 8.4 容器，端口仅绑定 `127.0.0.1:18336`。未连接应用现有数据库。

通过真实 Flyway 10.10.0 执行：

1. 空库完整应用 V1–V37，validate 成功，再次 migrate 为 0 次变更。
2. 第二个空库先应用至 V36，插入构造的账号和额度记录，再升级 V37。
3. 核对历史额度金额与余额保持 123，生成 `OVCQ_` 交易号且状态为 POSTED；validate 和重复迁移通过。

这是构造数据的升级演练，不冒充生产备份恢复或生产数据验收。Flyway 对 MySQL 8.4 发出支持版本提示，本次实际演练通过；GitHub 原有数据库任务仍使用 MySQL 8.0。

复现脚本：`scripts/ci/V3MigrationSmoke.java`。它仅面向新建的临时容器，固定创建 `v3_merge_empty`、`v3_merge_upgrade` 两个测试库；已有同名库时会失败，不会删除它们。先用 Maven `dependency:build-classpath` 导出 orange-server 的依赖，再通过 Java 21 源文件模式运行。不要指向业务数据库。

GitHub CI 的最终状态以 PR #2 最新提交的 checks 为准；不得把旧版本成功任务或 skipped 当作本版通过。本轮不部署生产、不执行 V38 之后的迁移、不调用真实模型或支付渠道。
