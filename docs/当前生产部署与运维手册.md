# OrangeJD 当前生产部署与运维手册

> 文档状态：当前部署的唯一可信手册（Single Source of Truth）
> 最后更新：2026-07-17
> 适用项目：`D:\Orangejd` 当前主线代码
> 目标：让没有历史对话的新智能体也能完成部署、验证、迁移和回滚。

## 1. 先读这些约定

1. 本文不保存任何密码、AccessKey、JWT 密钥或 AI Key。秘密只放在服务器的 `/etc/orangejd/orangejd.env`，权限必须为 `600`。
2. 日常发版只更新 JAR 和前端静态文件，不清空数据库、不覆盖上传目录、不删除 Redis 数据。
3. 只有明确执行“本地全量数据迁移”时，才允许替换生产数据库数据。
4. 数据库结构只由 Flyway 管理。已有迁移文件不可修改，新增结构必须增加新的版本迁移。
5. 正式上线必须使用域名和 HTTPS。公网 IP 仅用于临时联调，Cloudflare Turnstile 也应绑定正式域名。
6. 执行任何数据替换、升级或回滚前，先备份数据库、JAR、静态文件和上传目录。

## 3. 当前架构

```text
浏览器
  -> Nginx :80/:443
     -> /              用户端 Vue 静态文件
     -> /admin/        管理端 Vue 静态文件
     -> /api/*         反向代理到 Spring Boot 127.0.0.1:8080
     -> /uploads/*     本地历史上传文件

Spring Boot
  -> RDS MySQL（内网 + TLS）
  -> 本机 Redis 8（127.0.0.1:6379，包含 Search/Vector 能力）
  -> OSS（服务端上传，Bucket 私有）
  -> AI Embedding 服务（RAG 向量生成）
```

健康检查成功时，`/health/detail` 应返回 `db`、`redis`、`rag_vector_store` 均为 `UP`。

## 4. 首次准备服务器

### 4.1 基础软件

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jre-headless nginx mysql-client curl unzip tar
sudo systemctl enable --now nginx
java -version
nginx -v
mysql --version
```

### 4.2 Redis 8

当前生产机通过 `packages.redis.io` 的 APT 仓库安装 Redis 8.2.7。不要再依赖 Docker Hub 或 Redis Stack 容器；当前 Redis 8 已验证支持 `FT.SEARCH`。

关键配置应保持为：

```text
bind 127.0.0.1 -::1
requirepass <从环境文件读取的强密码>
appendonly yes
maxmemory 2gb
maxmemory-policy noeviction
```

验证：

```bash
sudo systemctl enable --now redis-server
sudo bash -c '
source /etc/orangejd/orangejd.env
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli PING
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli COMMAND INFO FT.SEARCH
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli FT._LIST
'
```

预期至少看到 `PONG`，并且 `FT.SEARCH` 命令存在。首次部署时索引列表可以为空，应用启动后会创建 `default-index`。

### 4.3 RDS 网络

1. 轻量服务器和 RDS 必须都在上海，并开启轻量服务器与 RDS 的内网互通。
2. RDS 白名单加入轻量服务器私网地址或实际互通网段，不要长期开放 `0.0.0.0/0`。
3. 应用使用 RDS 内网地址，MySQL 连接要求 TLS。

测试连接时从环境文件读取凭据：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
MYSQL_PWD="$MYSQL_PASSWORD" mysql \
  --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" \
  -u "$MYSQL_USER" "$MYSQL_DB" \
  -e "SELECT VERSION(), CURRENT_USER(), NOW(); SHOW STATUS LIKE '\''Ssl_cipher'\'';"
'
```

## 6. systemd 服务

`/etc/systemd/system/orangejd.service` 建议内容：

```ini
[Unit]
Description=OrangeJD application
After=network-online.target redis-server.service
Wants=network-online.target

[Service]
Type=simple
User=admin
Group=admin
WorkingDirectory=/data/orangejd
EnvironmentFile=/etc/orangejd/orangejd.env
ExecStart=/usr/bin/java -Xms512m -Xmx2048m -XX:MaxMetaspaceSize=384m -jar /data/orangejd/orange-server.jar --spring.profiles.active=prod
Restart=on-failure
RestartSec=5
SuccessExitStatus=143
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/data/orangejd

[Install]
WantedBy=multi-user.target
```

加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now orangejd
sudo systemctl status orangejd --no-pager -l
sudo journalctl -u orangejd -n 150 --no-pager
```

不要使用 `pkill java` 管理服务，统一使用 `systemctl start|stop|restart orangejd`。

## 7. Nginx 反向代理与静态文件

临时通过公网 IP 联调时，`/etc/nginx/sites-available/orangejd` 可使用：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name 47.101.131.238;

    root /data/orangejd/web-dist;
    index index.html;
    client_max_body_size 100m;

    location = /admin {
        return 301 /admin/;
    }

    location = /admin/ {
        try_files /admin/index.html =404;
    }

    location ^~ /admin/ {
        try_files $uri $uri/ /admin/index.html;
    }

    # 支付回调需要保留 /api 前缀；普通 /api/ 代理会去掉该前缀。
    location = /api/epay/notify {
        proxy_pass http://127.0.0.1:8080/api/epay/notify;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }

    location /uploads/ {
        alias /data/orangejd/uploads/;
        try_files $uri =404;
    }

    location = /health {
        proxy_pass http://127.0.0.1:8080/health;
    }

    location = /health/detail {
        allow 127.0.0.1;
        deny all;
        proxy_pass http://127.0.0.1:8080/health/detail;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用并验证：

```bash
sudo ln -sfn /etc/nginx/sites-available/orangejd /etc/nginx/sites-enabled/orangejd
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/admin/
curl -sS http://127.0.0.1/health
```

`/admin/` 返回 403 通常是静态目录缺少 `index.html`、目录权限不足，或缺少上面的精确 `location = /admin/`。

## 10. Flyway 数据库迁移

当前代码应包含 V1-V7。V7 为：

```text
orange-server/src/main/resources/db/migration/V7__add_conversation_visibility_flags.sql
```

它补充 `conversation.hidden_by_initiator` 和 `conversation.hidden_by_receiver`，解决旧环境导入时出现 `Unknown column 'hidden_by_initiator'` 的问题。

应用启动后检查迁移：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
MYSQL_PWD="$MYSQL_PASSWORD" mysql --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" \
  -u "$MYSQL_USER" "$MYSQL_DB" \
  -e "SELECT installed_rank, version, description, success FROM flyway_schema_history ORDER BY installed_rank;"
'
```

确认 V7 的 `success=1` 后再执行数据导入。不要手工伪造 Flyway 记录，也不要修改已经执行过的 V1-V6。

## 11. 本地全量数据迁移到生产

这是高风险操作，只在明确要用本地数据替换生产数据时执行。日常发版跳过本节。

当前迁移包：

```text
deploy/orangejd_data_20260717.sql
deploy/orangejd_uploads_20260717.tar.gz
```

其中 `orangejd_data_20260717.sql` 是仅数据、完整列名的导出，不包含 Flyway 表。不要把 `deploy/orangejd_backup.sql` 导入生产，因为它包含 `DROP TABLE` 和旧表结构。

### 11.1 上传迁移包

本机 PowerShell：

```powershell
$key = "D:\浏览器下载\orangevc.pem"
scp -i $key D:\Orangejd\deploy\orangejd_data_20260717.sql admin@47.101.131.238:/home/admin/
scp -i $key D:\Orangejd\deploy\orangejd_uploads_20260717.tar.gz admin@47.101.131.238:/home/admin/
```

### 11.2 先备份生产数据

服务器端：

```bash
sudo mkdir -p /data/orangejd/backups
sudo bash -c '
set -euo pipefail
source /etc/orangejd/orangejd.env
stamp="$(date +%Y%m%d-%H%M%S)"
MYSQL_PWD="$MYSQL_PASSWORD" mysqldump --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" -u "$MYSQL_USER" \
  --single-transaction --routines --triggers "$MYSQL_DB" \
  > "/data/orangejd/backups/mysql-before-import-$stamp.sql"
tar -czf "/data/orangejd/backups/uploads-before-import-$stamp.tar.gz" \
  -C /data/orangejd uploads
'
```

### 11.3 替换数据

先确认当前 JAR 已成功执行 V7，然后执行：

```bash
sudo systemctl stop orangejd

sudo bash <<'EOF'
set -euo pipefail
source /etc/orangejd/orangejd.env
export MYSQL_PWD="$MYSQL_PASSWORD"

MYSQL=(
  mysql --ssl-mode=REQUIRED
  -h "$MYSQL_HOST"
  -P "${MYSQL_PORT:-3306}"
  -u "$MYSQL_USER"
)

"${MYSQL[@]}" -N "$MYSQL_DB" -e "
SELECT CONCAT('TRUNCATE TABLE \`', table_name, '\`;')
FROM information_schema.tables
WHERE table_schema = DATABASE()
  AND table_type = 'BASE TABLE'
  AND table_name <> 'flyway_schema_history';
" > /tmp/orangejd-truncate.sql

{
  echo 'SET FOREIGN_KEY_CHECKS=0;'
  cat /tmp/orangejd-truncate.sql
  echo 'SET FOREIGN_KEY_CHECKS=1;'
} | "${MYSQL[@]}" "$MYSQL_DB"

"${MYSQL[@]}" "$MYSQL_DB" < /home/admin/orangejd_data_20260717.sql
echo MYSQL_IMPORT_OK
EOF
```

恢复本地上传文件：

```bash
sudo mkdir -p /data/orangejd/uploads
sudo tar -xzf /home/admin/orangejd_uploads_20260717.tar.gz -C /data/orangejd
sudo chown -R admin:admin /data/orangejd/uploads
sudo systemctl start orangejd
curl -fsS http://127.0.0.1:8080/health/detail
```

导入后抽查核心表数量和业务登录。全量替换数据库后必须继续执行下一节的 RAG 重建。

## 12. RAG 向量知识库重建

本地旧 Redis 不支持 `FT.SEARCH`，因此不能直接搬运向量索引。MySQL 中保存的是知识库原文，生产 Redis 的向量必须重新生成。

当前代码提供管理员接口：

```text
POST /admin/knowledge/document/reindex
GET  /admin/knowledge/document/reindex/status
```

管理后台知识库页面也提供重建按钮和进度。重建前必须确认：

1. `AI_EMBEDDING_KEY` 有效并有足够额度。
2. 后端健康检查中 `rag_vector_store=UP`。
3. Redis 可用内存充足，当前策略为 `noeviction`。
4. 没有另一个重建任务正在运行。

重建会清理 `default:` 前缀的旧向量文档，然后按 MySQL 的 `knowledge_document.content` 重新切片和写入。当前基线约为 533 篇文档，其中约 523 篇有正文，预计约 5520 个可重建分片；实际数字以接口状态为准。

重建期间查看：

```bash
sudo journalctl -u orangejd -f
sudo bash -c '
source /etc/orangejd/orangejd.env
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli FT._LIST
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli FT.INFO default-index
'
```

完成后测试一次知识库检索或 AI 对话，不能只看索引名称存在。

## 13. OSS 配置和验证

1. Bucket `orangevc-prod-media-1` 保持私有。
2. 创建专用 RAM 用户，只授予该 Bucket 所需的对象读写权限，不使用主账号 AccessKey。
3. 服务器上传走内网 Endpoint，对外访问 URL 使用公网 Endpoint。
4. AccessKey 只写入环境文件，不写代码、Git、文档或聊天截图。
5. 上传后检查对象确实进入 OSS，并测试应用生成的访问 URL。

建议对 Bucket 开启服务端加密和合理的生命周期规则。实时日志、HDFS、定时备份不是当前应用上线的必需项，可按预算后续开启。

## 14. 域名、HTTPS 和 Turnstile

公网 IP 联调通过后再正式开放：

1. 完成域名备案并将域名解析到 `47.101.131.238`。
2. 在轻量服务器防火墙开放 80/443；不要向公网开放 3306、6379、8080。
3. 使用 Certbot 或阿里云证书配置 HTTPS，并将 HTTP 重定向到 HTTPS。
4. 把 `ALLOWED_ORIGINS` 和 `PUBLIC_BASE_URL` 改为正式 HTTPS 域名。
5. 在 Cloudflare Turnstile 控制台把正式域名加入允许主机名。
6. 使用包含正确 Site Key 的前端重新构建并部署。
7. 重启后端并重新测试注册、登录、上传和管理端。

裸 IP 页面中的 Turnstile 显示“无法连接到网站”通常不是后端故障，而是 Turnstile 主机名未匹配或页面尚未使用 HTTPS。

## 15. 上线验证清单

服务器内部：

```bash
sudo systemctl is-active orangejd nginx redis-server
curl -fsS http://127.0.0.1:8080/health/detail
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/admin/
sudo nginx -t
sudo journalctl -u orangejd -n 200 --no-pager -l
sudo tail -n 100 /var/log/nginx/error.log
```

浏览器端必须逐项验证：

- 用户端首页、刷新任意前端路由。
- 注册、验证码/Turnstile、登录和退出。
- 旧账号登录和核心历史数据。
- 管理端 `/admin/` 登录、刷新内部路由。
- 文件上传到 OSS、访问和删除权限。
- 知识库检索/AI 对话。
- Nginx 访问日志无持续 4xx/5xx，后端日志无持续 ERROR。

登录接口返回 HTTP 200 但 JSON 提示“用户名或密码错误”，说明网络和后端已经连通，应检查账号数据或密码，而不是继续排查 Nginx。

## 16. 回滚

### 16.1 回滚应用版本

```bash
sudo systemctl stop orangejd
sudo cp /data/orangejd/backups/<旧版JAR> /data/orangejd/orange-server.jar
sudo mv /data/orangejd/web-dist /data/orangejd/web-dist.failed
sudo cp -a /data/orangejd/backups/<旧版静态目录> /data/orangejd/web-dist
sudo chown -R admin:admin /data/orangejd/web-dist
sudo systemctl start orangejd
curl -fsS http://127.0.0.1:8080/health/detail
```

注意：若新版本已经执行了数据库迁移，回滚 JAR 不等于回滚数据库。优先采用向后兼容迁移；确需恢复数据库时，应进入维护窗口并使用 RDS 备份或本节生成的 SQL 备份。

### 16.2 回滚全量数据导入

停止应用，清空除 `flyway_schema_history` 外的业务表，导入 `mysql-before-import-*.sql`，恢复对应上传压缩包，再启动应用并重建向量。执行前确认备份文件完整且时间点正确。

## 17. 常见故障定位

| 现象 | 优先检查 |
| --- | --- |
| 浏览器提示网络连接失败 | Nginx access/error 日志、`/api/` 代理、前端是否写死 localhost |
| `/admin/` 返回 403 | `web-dist/admin/index.html`、目录权限、精确 Nginx location |
| Nginx 502 | `orangejd` 是否运行、8080 是否监听、后端启动日志 |
| 登录返回“用户名或密码错误” | 网络已通，检查数据是否导入、账号和密码 |
| MySQL `ERROR 2026` | 使用 `--ssl-mode=REQUIRED`，检查驱动和 RDS SSL 设置 |
| MySQL `ERROR 1044` | 确认数据库名为 `orangevc`，账号已授权 |
| `Unknown column hidden_by_initiator` | 部署含 V7 的 JAR，让 Flyway 成功执行后再导入 |
| Redis 拉取镜像超时 | 当前方案不需要 Docker；使用已配置的 Redis APT 包 |
| `FT._LIST` 为空 | 应用是否启动、RAG 配置是否开启、查看健康检查和日志 |
| Turnstile 无法连接 | 正式域名、HTTPS、允许主机名、Site Key/Secret Key 配对 |
| SSH `Permission denied (publickey)` | 本机 `scp -i` 是否使用正确私钥和 `admin` 用户 |
| `/root` Permission denied | `admin` 不应直接操作 `/root`，上传到 `/home/admin`，系统目录操作加 sudo |

## 18. 交接给新智能体时的检查顺序

新智能体应按以下顺序恢复上下文：

1. 阅读本文和 `docs/生产上线安全与数据治理.md`。
2. 检查 `git status`、当前分支和最近提交，不能覆盖用户未提交改动。
3. 阅读 `orange-server/src/main/resources/application-prod.yml`、Flyway 最新迁移、systemd 和 Nginx 模板。
4. 区分本次任务是“日常发版”还是“全量数据替换”，没有明确授权时只能做日常发版。
5. 构建并测试后端、用户端、管理端，检查前端 API 基址。
6. 部署前备份；部署后检查 systemd、健康接口、Flyway、Redis 索引和 Nginx。
7. 涉及知识库数据替换时，检查 `AI_EMBEDDING_KEY` 并执行批量向量重建。
8. 永远不要在回复、日志或 Git 中复述秘密值；如果秘密曾公开，应立即轮换。

这份文档应随服务器路径、云资源、环境变量名、数据库迁移或发布流程变化同步更新。
