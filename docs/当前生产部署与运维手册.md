# OrangeJD 当前生产部署与运维手册

> 文档状态：当前部署的唯一可信手册（Single Source of Truth）
> 最后更新：2026-07-21
> 适用项目：`D:\Orangejd` 当前主线代码
> 目标：让没有历史对话的新智能体也能完成部署、验证、迁移和回滚。

## 1. 先读这些约定

1. 本文不保存任何密码、AccessKey、JWT 密钥或 AI Key。秘密只放在服务器的 `/etc/orangejd/orangejd.env`，权限必须为 `600`。
2. 日常发版只更新 JAR 和前端静态文件，不清空数据库、不覆盖上传目录、不删除 Redis 数据。
3. 只有明确执行“本地全量数据迁移”时，才允许替换生产数据库数据。
4. 数据库结构只由 Flyway 管理。已有迁移文件不可修改，新增结构必须增加新的版本迁移。
5. 正式上线必须使用域名和 HTTPS。公网 IP 仅用于临时联调，Cloudflare Turnstile 也应绑定正式域名。
6. 执行任何数据替换、升级或回滚前，先备份数据库、JAR、静态文件和上传目录。

## 3. 当前架构

```text
浏览器
  -> Nginx :80/:443
     -> /              用户端 Vue 静态文件
     -> /admin/        管理端 Vue 静态文件
     -> /api/*         反向代理到 Spring Boot 127.0.0.1:8080
     -> /uploads/*     本地历史上传文件

Spring Boot
  -> RDS MySQL（内网 + TLS）
  -> 本机 Redis 8（127.0.0.1:6379，包含 Search/Vector 能力）
  -> OSS（服务端上传，Bucket 私有）
  -> AI Embedding 服务（RAG 向量生成）
```

健康检查成功时，`/health/detail` 应返回 `db`、`redis`、`rag_vector_store` 均为 `UP`。

## 4. 首次准备服务器

### 4.1 基础软件

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jre-headless nginx mysql-client curl unzip tar
sudo systemctl enable --now nginx
java -version
nginx -v
mysql --version
```

### 4.2 Redis 8

当前生产机通过 `packages.redis.io` 的 APT 仓库安装 Redis 8.2.7。不要再依赖 Docker Hub 或 Redis Stack 容器；当前 Redis 8 已验证支持 `FT.SEARCH`。

关键配置应保持为：

```text
bind 127.0.0.1 -::1
requirepass <从环境文件读取的强密码>
appendonly yes
maxmemory 2gb
maxmemory-policy noeviction
```

验证：

```bash
sudo systemctl enable --now redis-server
sudo bash -c '
source /etc/orangejd/orangejd.env
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli PING
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli COMMAND INFO FT.SEARCH
REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli FT._LIST
'
```

预期至少看到 `PONG`，并且 `FT.SEARCH` 命令存在。首次部署时索引列表可以为空，应用启动后会创建 `default-index`。

### 4.3 RDS 网络

1. 轻量服务器和 RDS 必须都在上海，并开启轻量服务器与 RDS 的内网互通。
2. RDS 白名单加入轻量服务器私网地址或实际互通网段，不要长期开放 `0.0.0.0/0`。
3. 应用使用 RDS 内网地址，MySQL 连接要求 TLS。

测试连接时从环境文件读取凭据：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
MYSQL_PWD="$MYSQL_PASSWORD" mysql \
  --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" \
  -u "$MYSQL_USER" "$MYSQL_DB" \
  -e "SELECT VERSION(), CURRENT_USER(), NOW(); SHOW STATUS LIKE '\''Ssl_cipher'\'';"
'
```

## 6. systemd 服务

`/etc/systemd/system/orangejd.service` 建议内容：

```ini
[Unit]
Description=OrangeJD application
After=network-online.target redis-server.service
Wants=network-online.target

[Service]
Type=simple
User=admin
Group=admin
WorkingDirectory=/data/orangejd
EnvironmentFile=/etc/orangejd/orangejd.env
ExecStart=/usr/bin/java -Xms512m -Xmx2048m -XX:MaxMetaspaceSize=384m -jar /data/orangejd/orange-server.jar --spring.profiles.active=prod
Restart=on-failure
RestartSec=5
SuccessExitStatus=143
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/data/orangejd

[Install]
WantedBy=multi-user.target
```

加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now orangejd
sudo systemctl status orangejd --no-pager -l
sudo journalctl -u orangejd -n 150 --no-pager
```

不要使用 `pkill java` 管理服务，统一使用 `systemctl start|stop|restart orangejd`。

## 7. Nginx 反向代理与静态文件

临时通过公网 IP 联调时，`/etc/nginx/sites-available/orangejd` 可使用：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name 47.101.131.238;

    root /data/orangejd/web-dist;
    index index.html;
    client_max_body_size 205m;

    location = /admin {
        return 301 /admin/;
    }

    location = /admin/ {
        try_files /admin/index.html =404;
    }

    location ^~ /admin/ {
        try_files $uri $uri/ /admin/index.html;
    }

    # 支付回调需要保留 /api 前缀；普通 /api/ 代理会去掉该前缀。
    location = /api/epay/notify {
        proxy_pass http://127.0.0.1:8080/api/epay/notify;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }

    location /uploads/ {
        alias /data/orangejd/uploads/;
        try_files $uri =404;
    }

    location = /health {
        proxy_pass http://127.0.0.1:8080/health;
    }

    location = /health/detail {
        allow 127.0.0.1;
        deny all;
        proxy_pass http://127.0.0.1:8080/health/detail;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用并验证：

```bash
sudo ln -sfn /etc/nginx/sites-available/orangejd /etc/nginx/sites-enabled/orangejd
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/admin/
curl -sS http://127.0.0.1/health
```

`/admin/` 返回 403 通常是静态目录缺少 `index.html`、目录权限不足，或缺少上面的精确 `location = /admin/`。

## 8. 本地构建发布物

当前首选统一发布脚本为 `scripts/build-release.sh`。它依次执行 Maven 全量验证、用户端 `npm ci` 与生产构建、管理端 `npm ci` 与生产构建，并把 JAR、两个前端、配置示例和全部 Flyway 迁移打入同一个压缩包。这样可以避免漏发管理端或误删 `/admin/index.html`。

在 Windows PowerShell 的 `D:\Orangejd` 执行：

```powershell
Set-Location D:\Orangejd
$env:VITE_TURNSTILE_SITE_KEY = "<Turnstile Site Key>"
$env:VITE_LEGAL_OPERATOR = "orange团队"
$env:VITE_LEGAL_CONTACT_EMAIL = "1281748852@qq.com"

& "C:\Program Files\Git\bin\bash.exe" --login -c `
  'export PATH="/usr/bin:/bin:$PATH"; cd /d/Orangejd && ./scripts/build-release.sh'

Get-FileHash .\build\orangejd-release.tar.gz -Algorithm SHA256
```

脚本默认使用同域 `/api`，WebSocket 默认跟随当前页面协议和域名。不要把 Secret Key、数据库密码或支付密钥放进任何 `VITE_*` 变量。

发布前确认包内同时存在：

```powershell
tar -tzf .\build\orangejd-release.tar.gz |
  Select-String 'orange-server.jar','web-dist/index.html','web-dist/admin/index.html','database/migration/V12__'
```

## 9. 日常发版流程

### 9.1 发布前门禁

1. 确认 `git status` 中每项修改都属于本次版本。
2. 包含新 Flyway 迁移时，在 RDS 控制台创建当前时间点的手动备份。
3. 验证 `/etc/orangejd/orangejd.env` 中本次功能需要的变量存在，但不得打印变量值。
4. 记录发布包 SHA256；服务器收到文件后必须再次校验。

开源贡献模块额外要求 `GITHUB_TOKEN`、`AI_TREND_ENDPOINT` 和 `AI_TREND_KEY`。Token 应通过 GitHub API `/rate_limit` 返回 200 验证，不能只检查字符串非空。

### 9.2 从本机上传

以下命令只能在本机 PowerShell 执行：

```powershell
$key = "D:\浏览器下载\orangevc.pem"
scp -i $key D:\Orangejd\build\orangejd-release.tar.gz `
  admin@47.101.131.238:/home/admin/
```

### 9.3 在服务器安装

先把 `<EXPECTED_SHA256>` 替换为本机构建结果：

```bash
set -euo pipefail
archive=/home/admin/orangejd-release.tar.gz
expected=<EXPECTED_SHA256>
actual="$(sha256sum "$archive" | awk '{print toupper($1)}')"
test "$actual" = "$expected"

stamp="$(date +%Y%m%d-%H%M%S)"
stage="/home/admin/orangejd-release-$stamp"
backup="/data/orangejd/backups/release-before-$stamp"
new_web="/data/orangejd/web-dist-new-$stamp"

mkdir -p "$stage"
tar -xzf "$archive" -C "$stage"
test -f "$stage/orange-server.jar"
test -f "$stage/web-dist/index.html"
test -f "$stage/web-dist/admin/index.html"

sudo mkdir -p "$backup"
sudo cp -a /data/orangejd/orange-server.jar "$backup/"
sudo cp -a /etc/orangejd/orangejd.env "$backup/"
sudo cp -a /etc/nginx/sites-available/orangejd "$backup/"
sudo install -d -o admin -g admin -m 755 "$new_web"
sudo cp -a "$stage/web-dist/." "$new_web/"
sudo chown -R admin:admin "$new_web"

sudo systemctl stop orangejd
sudo install -o admin -g admin -m 0640 "$stage/orange-server.jar" /data/orangejd/orange-server.jar
sudo mv /data/orangejd/web-dist "$backup/web-dist"
sudo mv "$new_web" /data/orangejd/web-dist
sudo systemctl start orangejd
sudo nginx -t
sudo systemctl reload nginx
echo "BACKUP=$backup"
```

该流程不会覆盖生产环境文件，不导入数据库，不删除 Redis 数据，也不改动 OSS 对象。应用启动时只会执行尚未执行的 Flyway 迁移。

### 9.4 发布后基础验收

```bash
sudo systemctl status orangejd --no-pager -l
curl -fsS http://127.0.0.1:8080/health/detail
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/admin/
sudo journalctl -u orangejd -n 200 --no-pager -l
```

浏览器部署后执行一次 `Ctrl+F5`。用户端、管理端和后端有任意一端发生修改时，统一发布包都必须整体安装。

## 10. Flyway 数据库迁移

当前代码包含 V1-V12。生产服务器最后一次已确认到 V11；部署本地候选版本后必须确认 V12 成功。V7 为：

```text
orange-server/src/main/resources/db/migration/V7__add_conversation_visibility_flags.sql
```

它补充 `conversation.hidden_by_initiator` 和 `conversation.hidden_by_receiver`，解决旧环境导入时出现 `Unknown column 'hidden_by_initiator'` 的问题。

应用启动后检查迁移：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
MYSQL_PWD="$MYSQL_PASSWORD" mysql --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" \
  -u "$MYSQL_USER" "$MYSQL_DB" \
  -e "SELECT installed_rank, version, description, success FROM flyway_schema_history ORDER BY installed_rank;"
'
```

确认 V7 的 `success=1` 后再执行数据导入。不要手工伪造 Flyway 记录，也不要修改已经执行过的 V1-V6。

V8 为 `V8__secure_delivery_attachments.sql`，增加交付附件元数据列和 `storage_cleanup_job` 删除重试队列。部署新 JAR 后必须确认 V8 的 `success=1`，再验收交付附件上传与下载。

V9-V12 分别负责上线体检、法律同意记录、Epay 订单交易记录和开源贡献模块。V12 为 `V12__add_open_source_contribution.sql`，新增：

- `open_source_repository`：受管 GitHub 仓库源、技术栈和同步状态。
- `open_source_issue`：Issue 原文、中文摘要、认领/关联 PR 核验、难度与发布状态。
- `open_source_guide`：按用户和 Issue 唯一保存的贡献指南。
- `ai:open-source-match`、`ai:open-source-job-match`、`ai:open-source-guide` 三项配额价格。

V12 执行后必须检查三张表存在，并且 `flyway_schema_history.version='12'` 的 `success=1`。

## 11. 本地全量数据迁移到生产

这是高风险操作，只在明确要用本地数据替换生产数据时执行。日常发版跳过本节。

当前迁移包：

```text
deploy/orangejd_data_20260717.sql
deploy/orangejd_uploads_20260717.tar.gz
```

其中 `orangejd_data_20260717.sql` 是仅数据、完整列名的导出，不包含 Flyway 表。不要把 `deploy/orangejd_backup.sql` 导入生产，因为它包含 `DROP TABLE` 和旧表结构。

### 11.1 上传迁移包

本机 PowerShell：

```powershell
$key = "D:\浏览器下载\orangevc.pem"
scp -i $key D:\Orangejd\deploy\orangejd_data_20260717.sql admin@47.101.131.238:/home/admin/
scp -i $key D:\Orangejd\deploy\orangejd_uploads_20260717.tar.gz admin@47.101.131.238:/home/admin/
```

### 11.2 先备份生产数据

服务器端：

```bash
sudo mkdir -p /data/orangejd/backups
sudo bash -c '

source /etc/orangejd/orangejd.env
```

### 11.3 替换数据

先确认当前 JAR 已成功执行 V7，然后执行：

```bash
sudo systemctl stop orangejd

sudo bash <<'EOF'
set -euo pipefail
source /etc/orangejd/orangejd.env
export MYSQL_PWD="$MYSQL_PASSWORD"

MYSQL=(
  mysql --ssl-mode=REQUIRED
  -h "$MYSQL_HOST"
  -P "${MYSQL_PORT:-3306}"
  -u "$MYSQL_USER"
)

"${MYSQL[@]}" -N "$MYSQL_DB" -e "
SELECT CONCAT('TRUNCATE TABLE \`', table_name, '\`;')
FROM information_schema.tables
WHERE table_schema = DATABASE()
  AND table_type = 'BASE TABLE'
```

## 17. 常见故障定位

| 现象 | 优先检查 |
| --- | --- |
| 浏览器提示网络连接失败 | Nginx access/error 日志、`/api/` 代理、前端是否写死 localhost |
| `/admin/` 返回 403 | `web-dist/admin/index.html`、目录权限、精确 Nginx location |
| Nginx 502 | `orangejd` 是否运行、8080 是否监听、后端启动日志 |
| 登录返回“用户名或密码错误” | 网络已通，检查数据是否导入、账号和密码 |
| MySQL `ERROR 2026` | 使用 `--ssl-mode=REQUIRED`，检查驱动和 RDS SSL 设置 |
| MySQL `ERROR 1044` | 确认数据库名为 `orangevc`，账号已授权 |
| `Unknown column hidden_by_initiator` | 部署含 V7 的 JAR，让 Flyway 成功执行后再导入 |
| Redis 拉取镜像超时 | 当前方案不需要 Docker；使用已配置的 Redis APT 包 |
| `FT._LIST` 为空 | 应用是否启动、RAG 配置是否开启、查看健康检查和日志 |
| Turnstile 无法连接 | 正式域名、HTTPS、允许主机名、Site Key/Secret Key 配对 |
| SSH `Permission denied (publickey)` | 本机 `scp -i` 是否使用正确私钥和 `admin` 用户 |
| `/root` Permission denied | `admin` 不应直接操作 `/root`，上传到 `/home/admin`，系统目录操作加 sudo |

## 20. 正式开放前的服务器入口加固

本节是当前项目的目标安全基线。本文更新时只完成了代码和操作方案检查，尚未收到服务器端完整执行结果，不能标记为已完成。执行时必须保留当前 SSH 会话，并在第二个终端确认新规则可登录后才能关闭旧会话。

### 20.1 公网端口和监听地址

轻量服务器云防火墙只应保留：

| 端口 | 来源 |
| --- | --- |
| TCP 80 | `0.0.0.0/0` |
| TCP 443 | `0.0.0.0/0` |
| TCP 22 | `<TRUSTED_PUBLIC_IP>/32` |

删除或禁用来源为 `0.0.0.0/0` 的 SSH 规则，以及 3306、6379、8080、“全部 TCP”和“全部端口”规则。SSH 保持密钥登录即可，不必仅为了隐藏端口修改 22；限制来源 IP 更重要。

Ubuntu UFW 也设置第二层限制：

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from <TRUSTED_PUBLIC_IP> to any port 22 proto tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status numbered
```

环境文件中的 `SERVER_ADDRESS=127.0.0.1` 让 Spring Boot 只监听本机；Redis 必须继续只绑定 `127.0.0.1 -::1`。验证：

```bash
sudo ss -lntp | grep -E ':22|:80|:443|:6379|:8080'
```

预期 6379 和 8080 只出现在回环地址，80/443 由 Nginx 对外监听。

### 20.2 RDS、账号和秘密文件

1. RDS 白名单优先只保留轻量服务器实际互通源地址 `172.24.58.139`；删除 `0.0.0.0/0`、服务器公网 IP和不再使用的个人公网 IP。修改后必须立即验证 `db=UP`。
2. 初始 SQL 曾创建用户名 `admin`、默认密码 `123456` 的管理员。生产管理员必须通过管理端设置页修改为独立强密码。
3. 查询 `account` 表识别 `demo`、`test`、`connection_test` 等演示或测试账号，优先设置 `status='DISABLED'`；有作品、订单或会话引用的账号不要直接删除。
4. SSH 应禁用密码登录和 root 远程登录，只保留已验证的 `admin` 密钥登录。
5. `/etc/orangejd` 权限为 `700`，`/etc/orangejd/orangejd.env` 所有者为 `root:root`、权限为 `600`。该文件不得写入 Git、日志或聊天记录。

### 20.3 Swagger、健康详情和管理入口

项目已引入 SpringDoc，生产环境必须保留：

```dotenv
SPRINGDOC_API_DOCS_ENABLED=false
SPRINGDOC_SWAGGER_UI_ENABLED=false
```

Nginx 还应作为第二层防护：

1. `/swagger-ui/**`、`/v3/api-docs/**`、`/doc.html` 以及带 `/api` 前缀的同类路径统一返回 404。
2. `/health` 可保留为只返回 `status=UP` 的基础探活；`/health/detail` 和 `/api/health/detail` 只允许 `127.0.0.1`。
3. 管理静态站点 `/admin/` 和管理接口 `/api/admin/**` 只允许 `<TRUSTED_PUBLIC_IP>`；后端 JWT 鉴权继续保留，IP 白名单不能替代登录鉴权。
4. 限制规则必须写在通用 `location /api/` 之前；每次修改先备份配置并执行 `sudo nginx -t`，测试成功后再 reload。

以下片段中的 `<TRUSTED_PUBLIC_IP>` 必须先替换成实际运维公网 IP，再加入 `/etc/nginx/sites-available/orangejd` 的 `server` 块，并放在通用 `location /api/` 前面：

```nginx
location ~ ^/(?:api/)?(?:v3/api-docs|swagger-ui|swagger-ui.html|doc.html)(?:/|$) {
    return 404;
}

location = /health/detail {
    allow 127.0.0.1;
    deny all;
    proxy_pass http://127.0.0.1:8080/health/detail;
}

location = /api/health/detail {
    allow 127.0.0.1;
    deny all;
    proxy_pass http://127.0.0.1:8080/health/detail;
}

location ^~ /api/admin/ {
    allow <TRUSTED_PUBLIC_IP>;
    deny all;
    proxy_pass http://127.0.0.1:8080/admin/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

现有的 `location = /admin/` 和 `location ^~ /admin/` 也要加入相同的 `allow <TRUSTED_PUBLIC_IP>; deny all;`。若家庭公网 IP 变化，应先在保留中的 SSH 会话里更新云防火墙、UFW 和 Nginx 白名单，再测试新会话，不能直接关闭旧入口。

最终验证：

```bash

curl -sS http://127.0.0.1/health
curl -sS http://127.0.0.1/health/detail
curl -I http://127.0.0.1/api/swagger-ui/index.html
curl -fsS http://127.0.0.1:8080/health/detail
```

## 23. 开源贡献模块运维

### 23.1 功能和入口

用户端 AI 工具首页不再原地展开工具卡片，入口关系如下：

| 入口 | 路由 | 内容 |
| --- | --- | --- |
| AI 工具首页 | `/ai` | GitHub 双榜单、开源 Issue 滚动榜单、三条任务路径 |
| 做自己的项目 | `/project-tools` | GitHub 榜单、趋势分析、方案设计、上线体检 |
| 参与开源项目 | `/open-source?tab=discover` | 发现 Issue、AI 匹配、岗位匹配、贡献指南 |
| 工作能力参考 | `/submit-job` | 岗位与能力参考 |
| 管理端开源贡献 | `/admin/#/open-source` | 仓库源、Issue、翻译、发布和刷新状态管理 |

四个开源阶段都有独立且可重复播放的新手引导。浏览、筛选和查看 Issue 不扣配额；AI 匹配、岗位匹配和贡献指南分别在用户确认后按 `ai_service_pricing` 扣费，调用失败应退款。

### 23.2 抓取与刷新机制

V12 预置 25 个默认启用的 `CORE` 仓库和若干默认停用的 `EXTENDED` 仓库。每个启用仓库刷新时最多读取最近更新的 12 条 open Issue，并排除 GitHub API 中标记为 Pull Request 的条目。

- 完整刷新：默认 `0 20 3 */2 * *`，即每两天 03:20，时区 `Asia/Shanghai`。
- 轻量核验：默认每 12 小时，重新检查已发布 Issue 的 open 状态、assignee、评论认领线索和关联 PR。
- 翻译：每批 10 条，单次完整刷新最多处理 80 条待翻译记录；失败记录保留为 `FAILED`，可在管理端重试。
- 实时核验：同一 Issue 两分钟内复用最近核验结果，避免用户连续点击消耗 GitHub API 配额。

不要一次启用全部扩展仓库。启用新源前先观察 GitHub API 剩余额度、AI 翻译耗时和数据库增长。

### 23.3 部署后验收

先验证 GitHub Token，不输出 Token 本身：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
curl -fsS -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  https://api.github.com/rate_limit >/dev/null
echo "GitHub Token: VALID"
'
```

随后在管理端触发一次“完整刷新”，用以下命令观察任务：

```bash
sudo journalctl -u orangejd --since "10 minutes ago" --no-pager -l |
  grep -Ei "Issue|open.source|GitHub|翻译|refresh|error|warn" || true
```

检查数据库缓存量和同步状态：

```bash
sudo bash -c '
source /etc/orangejd/orangejd.env
MYSQL_PWD="$MYSQL_PASSWORD" mysql --ssl-mode=REQUIRED \
  -h "$MYSQL_HOST" -P "${MYSQL_PORT:-3306}" -u "$MYSQL_USER" "$MYSQL_DB" \
  -e "SELECT COUNT(*) repositories, SUM(enabled) enabled FROM open_source_repository;
      SELECT translation_status, published, COUNT(*) total
      FROM open_source_issue GROUP BY translation_status, published;
      SELECT full_name,last_sync_status,last_sync_time,last_sync_error
      FROM open_source_repository WHERE enabled=1 ORDER BY priority LIMIT 30;"
'
```

最终必须从用户端验证：发现页能显示中文标题与摘要、筛选和详情可用、实时核验可返回、AI 匹配和岗位匹配成功、指南生成后能在记录中重新打开。GitHub Token 失效时历史缓存仍可展示，但刷新与实时核验会失败；AI 服务失效时抓取仍可进行，但翻译和三项 AI 功能不可用。
