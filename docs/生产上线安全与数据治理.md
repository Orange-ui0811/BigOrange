# OrangeJD 生产上线安全与数据治理

本文档记录当前代码已具备的保护、上线时必须执行的操作，以及上线后的数据和支付运维基线。代码层完成不代表生产环境自动安全，标注为“人工”的项目必须由部署人员确认。

## 0. 大规模推广审计结论（2026-07-14）

| 维度 | 当前结论 | 本轮落地 | 上线门禁 |
|---|---|---|---|
| 体验舒适度 | 桌面端结构完整，窄屏主导航和管理菜单原先不可用 | 用户端增加移动底栏，管理端增加移动抽屉；补充跳转焦点、页面标题、动态视口、安全区和减少动画支持 | 使用 iOS Safari、Android Chrome、桌面 Chrome 各完成登录、发布、聊天、充值和后台审核真机走查 |
| 数据安全 | 鉴权、上传、XSS、限流和备份基线已具备；全局知识库存在普通用户写入口 | 全局知识库写操作仅保留管理端；文本上传强制 UTF-8、过滤控制字符；所有主要分页统一限制页号、页大小和偏移量 | 完成跨账号越权测试、备份恢复演练、隐私政策和数据删除工单流程 |
| 交易安全 | Epay 充值已具备服务端定价、验签、精确金额、行锁、幂等事件和唯一渠道流水号 | 支付回调限制字段数量/长度并避免不可信内容进入日志；生产环境强制支付地址为 HTTPS；充值跳转改为同页可靠跳转 | Epay 审核通过前保持五项配置为空；通过后完成沙箱/小额实付、重复回调、错金额、对账和退款演练 |
| 网络与会话 | 双 JWT、黑名单、CORS/CSP 和反向代理限流已具备 | 双端退出调用服务端吊销；WebSocket 仅接受 30 秒一次性 ticket，不再接受 URL JWT；静态资源启用压缩和哈希长缓存 | TLS、WAF/云防火墙、Redis ACL、数据库最小权限和密钥托管必须由运维验收 |
| 扩展能力 | 单实例可上线验证；静态 WebSocket 会话表不支持多实例广播 | 本轮不改变架构 | 后端水平扩容前必须引入跨实例消息分发；在此之前 WebSocket 流量固定到单实例或使用粘性会话 |

本轮遵循“不改变现有功能和架构”的边界，只做输入边界、权限、会话、移动适配和部署层优化。横向扩容、支付渠道主动查询、全链路可观测平台属于后续架构能力，不应伪装成已经完成。

## 1. 推荐上线顺序

1. 备份当前数据库并在隔离数据库完成一次恢复演练，记录恢复耗时。
2. 使用 `.env.prod.example` 在密钥管理系统或仅服务账号可读的 `EnvironmentFile` 中配置变量；不要提交真实 `.env`。
3. 分别生成管理端和用户端 JWT 密钥，禁止复用；轮换密钥会让现有登录失效。
4. 先发布后端。Flyway 会在启动时校验并执行数据库迁移；迁移失败时不得继续发布前端。
5. 检查 `/health`、后台登录、普通用户登录、上传、WebSocket ticket、配额消费和退款。
6. 发布两个前端，再切换 Nginx；观察错误率、登录失败率和支付回调至少 30 分钟。
7. 在线支付只有在真实渠道沙箱完成签名、金额、重复通知和乱序通知测试后才允许填写 `EPAY_*`。五项均为空时支付关闭。

## 2. 网络与应用安全基线

代码已实现：

- 生产启动强校验 JWT、HTTPS CORS 白名单、Turnstile 和支付配置完整性。
- 管理端/用户端分离 JWT，包含角色、token 类型、签发方、受众和唯一 ID；退出令牌以 SHA-256 摘要写入 Redis 黑名单。
- 管理接口每次请求检查账号状态与管理员角色；敏感 AI 接口要求登录。
- Redis Lua 原子限流覆盖登录、验证码、重置密码、充值创建和兑换码。
- WebSocket 仅使用 30 秒、一次性 ticket，避免 JWT 出现在 URL、浏览记录和代理日志中。
- 上传目录、MIME、文件魔数、图片尺寸和路径穿越均由服务端验证。
- AI 外部资源 URL 拒绝本机、内网、链路本地、多播、带凭据和非 HTTP(S) 地址；管理端在生产环境动态修改 AI 配置时只接受公网 HTTPS endpoint，密钥回显仅保留末四位。
- 用户端和管理端所有富文本渲染统一经过 DOMPurify，阻断存储型 XSS；内容类型只允许 WORK/REQUIREMENT。
- 会话、消息已读、报价、收藏、评论、浏览历史和私有内容均校验当前账号归属或参与关系。
- Nginx 模板启用 HTTPS 跳转、HSTS、CSP、安全响应头、请求体限制和接口限流。
- 外部异常统一返回通用信息；请求日志带 Request ID，管理审计日志单独留存。

上线人工检查：

- 云安全组只开放 80/443；MySQL、Redis 和 8080 只允许内网或本机访问，SSH 只允许运维来源。
- Redis 开启 ACL/密码，MySQL 使用独立低权限业务账号；迁移账号可在发布窗口临时拥有 DDL 权限。
- TLS 证书自动续期并监控到期时间；Nginx `server_tokens off`。
- Swagger 在生产关闭或限制为运维网络访问。
- 移除 README 中的默认管理员密码，并在首次部署后立即修改；生产库不得使用初始化口令。
- 完成越权测试：用户 A 不能读取或修改用户 B 的作品、需求、订单、会话、文件和配额。
- 检查所有客户端均通过 `/app/auth/ws-ticket` 建连，任何携带 `token` 查询参数的连接都必须被拒绝。

## 3. 数据治理基线

数据分级与最小化：

| 级别 | 当前数据 | 要求 |
|---|---|---|
| 高敏感 | 密码摘要、JWT/验证码、支付商户密钥 | 不记录日志；密钥只在密钥管理系统；验证码短 TTL；密码仅 BCrypt |
| 敏感个人信息 | 邮箱、手机号、私信、订单、IP | 按业务授权访问；后台默认脱敏；导出需审计 |
| 财务审计 | 充值单、渠道流水号、配额流水、支付回调事件 | 只追加或状态机更新；定期对账；至少保留法务要求的期限 |
| 普通业务 | 作品、需求、分类、公开资料 | 明确公开范围；支持下架、注销和删除流程 |

建议保留策略：验证码和 WebSocket ticket 到期即自动删除；应用运行日志 30 天；管理和安全审计日志至少 180 天；支付与配额流水按会计和当地法规确定（常见做法不少于 5 年）；原始支付回调仅保留已白名单字段。隐私政策必须写明用途、保存期限、第三方处理方和用户删除渠道。

备份要求：

- `backup.sh` 使用一致性快照、压缩校验、原子落盘和默认 14 天本地保留。
- 每日增量/全量策略应满足建议 RPO ≤ 24 小时、RTO ≤ 4 小时；具体值由业务负责人确认。
- 至少一份备份跨主机或跨可用区，并进行服务端加密；每月至少恢复演练一次。
- 备份也属于敏感数据，限制读取、记录下载审计并设置生命周期删除。

容量与性能要求：上线推广前用脱敏或合成数据完成至少一次峰值压测，覆盖市场列表、登录、聊天、AI 任务提交和支付回调；压测不能调用真实支付或真实短信/邮件。分页接口单页最多 50 条、页码最多 10000，超限输入由服务端归一化。数据库慢查询阈值、连接池等待、Redis 命中率、JVM 堆和队列积压必须纳入告警。

## 4. 支付上线门禁

上线前必须在渠道沙箱验证以下用例：签名正确、签名篡改、商户号错误、金额错误、订单号不存在、相同回调重复 10 次、不同渠道流水号冲突、已关闭订单回调、回调超时重试。期望结果是只有“签名正确 + 商户一致 + 精确金额一致 + `TRADE_SUCCESS` + pending 状态”能入账一次。

本地充值单号使用账户标识加完整 128 位随机 UUID，并由数据库唯一键兜底。创建支付链接和写入待支付订单位于同一事务，渠道链接创建失败时不得遗留不可支付订单；回调订单号、渠道流水号和状态长度在查询或写库前校验。

每日对账至少比较 `top_up`、`payment_callback_event`、`quota_log` 与渠道账单：渠道成功但本地未成功、同一订单多渠道流水、充值金额与 Segments 不匹配、人工调整无审计均需告警。当前“管理员盲重试入账”已禁用；接入渠道主动查询接口后，才能实现以渠道查询结果为依据的补单。

作品交易订单中的“付定金/付尾款”目前只是原型状态流，不等同于 Epay 的 Segments 充值。开发环境可继续演示，生产环境通过 `orange.trade.simulated-payment-enabled=false` 强制禁止模拟确认付款。订单金额以服务端报价为准，定金与尾款必须精确等于总价；订单删除改为买卖双方各自隐藏，财务和交付记录不允许物理删除。正式启用作品资金交易前，必须另行接入订单支付、退款、对账或合规托管流程。

发生支付事故时先关闭支付配置或入口，不直接修改余额；保留回调和请求 ID，生成补偿单，通过幂等业务编号执行并双人复核。

## 5. 发布与回滚

- 发布前执行：`mvn test`、两个前端 `npm run build`、`git diff --check`。
- 数据库采用向前兼容迁移：先加表/加列，再发兼容代码；删除列必须跨至少两个版本。
- 应用回滚前确认旧版本能够读取新结构。已执行的 Flyway migration 不应手工改 checksum 或直接删除记录。
- 回滚验证包括登录、公开市场、后台列表、配额流水、文件读取和 WebSocket。
- 生产告警至少覆盖 5xx、登录失败激增、Redis/MySQL 不可用、磁盘不足、备份失败、支付验签失败和支付对账差异。
