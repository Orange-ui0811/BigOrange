# B版＋模型 Reranker：第一轮对照

用户于2026-11-02选择使用已有Gitee接口。使用`bge-reranker-v2-m3`，复用`.env.local`中的凭据，不输出凭据、不修改网站。

本轮固定24题：16道语义检索题、4道点名回归题、4道业务规则题。问题和已有来源/原文锚点来自旧评测集，先冻结，再采集候选；均为助手标注诊断，不称为独立盲测。

每题实际运行当前B原生Top8及Top20（阈值0.55），需要最多48次本地bge-m3查询请求，独立账本计数。保持当前活动代际、全文结构分块、混合召回、条件过滤和去重。不重新入库、不创建或切换业务索引；关闭定时任务和启动恢复，调用测试入口，网站后端不用启动。

两组使用同一份已冻结Top20：

- 无Reranker：原有排序与选择规则，逐题验证能复现实际Top8及回答策略。
- 有Reranker：只替换候选排序，随后执行相同项目多样性与价格证据规则；原RRF分数与模型分数分开保存。

这是在原生Top20之后追加重排的小实验；候选已做过B版多样性选择。它能检验是否值得进一步接入，但不代表在完整80条融合候选阶段重排的最终效果。

候选快照完成后冻结逐条真实请求。每个非空候选集一次请求，最多24次Gitee Reranker请求，失败/超时计数，不自动重试；空候选不调用。无聊天、生成、分类、文档Embedding调用。

统计目标来源及目标原文命中@1/3/5/8、MRR@8、候选集中的可达上限、逐题升降、业务策略变化、实际新增重排耗时P50/P95。原文锚点不是完整事实/限制标注；不报告完整证据召回率、最终答案准确率或完整相关性nDCG。

耗时只作为顺序小样本诊断：保留真实无重排耗时和新增重排调用耗时，不将历史不同场次P95相加；不冒充网站端到端性能和持续压测。

程序：`python scripts/rag_b_reranker_eval.py prepare`、`capture`、`run`、`verify`。旧实验材料保留。
