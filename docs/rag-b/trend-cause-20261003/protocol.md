# 智能分析 A/B 成本与耗时归因复测

日期：2026-10-03。目标是验证 B 在上一轮更慢、更贵的原因，不预设旧流程缺陷就是原因。

## 设计

- 四个合成场景：Spring 入门、Python 跨语言 RAG、Python 数据分析、无匹配项目。
- 8 次完整生产生成链路（4 题 × A/B），管理员开发接口开启线程隔离观测；保存实际模型请求，不读取账号画像，不扣积分，不写趋势历史。
- 每份完整请求再重放两次，合计 24 次带知识证据生成。重放跳过检索及业务查询，请求体 SHA256 必须与捕获请求一致；因此重复差异不能归因于检索变化。
- 每题另做两次移除知识库证据的重放，共 8 次。不改变系统提示、画像、图谱、业务候选、参数。A/B 去证据后的请求若不一致，必须报告，不视为同一公共对照。
- 共计划 32 次模型调用，单并发，固定种子随机排列题目与 A/B；所有成功和失败保存，不自动重试。
- 另做 24 次检索观测（4 题 × A/B × 3 次），不调用生成模型。普通入口继续 A；不改索引、模型、Prompt 或业务逻辑。

## 观测边界

记录 Embedding HTTP、向量检索含 Embedding、词面检索、名称检索、元数据恢复、数据库及条件过滤、融合、片段去重、相关性门槛、证据压缩、业务候选、图谱、Prompt、生成 HTTP、JSON 解析组装和来源绑定。

嵌套阶段不可直接累加。向量检索总时间减去 Embedding HTTP 只是剩余本地处理与 Redis 等耗时，不是纯 Redis 网络时间。供应商内部排队、预填充、思考及解码阶段没有分阶段时间，不能将整个模型耗时或首次响应时间直接称为思考耗时。

记录供应商返回模型 ID、用量、思考 Token、缓存信息、完成原因、客户端总耗时及完整请求。每次调用不加入 RAGAS、事实裁判或额外校验模型；输出校验采用原智能分析解析与绑定。

只按上一轮统一标价（输入 12 元／百万 Token、输出 24 元／百万 Token）做费用对照；输出已包含思考 Token，不重复计费，不当作实际账单。未追加入库、翻译或索引重建费用。供应商返回版本不一致时报告混合结果及同版本结果，不声称已冻结实际模型权重。

## 判定

1. 差额分配到检索、本地处理、生成，避免用总耗时猜原因。
2. 检查 B 是否只是输入变长、调用次数增加、重试增加或本地处理更慢。
3. 同一冻结请求的三次重复衡量输出 Token 与耗时波动；每个场景重复不是独立新题。
4. 与去知识证据请求对照，判断特定证据内容是否稳定影响用量；四题不能推导所有场景。
5. 模型返回别名、生成波动及样本局限必须保留；不能观察的供应商内部原因标为未证实。
