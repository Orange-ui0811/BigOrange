# 五模型与分块方案真实对照报告

实验日期：2026-10-02。用户明确授权调用 Gitee Embedding 后执行。未修改 A/B 活动索引、平台模型配置或原始文档。

费用补充复核：Gitee官方向量化与重排文档目前明确说明此类已部署模型免费，故按公开政策本轮Embedding调用费应为0元。实际请求、Token与账户核验边界见同目录`cost-report.md`；原报告中的“金额未知”是查到该政策前的状态。

## 结论

在本轮候选范围内，`bge-m3 + 结构分块 target512 / cap768 / overlap<=64 Token` 的证据检索质量最高，建议作为 B 版下一轮完整链路候选。不是立即替换上线的结论。

速度优先候选为 `Qwen3-Embedding-0.6B + target512 / cap768 + 查询指令`。它的单查询中位延迟更低，但证据排名和覆盖逊于 BGE-M3。没有供应商完整账单，因此不能宣称它实际费用更低。

结构分块不是必然提升：原小模型使用新短块时，证据 Recall@8 从 58.3% 降到 56.7%，MRR@8 从 0.466 降到 0.409。较大模型也不是必然优于较小模型：Qwen3-4B 本轮没有超过 BGE-M3。

## 方法和范围

- 只读快照：68 份 READY 文档，原分块 1307 个，原文 460577 字符。快照哈希与方案清单见 `manifest.json`。
- 固定 110 题：50 题原项目定位回归；30 个真实事实各编写中英文问题，共 60 题语义检索。题目、来源、证据锚点在模型调用前冻结。
- 主排名依据：新增 60 题的证据 MRR@8，其次证据 Recall@8。50 个旧定位题只标了来源，不能混入最终事实支持率。
- 第一轮五模型输入完全相同的结构块；第二轮测试模型自己的 512/768 Token 配置；补充八组官方查询指令对照，共 18 组质量结果。
- 检索方式为 float32 归一化后的精确余弦检索，统一 Top8 和来源类型范围。不设跨模型统一相似度阈值。
- 没有运行 HNSW、RRF、业务硬条件复核、Reranker、拒答策略或 LLM 回答。因此本报告不等于平台完整 RAG 效果与延迟验收。

结构分块原型识别代码围栏外的 ATX 和 Setext 标题，并在章节内按段落、代码块、句子/换行边界拆分。保留原文连续偏移和完整覆盖；只在同一章节内重叠。没有去除 HTML，没有标题增强，没有父章节扩展，也没有实现超长表格重复表头。这些改动没有混入本轮模型比较。

所有分块均按三个分词器家族检查预算。另核对了大模型自身分词器：BGE-large 与 small 词表相同但大小写规范化不同，19 个共同块超过名义384 Token，最大460 Token，仍低于512输入容量。五模型收到的共同块文本完全相同。

## 每个模型的最佳候选

下表的质量指标只针对60个语义证据题。MRR越高，标注证据通常越靠前；Recall@8只表示前8条中出现证据，不是最终回答准确率。

| 模型与方案 | 块数 | 证据 Recall@8 | 证据 MRR@8 | 二值证据 nDCG@8 |
|---|---:|---:|---:|---:|
| 当前 small，500字符原分块，无指令 | 1307 | 58.3%（35/60） | 0.466 | 0.466 |
| large，共同256结构块，查询指令 | 1627 | 90.0%（54/60） | 0.699 | 0.738 |
| **M3，512结构块，无指令** | **1391** | **100%（60/60）** | **0.828** | **0.847** |
| Qwen3-0.6B，512结构块，查询指令 | 1364 | 95.0%（57/60） | 0.710 | 0.754 |
| Qwen3-4B，768结构块，查询指令 | 1336 | 91.7%（55/60） | 0.717 | 0.744 |

Qwen3-4B 的512结构块加指令方案 Recall@8 更高，为93.3%（56/60），MRR为0.711。768方案只是本轮MRR点估计更高，没有证据证明768明显优于512。

M3方案有44/60题在第1条找到标注证据。它在50个定位回归题上全部第1条找到目标来源。不能把来源命中当作每题已找到完整回答所需的全部事实。

## 原小模型与M3的分题型结果

| 题型 | 数量 | 当前small证据Recall@8 | M3-512证据Recall@8 |
|---|---:|---:|---:|
| 中文问题检索中文业务资料 | 20 | 95% | 100% |
| 英文问题检索中文业务资料 | 20 | 0% | 100% |
| 中文问题检索README资料 | 10 | 60% | 100% |
| 英文问题检索README资料 | 10 | 100% | 100% |

README组包含英文为主及中英文混合内容，不代表所有题都是严格纯英文语料的跨语言测试。

原small在中文业务题的MRR为0.925，M3为0.834，说明M3并非每个题型都更靠前。M3的综合优势主要来自双语适配、中文检索README和证据覆盖。实际生产如果几乎没有英文问题，不能直接照搬本轮中英文各半的综合分，应按真实查询分布重新加权并验证。

## 分块和查询指令的影响

| 对照 | Recall@8变化 | MRR变化 |
|---|---:|---:|
| small原字符块 → 共同短结构块 | 58.3% → 56.7% | 0.466 → 0.409 |
| M3共同短块 → 512结构块 | 96.7% → 100% | 0.795 → 0.828 |
| Qwen3-0.6B共同短块 → 512结构块，均不加指令 | 91.7% → 95.0% | 0.622 → 0.670 |
| Qwen3-0.6B-512加查询指令 | 95.0% → 95.0% | 0.670 → 0.710 |
| Qwen3-4B-768加查询指令 | 90.0% → 91.7% | 0.653 → 0.717 |
| large共同短块加查询指令 | 88.3% → 90.0% | 0.613 → 0.699 |

查询指令只加到问题，不加到文档。Qwen采用模型卡示例 `Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery:{query}`；BGE v1.5采用`为这个句子生成表示以用于检索相关文章：`。输入按Gitee实际部署测试，未假设服务内部一定添加或不添加指令。

M3相对共同短块减少236块，约14.5%。它相对原B块数仍增加约6.4%，不能说比当前B减少存储。章节中的大量独立短字段使所有结构方案都有不少短块；M3-512有552块低于32 Token，目标512不等于每块都达到512。后续应单独试验相邻业务字段的有意义合并和标题增强，不能据本轮将每个短字段长期固定为独立向量。

按30个事实组进行配对bootstrap，M3-512相对当前基线MRR增量为0.363，探索性95%区间[0.253,0.471]；相对Qwen3-4B最佳候选增量为0.112，区间[0.025,0.211]。M3-512相对M3短块增量为0.033，区间[-0.009,0.080]，包括零。区间未修正18组配置中的选择效应，也不是独立人工盲测的统计保证。

## 单查询供应商延迟

各模型30次新的单查询请求，另各2次预热，随机交错执行，排除预热统计。全160次请求均成功。M3与small使用原始问题，其他模型使用其最佳候选的查询指令。

| 模型 | P50 | P95 |
|---|---:|---:|
| 当前small | 206 ms | 309 ms |
| large | 599 ms | 798 ms |
| M3 | 348 ms | 426 ms |
| Qwen3-0.6B | 165 ms | 403 ms |
| Qwen3-4B | 286 ms | 419 ms |

这些包含Gitee服务和网络耗时，不包含Redis、业务数据库或生成。30个样本仅供探索，不能证明长期SLA、并发能力或模型本体的推理速度。large在本轮延迟明显较高；Qwen3-0.6B中位延迟最低，但P95优势不明显。

## 调用、存储和费用

- 质量实验：970次成功批请求、15439项实际向量输入；文档与查询缓存复用避免重复发送。无失败重试记录。
- 单查询复测：160次成功请求，含10次预热。合计1130次成功请求，文本生成调用0次。
- 返回维度：small512维，另外四模型均1024维。Qwen3-4B原模型最大维度与Gitee部署实际输出不同，结果只代表本次1024维服务。
- 正数供应商用量汇总只是已报告部分：批请求中Qwen3-4B的269批全部返回0，M3的45批用量为0或缺失。0不代表免费；完整人民币费用无法由响应计算。
- M3-512稠密float32向量本体约5.43MiB，当前small约2.55MiB，约2.13倍。未计入Redis文档、元数据、HNSW图和新旧代际共存空间，不是实测Redis占用。

## 下一轮应如何使用结果

将M3-512作为独立B实验代际的首选，将Qwen3-0.6B-512加指令作为速度优先备选。不要直接切换共享EmbeddingModel：必须绑定模型、维度、分块版本和索引代际，文档与查询一致。

后续验证需要保留原混合召回、硬条件、业务状态和引用校验，对比完整链路的证据覆盖、中文事实排序、最终回答支持率、拒答、P95与实际账单。增加业务人员独立题和真实语言分布；再决定是否迁移。
