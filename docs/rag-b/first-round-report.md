## 固定评测结果

评测集版本：`rag-b-starter-v1`，12 题，`topK=8`，相似度阈值 `0.55`。

| 指标 | A 版 | B 版 |
|---|---:|---:|
| 当前评测规则通过率 | 91.7%（11/12） | 58.3%（7/12） |
| P50 | 205 ms | 229 ms |
| P95 | 1,034 ms | 366 ms |
| 证据可追溯率 | 未统计 | 66.7% |
| 可进入带引用回答的比例 | 未统计 | 66.7% |

B 版通过：入门 Java、职业 Java、职业面试、前端岗位、README 部署、README 依赖、来源追溯。

B 版未通过：

1. `beginner-vue`：样本中的入门项目没有提取到精确 Vue 元数据，43 个候选被判为语言不匹配。
2. `job-java`：25 个岗位候选的语言字段为未知，严格策略全部拒绝。
3. `no-docker`：40 个入门候选缺少“是否依赖 Docker”的确定字段，严格策略拒绝。
4. `no-database`：34 个入门候选缺少“是否依赖数据库”的确定字段，严格策略拒绝。
5. `insufficient-evidence`：商业授权价格问题仍召回了足量但不相关的长片段，错误进入回答阶段。

当前“通过率”只验证期望来源或空结果，不验证具体相关文档，因此不能等价为 Recall@K 或答案正确率。尤其是“Java 入门项目”虽然按现有规则通过，实际回答指出候选主要是 JavaScript、React 和 TypeScript，说明语言匹配存在 `Java` 与 `JavaScript` 的子串碰撞，必须在下一轮前修复。

## 回答与引用测试

| 问题 | 检索策略 | 生成耗时 | 结果 |
|---|---|---:|---|
| 新手、两周、Java 项目 | 带引用回答 | 22.4 秒 | 3/3 事实句通过文本支持校验，但内容暴露 Java/JavaScript 条件碰撞 |
| 有效 Java 岗位要求 | 无匹配即拒绝 | 0.5 秒 | 正确停止生成 |
| 项目依赖、数据库或密钥 | 带引用回答 | 23.7 秒 | 1/6 事实句通过，整体标记为不可发布 |

引用闸门在本轮发挥了作用：一条低支持回答被阻止发布。但当前文本重合校验对“证据中没有提及某项内容”这种否定事实不稳定，后续需要语义蕴含校验或更明确的结构化缺失字段。

| 项目 | 本轮实际规模 |

| 文档向量对象 | 1,146 个分块 × 2 个索引代际 = 2,292 个 |
| 文档向量批次 | 111 批 × 2 = 222 次 |

| Embedding 外部请求合计 | 约 273 次 |
| Embedding 文档输入字符 | 917,228 字符，加少量查询文本 |

Gitee AI 官方说明其资源包可能按调用次数或 Token 计费，具体模型和资源包单价需要以账户“统计与日志”为准；当前 Embedding 客户端没有保存服务端 usage，因此本报告不能给出可信的人民币实扣金额。按当前实现，建立精确基线后再重建 HNSW 会对全部分块重复生成一次向量，这是本轮最明确的成本浪费点。

DeepSeek 客户端同样没有保存 usage。本轮 `deepseek-v4-pro` 只实际生成两次回答，输入和输出规模较小；按官方当前峰值时段每百万 Token 输入/输出价格估算，费用量级低于 0.01 美元，但应以 DeepSeek 账单为准。

## 实验中发现并修复的问题

1. MySQL 多表状态更新同时修改文档和版本时返回 2 个受影响行，原代码误认为必须等于 1，导致所有新文档失败并卡在处理中。现已改为接受任意正数并补充失败状态补偿和回归测试。
2. A 版 Redis 实际保存了来源元数据，但 Spring AI 检索结果没有自动恢复自定义字段，导致首次评测把 A 版误记为 0%。现已复用 Redis 原始元数据恢复逻辑，校正后 A 版为 91.7%。
3. 实验脚本最初把切换后的索引状态 `ACTIVE` 当成尚未完成；现已修正并支持复用活动代际，避免重复向量化。

## 下一轮前的处理顺序

1. 把语言条件改成规范化枚举或边界匹配，消除 Java/JavaScript 子串碰撞。
2. 在导入时补齐岗位语言、Docker、数据库、密钥等结构化字段；未知值仍保持严格拒绝。
3. 增加问题与候选的相关性闸门，确保“商业授权价格”不会因片段数量多而被判为证据充分。
4. 把固定评测集扩展为带期望文档/片段 ID 的人工金标集，再计算 Recall@K、nDCG@K 和硬条件满足率。
5. 持久化 Embedding 与文本模型 usage，按实验运行记录实际 Token 和费用；索引重建优先复用已有向量。

原始机器可读结果见 `first-round-result.json`。
