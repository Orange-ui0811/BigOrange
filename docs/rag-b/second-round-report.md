# RAG B 第二轮修正与 A/B 对比报告

实验时间：2026-09-29（Asia/Shanghai）

## 本轮修正

1. 语言条件改为规范化词元匹配，`Java` 不再命中 `JavaScript`；同时保留 `TS/TypeScript`、`Vue.js/Vue` 等明确别名。
2. 入门项目和职业项目直接读取业务表中的语言、技术栈、周期、难度、Docker、数据库和密钥字段；岗位从已审核岗位正文提取明确技术词。
3. 精确检索和 HNSW 混合检索共用一套硬条件判定器；来源类型在 Redis 检索前过滤，完整业务条件在返回前用业务库权威字段复核。
4. 增加定价证据门禁。商业授权价格问题只有在同一证据片段同时出现授权语境和价格事实时才能进入回答阶段。
5. 评测升级为 `rag-b-quality-v2`。通过条件同时检查来源、硬条件、回答或拒答策略；Java 入门项目在当前业务库没有已发布候选，因此正确结果是明确拒答。
6. 引用就绪率和可追溯率只以应当回答的用例为分母；拒答用例单独计算拒答准确率。

## 最终质量结果

固定评测集 12 题，`topK=8`，阈值 `0.55`。

| 指标 | A 版 | B 版 |
|---|---:|---:|
| 严格规则通过率 | 41.7%（5/12） | 100%（12/12） |
| 应回答用例 | 未单独统计 | 10 |
| 应回答用例可追溯率 | 未统计 | 100%（10/10） |
| 应回答用例引用就绪率 | 未统计 | 100%（10/10） |
| 拒答准确率 | 0%（0/2） | 100%（2/2） |

B 版现在能够：

- 对不存在的 Java 入门项目明确返回无匹配结果，不再用 JavaScript 项目代替。
- 找到 Vue 入门项目和 Java 求职项目。
- 对 Java 岗位执行精确语言过滤。
- 返回不依赖 Docker、数据库的项目，并排除违反条件的候选。
- 对资料没有提供的商业授权价格拒答，并记录 `PRICING_EVIDENCE_MISSING`。

A 版的 41.7% 是在新版严格规则下计算的结果。它不再只检查“是否返回某种来源”，还要求硬条件与拒答行为正确，因此不能与第一轮旧规则下的 91.7%直接比较。

## 性能结果

| 场景 | A P50 | A P95 | B P50 | B P95 |
|---|---:|---:|---:|---:|
| 服务重启后的冷态轮次 | 250 ms | 835 ms | 276 ms | 675 ms |
| 随后的热态轮次 | 214 ms | 329 ms | 276 ms | 390 ms |

B 版热态 P95 为 390 ms，满足当前迁移门槛 `P95 ≤ 500 ms`。B 版热态 P50 比 A 版高约 62 ms，主要来自业务状态和权威元数据复核；在 68 份文档规模下可以接受，但扩大数据量前仍应减少逐候选数据库查询。

## 结论与边界

本轮说明 B 版在这 12 个固定用例上已经解决第一轮发现的条件误判、元数据缺失和无证据继续回答问题，质量与热态延迟均达到当前门槛。它仍不是替换 A 版的充分依据：评测集只有 12 题，而且尚未标注期望文档和片段 ID，不能计算可靠的 Recall@K、MRR 或 nDCG。

下一阶段应扩展至少 60 个业务金标问题，持久化模型 usage，并把业务元数据批量读取或缓存，随后进行更长时间的双跑观察。A 版继续保持线上基线，B 版继续作为实验模块。

机器可读的热态结果见 `second-round-result.json`，冷态结果见 `second-round-cold-result.json`。
