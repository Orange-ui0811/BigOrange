## 可以直接复核的证据缺口

1. `spring_beginner-2-B.json` 的 E3 证据卡只包含 “Spring Boot Integration Architecture”；回答却扩写出“外部代理服务集成、消息通信或任务调度”。仓库 URL 有效，但这些具体能力没有被本次 Prompt 证据支持。
2. 同条回答的 E2 只给出 “Build a Spring Boot App with User Authentication”等教程条目；生成了登录、注册、表单验证、会话管理和基础安全配置等细节。认证相关推测可能合理，但不是经过逐项核实的仓库事实。
3. `rag_python-1-A.json` 把“后续可无缝扩展到中文提问英文文档”写成能力判断；送入模型的证据只有通用 RAG 流程，没有跨语言检索实验或模型配置支持。“能做 RAG”不等于“已验证跨语言效果”。
4. `printing_explore-1-A.json` 出现“Mainsail 的模拟模式”等建议，本次卡片只明确文件管理、编辑与多打印机功能；硬件与运行方式需要补充对应章节，不能由项目名称推断。
5. `data_analysis-1-B.json` 中，两路 B 原生检索均为 USED，返回算法仓库等片段；接入后 `selectedCount=0`。旧查询没有显式推荐意图，同一仓库占据多条片段，之后旧主题过滤又清空证据。这属于接入策略问题，不能归因于 bge-m3 不支持中文。
6. 模型输出中的周期、难度和商业可行性是生成的评估／建议，不是经过数据库硬条件检查的结论。当前 `VERIFIED_CANDIDATE` 只绑定身份，UI 不应让用户误读为“所有条件、事实均已验证”。

## 后续改进顺序

1. 让智能分析显式传递推荐意图，先按真实项目去重和形成候选，再选章节；校准旧词面过滤与 B 语义召回之间的边界。
2. 统一知识候选与学习／职业候选的条件检查；明确“掌握的语言”与“只允许的语言”，将未知周期、资源与难度保留为未知。
3. 从标题或零散关键词改为最小事实包：项目定位、实现语言、运行依赖、建议范围、证据定位；不足时减少推荐数量，不用推测补满两项。
4. 对描述中的具体事实执行支持校验；将学习计划和改造建议明确标注为建议，不冒充现有仓库能力。
5. 固定生成供应商版本并控制思考预算后重新做同题比较；必要时再对照 Flash，不能同时换 RAG、模型和 Prompt 后把所有收益算给 B。

本轮没有在测试过程中修改上述行为，也没有把 B 切到普通用户入口。
