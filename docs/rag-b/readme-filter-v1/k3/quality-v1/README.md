## 已定位并修正

1. Vosk 返回中把 `PLATFORM_SPECIFIC` 填入 `kind`，导致整批被拒绝。提示词 V2 明确区分知识类型与归属范围；复验成功，仍保持严格枚举校验。
2. 社区版与企业功能混在同一块时，模型可能统一判作 CORE。新增无明确版别标题时的混合版别保护，并要求多归属块送审；复验消除了本轮不确定块误放行。
3. 已验证新提示词使旧缓存失效，不会套用旧版本判断；重复执行已完成的批次也不会新增出站或覆盖原预算回执。

修复定向禁网测试 38 项通过，另有 1 项新提示词缓存失效检查通过。Maven 测试运行成功只证明执行器与保护机制正常，不代表分类质量门槛通过。

## 仍需解决

- 3 条代码/使用说明已获模型 KEEP，但前置说明或配套步骤未一起获准，合并后仍 REVIEW：`Q1-46-26`、`Q1-523-36`、`Q1-523-48`。需要完善依赖闭包；现有代码还会把部分因依赖待定的完整代码当成不完整示例来隔离，需细化原因判断。
- 4 条课程认证资料被保守送审：`Q1-51-42/44/46/48`。需明确学习资料的知识价值判定，再用新样本验证，不能把所有非现成应用都排到无用内容。
- 3 条目录入口被模型排除：`Q1-267-70/71/73`。冻结标签要求保留为导航元数据，但不作为功能证据；这一产品口径仍建议由用户复核，原始标签和分数没有回改。
- 有 1 项“构建变慢背景”类型分歧：原标签允许技术说明/用法，模型给 LIMITATION。属于标签边界复核项，不据此声称已经发生事实错误。

下一步优先修复依赖闭包和入口元数据口径，再冻结新的仓库样本，以**同一个版本**重做分类质量验收。当前暂缓 K4 的正式知识入库切换。

## 具体范围

- 16 个仓库：原有 8 个复验/控制仓库，以及原 38 份以外的 8 个新仓库。
- 15 个模型批次、54 条目标原文；其中打印耗材项目因必要上下文超预算，只作规则控制，不向模型发送。
- 14 条规则控制项：包含设备/认证限制、截断和时效等；控制项不混入模型准确率分母。
- 建议新增最多 **20 次**真实请求：15 次首轮＋5 次失败定位与回归预留；失败、超时和重试均计数。
- 默认不自动重试。首轮先覆盖全部批次，再分析错误；新仓库首轮结果独立保存，不在看过结果后修改其标签或宣称仍是独立验证。

原文与预期判断见 [gold-labels.md](gold-labels.md)，机器数据见 [frozen-dataset.json](frozen-dataset.json)。标签由助手在模型运行前审阅填写，用户尚未人工确认；不是独立人工金标准，也不能代表全库随机分布。

## 为什么这样选

复验覆盖 Vosk 的先前拒绝、LangGraph 与 LangSmith 的产品边界、Konva 的浏览器/Node 条件、ToolJet 企业版、文档网站构建和推理服务前置条件。

新仓库覆盖课程认证、UI 库、停止维护的运行时、Agent 课程、个人智能家居配置、设备通信库、自托管指南和后端队列插件。目录链接只能证明入口；个人配置和课程不能当成现成业务系统。

## 评分口径与建议通过门槛

| 项目 | 统计方式 | 调用前制定的建议门槛 |
|---|---|---|
| 输出合法率 | 完整通过校验的响应 / 实际返回响应；网络失败另列 | ≥95%，不足则先修协议 |
| 决策一致率 | 目标 KEEP/DROP/REVIEW 与冻结标签一致 / 54；无效批次保持 REVIEW 并计入覆盖损失 | ≥85% |
| KEEP 精确率 | 标为 KEEP 且预期 KEEP / 全部模型 KEEP | ≥95% |
| 知识恢复率 | 合并依赖后成为 KEEP 的预期 KEEP / 全部预期 KEEP | 单独报告，不能用全 REVIEW 获得高分 |
| 类型与范围 | 模型 KEEP 的 kind/scope 是否在原文标签允许集合中 | 逐项报告，产品/版本/平台越界为关键错误 |
| 关键条件误删 | 预期 KEEP 的关键项被最终判 DROP | 0 |
| 不确定内容误放行 | 预期 REVIEW 却最终成为 KEEP | 0 |
| 原文和引用 | UTF-16 回溯、来源身份、原文未改写、候选包不含非 KEEP | 全部通过 |
| 规则控制 | 14 条指定原文最终决定是否保持 | 全部通过，单列分母 |

输出合法、模型选择正确、合并后真正可用分别统计。失败与 REVIEW 不自动视为正确；缓存命中不计新请求；只统计已标注目标，不把未标注文本算作正确。

## 执行控制

使用独立的新授权账本，限额在 HTTP 边界和 K3 持久预留层共同执行；旧账本不重置。执行前校验数据集、源文、提示词和实现版本。保存每次返回的原始 content、finish reason、usage 和摘要，便于诊断上轮没有定位到的非法字段；来源和响应保存在本地 staging，未通过校验不进入候选。

本轮在收到新增 20 次授权后执行，实际结果与未达标结论已保存在本目录。剩余 2 次未使用，后续仍受同一授权上限约束。
