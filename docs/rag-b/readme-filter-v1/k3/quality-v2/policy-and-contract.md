# README 项目知识规则与派生结果契约 v2

状态：**用户选择已确认，K3-R3 已实现以下适用性与归属投影，并通过离线验证。生产入库与检索接入仍属于 K4。** 实际对象、协议版本与验证见 [R3 实现说明](r3-implementation.md)。

## 1. 三个不同判断

1. **内容判断**：KEEP / DROP / REVIEW，回答原文是否可理解且有可回溯价值。DROP 只用于明确装饰、噪声等；不因不在推荐范围而删除事实。
2. **推荐适用性**：IN_SCOPE / OUT_OF_SCOPE / UNKNOWN，回答原文是否支持可运行项目或可研究源码部分的推荐。必须绑定证据块；不能仅根据“课程”“示例”“README”等关键词推断。
3. **输出去向**：KNOWLEDGE_CANDIDATE / POINTER_METADATA_ONLY / ARCHIVE_ONLY / REVIEW_QUEUE，回答允许下游如何使用。KEEP 不自动等于可入正文索引。

原文永久保留。全部状态都是派生判断，不覆盖原文；REVIEW 不是事实为假，OUT_OF_SCOPE 不是内容无用。

| 原文情况 | 内容判断及适用性 | 去向 / 限制 |
|---|---|---|
| 可运行项目的用途、安装、API、架构、构建测试 | 有明确依据时 KEEP + IN_SCOPE | 正文候选，必须携带依赖和适用范围 |
| 课程仓库中明确可运行的示例、可研究代码模块 | 对该部分判断，不能推广到所有章节 | 可成为相应源码学习/二次开发候选；纯课程宣传不混入 |
| 课程考试资格、证书展示、证书撤销政策 | 信息可能有效，但为 OUT_OF_SCOPE | 原文归档及排除理由；不当作项目部署、许可条件 |
| 只列课程或工具链接的资源集合 | 不能据此建立本仓库业务能力 | 导航元数据或归档，不成为本仓库功能证据 |
| “备份 / 业务管理”等带标签目录链接 | 只认定标签和链接字面存在 | POINTER_METADATA_ONLY；不访问地址、不声称锚点存在或外部内容已收录 |
| 原文无法说明项目用途、示例能做什么 | UNKNOWN / REVIEW | 复核，不能推断技术栈、工期或部署资格 |
| 商用许可例外、非生产限制、版别/平台要求 | 范围内知识的必要条件必须保留 | 与对应内容成组；不能因含否定词而丢弃 |
| 核心产品与外部产品能力混在一块 | 无法安全分离时 REVIEW | 不统一标成 CORE；本轮不承诺跨片段改写或自动补全 |
| 徽章、装饰、社交统计、求 Star | 明确时 DROP | 仅原文归档；许可徽章仍按许可线索处理 |

附属许可证或维护信息不能自动证明某仓库属于推荐范围；也不能为减少噪声而绕过它们对已入选内容的限制。仓库提示类型只是线索，不是推荐资格的最终结论。

## 2. 依赖处理（K3-R2）

- 原文块 ID、UTF-16 半开区间、正文与哈希固定不变。
- 区分 INCOMPLETE_STRUCTURE、SEMANTIC_REVIEW_NEEDED、DEPENDENCY_NOT_APPROVED。只有真正破损的代码触发 INCOMPLETE_EXAMPLE_CONTEXT，完整代码的待复核不能伪装成截断。
- 标题提供范围。代码与相邻正文说明关联，链接、图像、布局和新标题构成关联边界，不能把社交徽章当作安装前置条件。
- 连续示例中的命令、说明及配套恢复命令建立依赖；冒号引导语不能在对应命令未批准时单独发布。依赖组是程序的保守关联，不宣称理解所有 Markdown 语义。
- 需要模型判断的依赖作为 targets 一起送审，已批准依赖作为 context；明确需要复核且模型不能处理的依赖不能被裁剪或放行。
- 依赖组超过块数或输入预算时整组延后，不通过拆掉前提来塞进请求。可以在后续独立设计安全拆分，但本轮不增加上限。
- 模型提案完成后重新计算依赖闭包；组内必要项 DROP、REVIEW 或未执行，相关知识仍不能形成可用候选。有限图遍历避免循环依赖造成死循环。

## 3. 结果契约（K3-R3 已实现）

复用当前 Source、Block、Packet、Preview 及 Selection 的原文身份，不为本阶段增加数据库迁移。

| 字段 / 对象 | 约束 |
|---|---|
| sourceIdentity | documentId、versionId、sourceRef、sourceSha256，与现有原文版本一致 |
| blockId / sourceSpan | 指向现有不可变 Block；不能输出模型改写正文 |
| decision / reason | 保存规则或模型结论及依据；拒绝非法枚举、未知或遗漏 ID |
| applicability | IN_SCOPE / OUT_OF_SCOPE / UNKNOWN；需原文证据与原因；和内容 decision 独立 |
| knowledgeKind / subjectScope | 类型与 CORE、RELATED_PRODUCT、ENTERPRISE、COMMUNITY、VERSION_SPECIFIC、PLATFORM_SPECIFIC、NON_PRODUCTION 等归属分别存储；不能用一个枚举替代多个同时存在的条件，无法表达则复核 |
| dependencyBlockIds | 标题、说明、命令、限定条件的引用关系；同源、有限、可定位 |
| disposition | 正文候选、导航、归档、待复核；下游不得只看 KEEP 绕过去向 |
| proposed / effective | 模型提案与程序最终决定分别保存；不能把被程序拦截的提案当成可用证据 |
| versions | parser、rulePolicy、selectionPolicy、prompt、schema、模型配置标识、runId；结果与缓存关联明确 |
| pointer | 保存标签、原始 href 与 evidenceBlockId；不保证链接可访问，不读取目的页 |

Selection 的 scope 与 applicability 经程序和原文约束校验后进入 Assessment 与 Candidate。Candidate 具有 subjectScopes，evidence 中每块保留自身 scopes、适用性、依据和依赖；不再只保存在模型响应中。程序可以从明确原文保留企业版+平台等多个标签；无法无损归属的混合块继续 REVIEW，不通过默认 CORE 降低限制。最终消费入口为 Result.recommendation。

### 组合规则

- 正文候选：KEEP + IN_SCOPE + 所有必要依赖获准 + 归属明确 + 原文映射完整。
- 导航：已确认标签和地址的字面信息，仅 POINTER_METADATA_ONLY；不得因为目录名为“备份”而判本仓库具备备份功能。
- OUT_OF_SCOPE：不参与项目推荐；纯课程原文和原因保留。导航若可单独提取可保留为元数据。
- UNKNOWN、冲突、截断：REVIEW_QUEUE，不产生正面或反面推荐结论。
- 范围内知识需要的许可、限制等不能通过 OUT_OF_SCOPE 绕过。上下文依赖也必须检查最终去向，防止已排除的课程内容通过 context 混回正文。

## 4. 评测约定

旧 v1 标签和历史分数不重写。v2 在运行前标注范围、用途、类别、必要依赖、关键条件与预期去向。助手标注，不称独立人工金标准。

- 决策一致率：冻结的范围内分类目标中，最终 KEEP/DROP/REVIEW 与预期一致的比例。
- 保留内容精确率：最终实际进入正文候选的已标注目标中，正确保留的比例；范围外误入需要计错，不能从分母移除。
- 应保留知识恢复率：冻结的应保留正文知识中，最终在候选中可用且依赖完整的比例。被预测成范围外的应保留内容仍在分母中。
- 导航、规则控制、范围控制单列；未标注内容不计为正确。每个比率同时显示分子分母；无有效分母不能宣布达标。
- 依赖修复模拟测试、模型分类质量、实际检索问答质量是三种不同证据。本阶段不能声称已经提升检索 Recall 或推荐成功率。

## 5. 未知与后续

README 有限：没有明确运行或源码研究价值的内容继续 UNKNOWN；不扩抓文档、不执行 README 命令。R3 实际字段已定稿，没有增加额外自主工具调用。只有标签的许可/要求链接进入导航，并标记未读取知识缺口；不能据此宣称已核验许可、已符合硬件条件或没有限制。

依赖组可能过大：保持待复核并单列覆盖损失。新集验收若受影响再独立设计安全分组，不能为了分数临时提高预算或删除限制。

真实验收批次和额度在 R4 冻结后确定。K4 才负责入库及所有检索消费者一致执行此去向；本契约不是已上线保证。
