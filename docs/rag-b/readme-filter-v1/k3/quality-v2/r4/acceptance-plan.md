# R5 评分与执行约定（R4 调用前准备）

本文件说明如何使用已冻结标签。当前没有真实预测、R5 调用授权或上线结论。

## 评分单位与三个维度

原文单元使用 `caseId + blockId + documentId + versionId + sha256`，不能按自由生成的文字近似匹配。KEEP/DROP/REVIEW 是内容与最终判断；applicability 表示推荐范围；disposition 表示输出去向。范围外有效事实可以 KEEP 后归档，不能因为未入库就当成 DROP 噪声。

以 `Result.recommendation` 为最终结果来源，检查其 Candidate、每块 Assessment 与原始 Packet。必须保留原始模型提案及失败记录，以便区分模型分类、依赖阻断与程序准入问题。对规则固定 KEEP 的块，不能把原始 Block 决定当成最终可用结果。

| 指标 | 冻结口径 |
|---|---|
| 正文精确率 ≥95% | 已标注且最终实际进入正文证据的原文单元中，正确进入的数量 / 实际进入的数量。范围外、噪声、导航或未知内容误入必须计错，不能事后排除 |
| 范围内决策一致率 ≥85% | 预期 IN_SCOPE 的模型目标中，最终 effectiveDecision 与预期 decision 一致的数量 / 该冻结目标总数；包含 H 的最终 REVIEW；另报告全 123 个目标的一致率及适用性、去向、范围标签正确率 |
| 应保留知识恢复率 ≥85% | B 类 82 条中，最终作为原文证据可用、归属符合、必要依赖完整的数量 / 82；另拆分模型目标与 24 个控制中的 B，防止规则项掩盖模型分类问题 |
| 导航保留 | 26 个 N 类逐条检查标签、原始 href、证据块、去向；多链接块检查所有已标注入口。缺失导航为遗漏，误作正文为越界 |
| 有用但阻断的知识 | H 类 1 条单列，不算应放行正文；不能称作噪声，也不能声称已完成许可核验。另报告 B+H 的有用知识覆盖情况 |
| 关键项 | 61 条逐条报告是否丢弃、待复核或正确可用；安全保持 REVIEW 应计覆盖损失，不冒充关键知识已恢复 |

所有比率展示分子、分母；没有分母不能判为达标。失败、超时、非法输出、未执行仍按最终状态进入原分母；未标注原文不能默认算正确，应单列“未标注候选”及其块数、用途。最终候选中的上下文也要检查，不能让导航或范围外事实借 context 绕过准入；标题只提供范围定位，不把标题本身计作恢复的正文知识。

必要语义依赖由 `expected.requiredBlockIds` 事先指定，不从程序的预测依赖反推预期答案。检查同一可用候选内原文与依赖是否同时可追溯，不能只检查模型返回 KEEP。保留多个替代部署命令表示原文的可选方案，不代表用户必须同时满足或执行所有方案。`requiredScopes` 检查每个证据块的归属；必要的 ENTERPRISE、RELATED_PRODUCT、PLATFORM_SPECIFIC、VERSION_SPECIFIC 等不能在组包后消失。范围标签不能代替原文的具体条件。

## 零容忍项

- 关键条件错误 DROP、当作无关噪声删除，或下游在缺少必要条件时仍作为无约束证据使用。
- 课程、资源集合、未知用途进入项目正文候选；企业/相关产品能力扩大为本体或社区默认能力；导航被当成已收录功能事实。
- 原文错引、改写后冒充原文、跨仓库证据或位置/哈希不一致。
- 截断、冲突、UNKNOWN、必要依赖待审等不确定内容被错误放行。
- 引用数据中的指令被执行，或触发本任务以外的工具调用。

REVIEW 不等于误删。若大量有用内容安全地保持 REVIEW，零容忍项可能通过，但恢复率仍会失败；必须同时满足质量和完整性要求。

## 执行安排

1. 先检查 `r4-seal.json`、冻结 manifest 的所有文件、原文、代码、模型配置指纹、提示词和 schema。授权须绑定最终 seal、数据集及请求清单哈希。源码/配置变化就停止，不把新旧结果拼成统一版本。
2. 按仓库执行所有冻结批次，固定 34 个首轮请求，输出上限 2048、每批最多 4 块、输入保守上界 12000、超时 35 秒。传输自动重试为 0。每个仓库完成后基于全部已接收选择重新生成最终候选，不能各批单独覆盖同仓库结果。
3. 实际出站前持久计数；超时和失败也计数。建议最多新增 40 次，其中 6 次只用于同一冻结请求的传输或协议失败；不能因为语义答案不满意反复抽样。具体次数仍需用户授权。
4. 出站账本拟使用 `docs/rag-b/readme-filter-v1/k3/quality-v2/r5/provider-calls.jsonl`，选择器自身还记录预留及结果。确认提供方 SDK 没有隐藏重试；中断恢复不重复已经完成的样本。
5. 首轮结果永久保留；失败重试单列。只有冻结版本一致的结果可以组成该版本的诊断汇总，不能把重试后的更优答案替换首次成绩。实际 usage 与保守预留分别统计。
6. 保存逐条结果、原始响应、最终候选、失败原因、账本和门槛结论；全部门槛通过后才进入 K4。若用新集结果修实现，本集转为回归集，不能再称未用于调参的新验证集。

原文来自本地保存的版本；本集没有访问链接、执行 README 命令，也不验证原文宣传指标是否真实。R5 检查的是分类和证据准入，检索 Recall、推荐成功率、端到端耗时由 K5 另外测量。
