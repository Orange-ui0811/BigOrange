# 真实试跑前的确定性修复队列

本文件来自 29 条归因和实际 V5 Java 批次。尚未更改生产规则，也没有新模型请求。

## F1：排版闭合标记进入代码依赖

- 原文：Flowise 第 145 行，`    </details>`。
- 位置：`ReadmeKnowledgeFilter.dependencies` 对 INDENTED 前置块的处理；`ReadmeModelReview.reviewUnits` 将非标题依赖连成不可拆组件。
- 影响：当前 18 个待模型目标所在组件被硬待审节点挡住；原 29 条缺口中的 5 条位于该组件。maxBlocks 从 4 调到 8 仍无法发送它们。
- 修复目标：纯排版闭合标记不成为代码的知识前提，源文与位置继续归档；真实错误说明、恢复命令、HTML 警告和限制仍保持依赖。不要把全部 HTML 或 INDENTED 块一概忽略。
- 验收：用当前原文复现，检查启动命令和配套解释进入规划；删除真正的恢复步骤时，完整示例仍不能放行。重新检查 303 份原文与既有依赖回归。

## F2：许可证导航被当成全局必要条件

- 原文：n8n `Q2-427-59`，“有关许可证模式的更多信息，请参阅[文档](...)”。
- 位置：`ReadmeSourceSemantics.condition/applies` 与 `ReadmeRecommendationProjection` 的 guard 完整性检查。
- 影响：这个原文块已经是导航，但仍被 guard 判断要求进入正文；导航按设计禁止作为正文上下文，因此 7 条相关知识被连带阻断。
- 修复目标：程序有原文依据的“仅导航／未读目的页”不能成为正文必需依赖，许可未知信息单列。真正的许可证正文、例外、运行限制仍保留，不能因模型选择 SOURCE_POINTER 或 OUT_OF_SCOPE 被绕过。
- 验收：纯导航不阻断普通事实；“Requires 8 GB. See docs.” 等含真实条件的段落仍携带条件；企业版条件不扩大到社区版；未读取目的页不能声称许可核验完成。

## F3：规则固定 KEEP 把非独立正文直接放行

- 原文：Appsmith `S1-522-34` 两种使用方式的引导句；`S1-522-39` 安装文档目录表。
- 位置：`ReadmeKnowledgeFilter` 的安装章节与完整表格保留，及 `ReadmeRecommendationProjection` 对规则保留块的最终知识类型判断。
- 影响：这两块不需要模型选择就能进入正文；单独重跑 V5 不会自动修复它们。补标后精确率从 53/54 扩为 53/56，表明原评测未覆盖全部实际候选。
- 修复目标：引导句与其正文／导航关联，暂不作为独立部署事实；纯链接表进入导航，保留原始标签、地址和提示。包含真实功能、负面值、版本要求的表格继续保留正文。
- 验收：两条新标签各自达标；链接表不进入正文或正文上下文；真实技术表格和有依据的安装条件不被误删。
