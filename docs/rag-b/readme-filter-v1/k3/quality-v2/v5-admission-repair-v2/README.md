## 问题和修改

AnythingLLM 第 52 行是完整原句：

> AnythingLLM 是一款全能 AI 应用，让您能够构建私有、功能齐全的 ChatGPT——无需妥协。

旧规则根据“是一款……应用”将整块判为用途正文，最终准入也直接接受，导致“无需妥协”的未经核验承诺一起成为证据。问题是准入，不是原句截断。

本轮修改：

1. `ReadmeSourceSemantics.unqualifiedPromise` 检查明确的“无需妥协／without compromise／no trade-offs”等承诺措辞；只由规则过滤器用于普通正文，不因 all-in-one、fully featured、无需 GPU 等描述单独触发。
2. `ReadmeKnowledgeFilter.decide` 将匹配正文设为 REVIEW，原因是 `UNQUALIFIED_PROMISE_REQUIRES_REVIEW`；完整原文、块 ID、位置和哈希不变，不截句拼接，也不改写成事实。
3. `ReadmeRecommendationProjection` 强制保持 REVIEW、适用性 UNKNOWN、归属未确认；不能被模型 KEEP、SOURCE_POINTER 或 OUT_OF_SCOPE 绕过。
4. 该类块不进入模型自动放行目标，也不作为项目资格锚点或最终正文证据。后续若要恢复其中有用的定位事实，需另做有原文位置依据的拆分设计。

显式否认承诺的说明、代码字面量、真实运行限制仍按原规则处理。规则没有仓库名单或 documentId 特判；这是一组窄措辞保护，不代表已解决所有广告、夸大或事实核验问题。
