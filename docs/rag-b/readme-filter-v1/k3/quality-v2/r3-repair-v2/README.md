## 改动位置与作用

| 代码 | 本轮处理 |
|---|---|
| `ReadmeSourceSemantics` | 本地解析可见文字、Markdown/HTML 导航；识别图片、条件作用域、跨块缩进围栏和数量矛盾。复用已有 Jsoup，无链接抓取 |
| `ReadmeKnowledgeFilter` | 图片及导航先于条件判断；正文许可和维护警告继续保留；末尾疑似截断复核；结构与语义依赖统一进入组包 |
| `ReadmeRecommendationProjection` | SOURCE_POINTER 禁止回落正文；待审原文禁止直接生成导航；资源/配置集合、产品混合、版本归属和条件完整性在最终候选上校验 |
| `ReadmeModelReview` | 共用确定性合并入口；保护原有硬复核；提示词升级 V5，缓存键随新版本失效；真实调用和旧响应回放分开 |

现在的处理顺序是：保留原始块与位置 → 识别标记、导航和可见正文 → 判断知识、资格和归属 → 合并已通过协议的模型选择 → 检查作用域和必要依赖 → 形成正文／导航／归档／待审结果。

原文和块边界没有重写。解析器仍为 `CONTIGUOUS_MARKDOWN_BLOCKS_V1`；规则及选择策略 V1.4、提示词 `README_SELECTOR_ZH_V5_SOURCE_ADMISSION`、输出 schema V2、最终准入 `README_RECOMMENDATION_V2`。

## 修复的具体边界

1. HTML `<a href>` 和 Markdown 链接保留原始地址、标签及证据块。解析不足的 SOURCE_POINTER 留待审，不回落为功能正文；危险协议及实体编码绕过被拒绝。代码中的示例链接不生成导航。
2. 徽章、图片地址和属性里的 MIT、only、CPU/GPU 不证明实际许可或硬件要求。徽章单独待审；可见正文的许可、非生产警告、弃用和维护状态继续保留。
3. 局部 Windows、源码安装等条件只关联适用内容；真正的项目级许可和安全限制继续保护。相关条件可以作为上下文，不能随模型 OUT_OF_SCOPE 标签消失。
4. 纯资源集合归档；配置集合缺少源码项目用途依据时复核；明确的混合仓库源码部分仍可参与。Cloud 导航不证明本地项目具备云服务能力。
5. 产品本体和 Lite 等变体混在同块时复核；导航可以保存多个入口。语言版本和平台标签可以并存，不能把 `Go 1.22+` 仅标为平台。
6. CLI 参数示例携带参数定义；缩进命令保留引导句、明确的包管理器前提和启动后的访问说明。跨空行的缩进围栏按完整示例关联，缺围栏或必要片段时待审。
7. 数量描述与紧随的模块列表矛盾时复核，不替原文改数量。命名故事与技术知识分开，OTHER 不能被模型 KEEP。

Linux、PowerShell、CMD 等片段放在同一原文上下文中，只表示它们属于同一示例。后续回答仍需按用户平台选择；不表示用户应同时执行所有平台命令。编译器要求保留源码安装标题，不能扩大成预编译程序的通用运行要求。
