2026-10-31。V2 已将知识组必要证据完整率从16/22提高至21/22，没有正例回退。剩余 R06 的架构块向量排名第1，却因正文关键词只匹配项目名而被挤到第6。

## 通用修改

新增 `RagBContentQuery`：仅移除候选元数据中已明确识别且在用户问题中显式出现的项目名，保留 Docker、Compose、JSON、CI 等技术词；保留原有完整用户问题用于向量检索，名称通道也继续使用原问题。已知项目名不再成为正文关键词。没有有效正文词时不构造通配查询，依靠原向量相关性选块。

生产 `RagBRedisStackRepository` 先做向量与名称召回，再提取项目别名处理正文关键词，继续采用 V2 项目内相关性评分。没有按 R06 或 Flowise 硬编码例外；没有改中文分词器或事实标签。

## 验证与证据保留

V1/V2 的问题、标签、索引、原始输出和账本保持原样。V2 的13份输入源码在本目录 `previous-v2-sources` 归档；其中生产 Repository 的当前源码随V3更新，旧V2脚本若直接比较当前源码会失配。V3 校验按旧哈希检查归档源码和原始产物，并检查当前V3源码，不能将当前源码变更误称为旧产物被重写。

使用 V2 保存的完整真实向量／名称排名和相同固定问题，重新执行实际 Redis 正文查询，再应用同一项目内评分。每题每组重复三次，保存新正文词、完整候选和最终排名。复用原有向量，模型／Embedding新增调用为0，主实验不写索引。这是受控回放，不冒充全新端到端性能测量。

回归覆盖项目名分离、技术词保留、非显式项目名不改写、多项目比较、仅项目名查询。真实生产 Repository 的 Redis 集成测试再次验证过滤、并发和索引适配，临时随机 it 索引仅在测试容器中创建并清理。
