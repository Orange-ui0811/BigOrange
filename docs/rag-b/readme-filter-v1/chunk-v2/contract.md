# README 过滤后分块契约 V2

2026-10-31。阶段目标：把已通过 K3 最终准入的原文变成可核验的知识单元和检索块，先做离线预览。本轮不启用生产入库，不重新调用分类模型，不调用 Embedding，不切换 B 版活动索引。

## 数据流和边界

```text
冻结 README Source
  → 已保存的 Result.preview + Result.recommendation
  → 验证最终准入、原文位置和依赖
  → 完整知识单元 Unit（READY / DEFERRED）
  → 限长检索草稿 Chunk（仅 READY）
  → 未来：隔离索引召回
  → 按 unitId 补齐完整证据 → 预算检查 → 回答与业务校验
```

分块入口只接受最终 `Projection.knowledgeCandidates`，不能使用早期规则 KEEP、模型 selections 或未经最终准入的原始候选。保留现有 K3 分类版本、模型身份和运行批次。分块适配层只收紧准入，不把 REVIEW、DROP、导航或未读链接内容提升为知识。

`ReadmeKnowledgeChunker` 是无副作用的 Java 组件，现阶段不注册 Spring Bean，不连接 `RagBDocumentService`。现有 B 版切块与索引继续按原入口运行。后续接入需要独立索引代际、候选状态存储和检索证据适配。

## 四种单位

| 单位 | 用途 | 边界 |
|---|---|---|
| 原文结构块 Block | 分类与定位 | 复用 K3 原有 blockId、SHA-256、UTF-16 区间、标题路径 |
| 知识单元 Unit | 确保事实、步骤、条件完整 | 每个正文种子加已批准的依赖、包级必要上下文、标题；相同单元去重 |
| 检索块 Chunk | 向量表示与召回 | 在知识单元内限长，可以有多个子块；不跨无关单元补长度 |
| 最终证据 Evidence | 回答支撑 | 命中任一子块后恢复完整批准单元；预算不足返回暂缓，不裁掉条件继续作答 |

一个 README 中同标题不等于同一知识单元。独立功能可分别检索；有依赖的步骤必须一起恢复。主内容不跨产品／版别范围合并。依赖的版本、平台、许可范围仍写在对应来源片段上，不覆盖为主体 CORE。

## 内容处理

| 内容 | V2 实现 |
|---|---|
| 定位、功能、架构 | 保留已批准的原文和现有明确条件。只做来源选择与分组，不让模型补写事实 |
| 操作步骤、配置、命令 | 复用 K3 依赖；补充“冒号引导句＋后续缩进内容”的双向完整性约束。任一必要子项未准入，整个单元暂缓。纯排版标签不成为依赖；遇到新的 details 折叠子分支停止向后绑定，该分支仍按 K3 自身依赖处理 |
| 长正文 | 优先整段；超限后仅按换行／句末自然边界拆分，子块都关联完整父单元；无安全边界则暂缓 |
| Markdown 表格 | 表头＋每行保持映射，长表分组重复原文表头。单行＋表头超限则暂缓整个单元 |
| 代码 | 原子保留；超限代码 V2 暂缓，暂不尝试拆函数、代码围栏或补全语法 |
| 导航、下载地址 | 原样保留 `Pointer` 元数据；不加入普通正文向量，不打开链接推断功能 |
| REVIEW／缺条件 | 保留暂缓原因和缺失 ID，没有可入库子块；不把其原文回填给回答节点 |

已知回归例：Flowise 第 155 行“6. 开发构建：”与第 157 行 `.env / VITE_PORT` 说明组成完整步骤。后者仍处于 REVIEW 时，前者不能单独生成检索块。此约束按通用缩进结构实现，没有仓库 ID 特判。

## Token 和大小预算

- 使用项目已有本地 BGE-M3 tokenizer；不访问模型端点。目标 512、最大 768 Token，最大 4096 子块。最大值包含 `Repository / Section / Knowledge / Subject scopes` 前缀和实际正文。
- 前缀属于派生检索元数据，不冒充 README 原文；正文中每段都有来源片段。最终存储的 `embeddingText` 是后续 Embedding 的唯一输入，不能再次隐式加标题。
- 同一单元短于预算时保持原样。V2 不额外添加滑窗 overlap：依靠完整父单元回查；长表重复表头属于必要结构。现有原文分块器的 64 Token overlap 参数没有照搬到新单元之间。
- 长表按相邻行分组，每组重用真实表头并保持表头与正文行之间没有额外空行；不使用过长单块强行索引。全局子块超限抛错，不返回部分预览。
- 回答端单元回查另有预算。离线预览演练 8192 Token 上限；这不是最终客服统一上下文预算，正式接入需由节点预算配置决定。

## 来源与身份

每份预览保存 `documentId / versionId / sourceRef / sourceSha256 / generationId`、K3 版本信息、分块策略和预算。`projectId` 必须来自核验过的业务映射，本轮冻结样本没有验证映射，明确为 null，不能拿 documentId 冒充。

每个单元保存主块 ID、必需块 ID、主体范围、知识类型、标题路径和暂缓原因。每个子块有确定性 ID、unitId、序号、最终文本及 Token 数。原文引用使用 `List<Span>`：每段保存 blockId、UTF-16 半开区间 `[start,end)`、原文、哈希、PRIMARY／DEPENDENCY／HEADING、该段范围。

不规范化换行再计算原文位置；CRLF、中文、emoji 均保留原始字符串。非连续来源不得用一个 start/end 冒充连续原文。标题、表头即使重复，也必须引用真实原文位置。全体子块应完整覆盖 READY 单元的所有来源字符。

## 本轮验收与未完成范围

离线验收：5 个已调试过的冻结仓库、真实分类输出不变、原文及范围回溯、依赖不缺失、导航隔离、表头保留、Unicode／换行不漂移、Token 限制、确定性和全量覆盖。另有助手构造边界样本测试。这不是独立人工语义评测。

上一轮分类 18 次额度已耗尽，本轮 Docker 禁用网络，调用数为 0。保留前序分类原始结果、账本、输入和评分，分别校验封存文件，离线分块不能掩盖分类问题。

后续隔离检索验证需另行冻结输入与问题集：

1. 先审阅每仓库预览，确认该保留的知识没有因错误依赖而大量暂缓。
2. 针对功能、版本、部署、许可／限制、证据不足问题标注预期项目与支持原文；特别覆盖“有项目但缺条件”和“未读导航不能证明功能”。
3. 在独立代际写入 READY 子块，统一 bge-m3 与检索／rerank 配置，与旧切块做同题对比。记录候选项目命中、证据召回、限定条件完整性、无依据回答及分阶段耗时。
4. 最终回答还需业务项目状态、账号权限和导入资格校验。本契约不覆盖这些规则，不宣称已达到生产推荐标准。

当前正式 K4 生产激活门槛保持未通过；此工作是隔离实验准备。混合许可、正文导航误判、n8n 命名故事误保护等 K3 已知问题仍需独立处理，不能由分块质量分数替代。

V1 首次离线预览暴露了普通构建与折叠排障的过度绑定，V2 修正；V1 预览和测试证据保持原样，21 份源码输入归档到本目录的 `previous-v1-sources`。当前代码以 V2 为准。V2 复验同时检查旧归档输入、旧产物与全部分类账本；旧脚本检查当前源码时失配不意味着旧产物被重写。

## 复验

首次执行：`python scripts/check_readme_chunk_v2.py`。完成后该代际封存，使用 `python scripts/check_readme_chunk_v2.py --verify` 检查来源、代码、预览与测试证据。修改策略或样本时创建新代际，不覆盖本轮或旧分类证据。
