# README三组检索实验 V1

2026-11-01。执行用户确认的A/B/C三组专项；不激活网站索引。

- A：完整冻结原文，现有B版`RagBTokenChunker`，512目标／768最大／64章内重叠。
- B：切块前共同批准的原文区间，按原序连续区间运行同一个B版切块器。删除间隔不拼接；相邻或重叠批准区间合并。
- C：与B相同的准入内容，复用现有知识单元、依赖、表格、代码及超限策略；512／768，不增加滑窗重叠。

三组均只嵌入原文正文，不拼派生前缀。C使用正式切块器的实验副本；离线检查严格验证副本仅改变类名和前缀返回值，其他算法逐字相同。原有源码与封存证据不修改。

共同批准集合由K3最终准入和依赖检查决定，在分块前确定。缺未批准依赖的单元不进入B/C；已经批准却因原子代码超长等不能切块的单元仍保留在共同集合及评分分母。B必须覆盖完整批准字符，C每个输出字符必须在同一批准集合中。

真实数据使用已保存的5仓库和分类结果；28题重新从完整原文核定事实行，再补12题。R20的VITE_PORT原文确实存在，即使待审也计入来源可答题。R21的具体商业许可条款没有在README全文给出，仍是不可答题，不能把许可链接当条款。单独记录来源可答性、准入供给和召回覆盖，不强求过滤方案获胜。

6份构造资料独立报告，每份2题；用于长正文、必要条件、表头、版别、限长代码和超长原子代码边界。构造资料的准入由助手标注，经过现有投影及依赖保护，不代表真实分类模型结果。它们与真实仓库使用相同三个索引，以scope过滤隔离检索，不互相成为干扰项。

只运行固定版本本地bge-m3、1024维；使用三个相同配置Redis HNSW索引，获取完整候选，按同一余弦相似度及ID稳定顺序评分。每题查询向量只生成一次；3组交错查询、每组3次。完整排名与独立精确余弦Top10核对，避免近似索引误差混入小样本分块比较。没有关键词、名称、改写、cross-encoder或聊天模型。

分别计算K=1/3/5/10；来源可答题的分母不随准入或出块数量变化。直接证据、直接证据2048预算、C父单元恢复2048预算分别报告。预算按完整片段BGE-M3 Token之和计，C同一父单元去重，其他重复原文保留并计成本；超限跳过并记录，不截断条件，不从TopK之外补取。

调用清单在`requests.json`冻结：按完整输入文本去重、每批8条本地Embedding，失败计数，不自动重试；guard绝对上限50次，同时不得超过冻结清单次数。不读取云端密钥，不调用分类或聊天模型，不连接业务MySQL。专用Redis无宿主端口与业务数据挂载，256MiB内存限制。

执行：`prepare`生成来源和标签 → `offline`检查三组字符覆盖和原文位置 → `freeze`冻结源码、数据和请求清单 → `run`执行 → `verify`只读复验。所有阶段由`python scripts/readme_three_arm.py <阶段>`驱动。旧分类、分块、排序和客服验收在前后只读复验。

本轮是已知来源、助手标注诊断，不是独立人工评测；真实与构造指标不混合。不将本轮分块结果解释为网站回答准确率、最佳参数或正式替换资格。
