## K5：检索与问答效果对比（尚未实施）

使用相同原文版本、相同 Embedding/召回/rerank 配置比较未过滤基线与过滤版，避免同时换模型和分块后无法归因。开发集用于调参，验证集用于一次冻结配置评估；验证结果若用于调参，应另准备新验证样本。

建议至少 30 条有目标证据的问题，覆盖三个使用方式、否定条件、企业版边界、未知信息和错误仓库类型。另保留无答案、截断、冲突及跨任务问题。先准备问题和期望证据，再运行真实检索。

| 指标 | 怎么算 / 如何解释 |
|---|---|
| 标注知识保留率 | 被保留的已标注知识原文单元 / 应保留单元；单独看许可和否定条件 |
| 噪声去除率 | 被排除的已标注噪声单元 / 应去除单元；不能以字符缩减率代替 |
| REVIEW 比例 | 待复核单元 / 全部处理单元；展示去噪与覆盖的权衡 |
| Recall@5、MRR@5 | 目标项目与目标证据分开统计；只命中项目名不算证据命中 |
| 条件保持率 | 返回证据是否携带必要表头、版本、否定和产品归属 |
| 无依据断言/引用错误 | 用人工复核集逐条检查，不只让模型自评 |
| 延迟与成本 | 入库模型调用/Token、Embedding 量、检索 P50/P95、端到端耗时分开测 |

建议发布门槛：关键限制及引用错误为 0；目标证据 Recall@5 不低于同配置基线；已标注噪声去除率提升；新增错误案例全部复核。性能门槛需在本地基线实测后设置，不虚构提前达标。38 份定向样本只能发现边界，不足以代表全库效果或统计显著性。
