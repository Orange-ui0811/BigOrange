不是全库随机抽样，也不是 38 份全文逐行标注。来源是数据库已保存的正文，可能经过旧流程翻译或截断，未重新从 GitHub 抓取。判断是助手审阅，尚未经用户人工确认。

## 对当前设计的影响

1. **过滤单位应是带作用域和依赖的原文块。** 表头＋行、企业版标题＋功能、前置条件＋命令要一起保留，不能只按关键词或长度删段。
2. **增加仓库角色和条件强度。** 先区分应用/SDK/文档/问题库，再区分必须、建议、可选、不支持；未知不能写成 false。
3. **保留负向证据。** 无认证、非生产、兼容范围、迁移和许可例外会直接改变推荐结果。
4. **知识不足要显式可见。** 缺正文、图片独占信息、截断和未抓取的链接，不应由模型自动补写后入库。
5. **需要覆盖所有检索入口。** 当前目录候选仍会读取原文前 12000 字；将来只过滤 Redis 中的向量块，不能阻止噪声从目录路径回来。

完整规则和代码接入点见 [filter-policy.md](filter-policy.md)，阶段验收和具体回归问题见 [acceptance.md](acceptance.md)。
