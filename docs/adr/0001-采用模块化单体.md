# ADR 0001：采用模块化单体

- 状态：Accepted
- 日期：2026-07-25

## 背景

OrangeVC 由一个 Spring Boot 后端、两个 Vue 前端、MySQL、Redis 和 OSS 组成。当前主要风险来自模块耦合、任务不可控、测试不足和发布流程分散，而不是单机性能或服务容量。

## 决策

继续部署一个后端应用，按业务能力建立模块边界。新代码使用 `api/application/domain/infrastructure` 分层，旧代码在业务修改时渐进迁移。通过 ArchUnit 阻止基础模块反向依赖业务层，并逐步禁止跨模块直接访问 Mapper。

## 结果

部署和运维复杂度保持不变，新功能有清晰归属。未来只有出现独立扩容、故障隔离或团队所有权需求时才拆分服务。
