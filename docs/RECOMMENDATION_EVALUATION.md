# 推荐系统实验与验收

本文汇总已保存证据及其适用范围，算法实现见 [推荐系统技术说明](RECOMMENDATION_SYSTEM.md)。代码核对基线为 `e4eb584b`。检索指标、项目适配、最终答案质量和工程回归必须分别报告；目前没有覆盖四条推荐路径的独立盲测总体准确率。

## 1. 证据位置与复现原则

main 保留算法、常规测试、固定小样本和迁移验收工具；完整历史实验封存在快照提交 `3a26d9e2a332a6483cf78d2c66f9b8661bff165b`。下文链接固定到该提交，不依赖未来可能移动的分支，也不把全部原文/排名日志复制到首页。

历史脚本的 `verify` 主要校验账本、哈希和已存输出，不能等同重新执行模型或检索；部分脚本还依赖未进入 Git 的本机 staging、索引、模型和密钥。应在独立检出对应快照后按其说明复验，不应将旧哈希校验直接套到已重构的 main。本文更新不新增模型调用。

## 2. main 内的固定评测入口

[RagBEvaluationService](../orange-server/src/main/java/com/orangejd/server/ragb/service/RagBEvaluationService.java) 提供管理端评测：

| 资源/入口 | 范围 |
|---|---|
| [evaluation-dataset.json](../orange-server/src/main/resources/rag-b/evaluation-dataset.json) | 12 道固定 smoke 题 |
| [evaluation-benchmark-v1.json](../orange-server/src/main/resources/rag-b/evaluation-benchmark-v1.json) | 60 道固定回归题 |
| `POST /admin/rag-lab/evaluation/run` | smoke；需管理员、B 开关及可用活动索引 |
| `POST /admin/rag-lab/evaluation/benchmark/run` | benchmark；结果与配置保存在实验记录 |

它将 A 的 VectorStore 搜索与 BSearch 在当前数据/参数下比较。它不是自动执行整个 `TrendV2Analyzer`、客服追问与最终生成的端到端评测。

- `SourceRecallAtK` 实际是有目标来源的题中，TopK 命中任一预期 sourceRef 的题目比例，不是全体相关文档的传统 Recall。
- 原文可追溯性检查源文档、版本和区间；citation readiness 是启发式就绪度，不等于逐句支持。
- 拒答指标检查检索策略与预期是否匹配，不等于最终客服拒答正确率。
- P50/P95 只对应本轮环境与样本。不能跨语料规模、缓存、并发、模型或索引版本直接拼接延迟。

固定题用于开发和回归，已用于调试的题不能再称为独立盲测。运行会发生 Embedding 等实际推理请求，应使用独立索引、记录调用账本与费用边界。

## 3. B 版追加 Reranker：24 题有界比较

证据：[封存报告](https://github.com/Orange-ui0811/BigOrange/blob/3a26d9e2a332a6483cf78d2c66f9b8661bff165b/docs/rag-b/reranker-v1/report.md)、[逐题评分](https://github.com/Orange-ui0811/BigOrange/blob/3a26d9e2a332a6483cf78d2c66f9b8661bff165b/docs/rag-b/reranker-v1/evaluation.json)。

已有助手标注的 16 道语义题、4 道点名题、4 道业务规则题；同一活动 B 索引，每题冻结同一个原生 Top20 候选池，比较原排序与 Gitee `bge-reranker-v2-m3`。这批候选已经过原 B 的筛选与多样性选择，不是后续正式服务的 80 条重排接入实验。

| 16 道语义题 | 原 B | 冻结候选追加重排 |
|---|---:|---:|
| 目标项目命中@1 | 7/16 | 14/16 |
| 目标项目命中@8 | 13/16 | 14/16 |
| 目标项目 MRR@8 | 0.585 | 0.875 |
| 字面关键原文命中@1 | 5/16 | 12/16 |
| 字面关键原文 MRR@8 | 0.464 | 0.776 |

点名题来源@8 两组均 4/4，规则题策略匹配均 4/4。新增网络重排耗时 P50 722 ms、P95 801 ms，是单次顺序采样，不是压测或整个客服响应时间。

已证实：在这个候选池和已知题集上，相关项目及标注原文的前排位置明显改善。未证实：全库准确率、完整事实/限制覆盖、最终推荐正确性或线上收益。

失败保留：`fresh-08` 原文从第 3 位退到第 6 位；LangGraph 的 `fact-20-zh`、`fact-21-zh` 所需事实不在 Top20，无法靠该候选池的重排补回。目标只标了部分项目/字面锚点，因此不报告通用 Precision 或完整相关性 nDCG。

## 4. 正式服务中的 Reranker 接入验收

证据：[接入报告](https://github.com/Orange-ui0811/BigOrange/blob/3a26d9e2a332a6483cf78d2c66f9b8661bff165b/docs/rag-b/reranker-integration-v1/report.md)、[失败与修正记录](https://github.com/Orange-ui0811/BigOrange/tree/3a26d9e2a332a6483cf78d2c66f9b8661bff165b/docs/rag-b/reranker-integration-v1)。

从旧题中选 8 道回归，使用相同活动索引。接入位置改为过滤/去重之后、项目多样性之前，对最多 80 条候选分批重排。4 道语义题的目标项目@8 从 1/4 到 3/4、关键原文@8 从 1/4 到 3/4；3 道业务策略两组均匹配，2 个禁用开关检查复现旧结果。子集指标有交叠，不得把分母直接相加计算总准确率。

接口实际限制每次 1–25 项，首次直接发送 80 项失败；改为每批 20 项。另一次回归暴露“免费功能/许可链接”误当商业许可价格证据，修正价格证据门禁后重新验收。失败记录未删除。

`fact-20-zh` 在较大候选池里可以找到，`fact-21-zh` 仍缺失。这里同时有候选池和接入位置变化，不能和上一节的 16 题数字直接混算。69 项相关单测和 8 题接入回归证明的是有界工程接入，不是总体推荐准确率。

## 5. 新 README 链路：三组纯向量对照

证据：[三组报告](https://github.com/Orange-ui0811/BigOrange/blob/3a26d9e2a332a6483cf78d2c66f9b8661bff165b/docs/rag-b/readme-filter-v1/retrieval-three-arm-v1/report.md)。注意实验组 A/B/C 的命名不等于网站的知识库 A/B 版本。

5 个冻结仓库：AnythingLLM、Flowise、n8n、Appsmith、Docguard。40 道真实题中 35 道原文可答；另有 6 份构造结构样本、12 道题，单独报告。助手标注，非独立人工盲测。

| 实验组 | 输入与切块 | Top5、2048 BGE Token 预算完整证据（真实） | 构造题 |
|---|---|---:|---:|
| A | 完整 README＋B 版结构切块 | 32/35 | 12/12 |
| B | 共同批准原文＋同样结构切块 | 20/35 | 11/12 |
| C | 同一批准原文＋知识单元切块 | 28/35 | 9/12 |

三组共享模型、查询向量及索引参数；正文向量检索，关闭派生前缀、关键词/名称加分、查询改写和 Reranker。目标/上限固定 512/768，不是长度调参实验。原文有答案但未准入计为遗漏。

结论：C 在已批准内容的组织上优于原实验 B，但完整来源口径仍输给 A；不能宣称过滤链路整体更优或分块策略最优。长代码/原子单元超限也导致构造题丢失，不能用更少返回内容冒充质量提升。

## 7. 工程验收与未覆盖的业务效果

[精简集成验收](releases/2026-11-02-customer-ragb-integration.md) 和 [主分支 CI](https://github.com/Orange-ui0811/BigOrange/actions/runs/41460071840) 记录：后端跨任务合计 1053 项通过，5 项历史/导出/真实模型测试未启用；用户端 164、管理端 5、浏览器 18 项通过，1 项真实身份浏览器场景未启用。MySQL、Redis 和本地 HTTP 替身分别验证了持久化、隔离、检索、去重、SSE 与降级；没有把 skip 当作 pass。

新手/职业规则目前有单测和发布校验，没有已保存的独立用户适配排名 benchmark。规则能解释其分数，不证明学习效果、求职成功率或真实用户满意度。客服也没有经独立用户验证的“平均几轮找到合适项目”结论。

## 8. 后续评测约定（尚未执行）

新增实验先冻结项目版本、索引 generation、用户任务、预期事实与限制、模型、预算和候选上限。分开报告：候选覆盖、排序、硬约束冲突、完整证据、推荐解释、追问收益、轮数、延迟与调用成本。调参集与最终保留测试集分开，模拟用户结果与真实用户结果分开。

项目推荐对照建议使用同一目录/知识版本：当前策略 → 强化逐需求匹配 → 加动态追问。静态排序比较共享相同已知信息；交互比较固定用户真实需求与允许揭示的信息，不能让某组提前看到答案。多项目都可能适合，应标注完整的相关性与不适配原因后再使用 nDCG/Precision 等排名指标。

当候选缺失、限制遗漏或关键事实未核实时，先定位准入、分块、召回、排序还是预算问题，再决定调整环节。以上是后续方案，不能列入当前已实现效果。
