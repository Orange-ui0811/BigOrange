# LangGraph4j 替换前验收续跑（2026-10-08）

本轮在相同模型、Prompt、B 索引和业务策略下继续验收。公开入口仍为 LEGACY；不是部署成功报告，不将本地验证替代服务器和观察期。

## 修复与冻结

- `CustomerTopicCoverage`：仅当推荐／收集请求缺少 topic 操作时，从本轮连续原话恢复有限集合的明确技术主题。保留显式 SET/CLEAR/REMOVE；否定、例子、引用和知识问答不自动成为推荐条件。没有额外模型调用。这是保守漏项防线，不保证任意自由表达均被理解。
- `CustomerMysqlCheckpointSaver`：每个 run 独立缓存已持久化检查点；第一次读取加载数据库历史，后续读取本请求内快照。每次写入仍同步落库，失败不会更新缓存，读出的嵌套状态有独立副本。没有共享跨请求状态，没有开启恢复。
- 20 个新表述场景冻结于 [independent-cases.json](independent-cases.json)，运行前已保存 SHA256。新旧引擎各两轮；两个多轮场景从真实推荐开始，再分别比较和查询第二项详情。80 个场景执行对应 88 个实际请求，不把重复执行算作 40 个独立场景。
- 旧题标准及旧报告保留，新增回归题在 [full-cases.json](full-cases.json)，不重写之前误计的 40/40。
- [source-manifest.json](source-manifest.json) 记录源文件及冻结题集哈希。

失败核对：

- N10两套两轮都只保存了“图书管理”topic，未保存“给自己的书店使用”goal。后续检查四份原始合成动作（full-synthetic-goal-actions.json）确认模型都已提取goal，真正失败在Java自定义目标的词面来源校验，见后面的根因修正。
- N18图编排第一轮：推荐种子返回INVALID_PURPOSE_REVIEW，错误为摘录超过12–180字符边界。最初输入接近6000字符预算，追加纠错反馈无法放入，未执行第二次尝试；后续COMPARE正确识别意图但没有可比较的先前候选，整体失败。第二轮图以及旧编排两轮完成了真实候选比较，不能把该差异直接归因为图路由。
- N12的RAG／180天条件保持，抽查仓库身份、章节摘录与引用关联可核对；N13仍可能只返回资料不足的参考卡，无引用的卡片保持importable=false。抽查不等同于逐句人工事实验收。

针对失败新增两处共享修复，生效于两套引擎：

1. CustomerGoalCoverage只在明确要求记录用途且缺少goal操作时，保留连续第一人称用途原话；不覆盖显式修改／取消，不从例子、引用、第三人称或多种歧义用途中强行选取。仍不是任意自由语义的通用提取器。
2. 用途核对输入预留512估算Token（当前估算为字符数）供有界服务端纠错反馈。保留同一候选输入、同一连续摘录规则、总输入上限和最多两次尝试，不通过修改无效摘录放行。预留空间可能减少尾部送审候选，因此修复后的完整行为仍需复验。

修复后的离线223项通过。repair-cases.json从冻结集复制N10和N18，准备单独的12请求复测；这些已用于修复的场景此后属于回归案例，不再标为未用于调参的独立验收题。post-batch-source-manifest.json记录修复后源码，不能将原88请求结果视为这些新代码的完整验收。

### 12请求复测结果与第二次根因修正

12请求全部进入明确终态，两套各6请求。两套均2/4场景通过：N18推荐后比较两轮全部通过，N10两轮全部失败。LEGACY模型尝试22次、已报告68139 Token、P95 19.150秒；图同为22次、65936 Token、P95 15.441秒；两边均2次失败尝试及2次纠错重试，缺用量0，金额仍未知。原始结果保留在repair目录。

读取限定本轮4个合成N10运行的动作，发现模型均已提取goal，例如“自用书店图书管理”，quote也确实是用户原话。真正失败点是CustomerGoals要求自定义goal值必须为quote的连续子串，模型改写的词面没有通过，CHAT逐字段处理随后丢弃了goal。第一次“缺字段才补全”的修复未覆盖这个问题。不得将此归为模型完全没理解，也不得将修复未生效的12请求统计为通过。

第二次修正：在明确记录、肯定的第一人称用途、单一SET、自定义值且quote真实覆盖用途的条件下，保存用户连续用途原话，代替不受原文支持的改写值。有效预设、原文目标、ADD/REMOVE/CLEAR、多目标、未落在当前消息中的quote继续走原规则，不放行模型虚构值。保留4份合成动作在synthetic-goal-actions.json；最新代码哈希见goal-provenance-source-manifest.json。该修复及历史基线246项离线回归全部通过（checks-goal-provenance/checks.log），尚未完成新的真实调用验收。

最后8请求目标保存复验已完成，见goal-provenance-validation/repair目录。两类明确自用用途（书店／实验室）两套各两轮，均4/4通过、8请求全部SUCCEEDED；每套4次模型调用，失败／重试0、缺用量0，没有检索或证据外发。模型输入由专用ACTION-only保护检查提示词、冻结消息、空画像、空摘要、空历史及最多8个动作调用，内部每次仍至多两次尝试。LEGACY已报告24404 Token、P95 7.117秒，图24992 Token、P95 7.137秒，金额UNKNOWN。保护添加前停止过一次尚在编译中的启动，没有创建run或调用模型，记录在同目录scope-guard-preflight*。

针对性通过不能回写原88请求分数，也不能视为修改输入预算后整套独立题集已通过。当前还需要完整复验、部署回退和观察期门槛；releaseApproved保持false。
