## 根因与改动

1. 原客服知识工具等待 15 秒，而共享 Embedding HTTP 的连接、读取超时分别为 30 秒；`Future.cancel(true)` 不保证原阻塞 I/O 立即释放。工具池两个线程配 `SynchronousQueue`，未释放请求及任务完成交接窗口都可能使后续请求被拒绝。
2. B 的 bge-m3 **查询**改用 Java HTTP 客户端，支持中断：连接最多 3 秒，HTTP 最多 8 秒，含并发等待最多 12 秒，并取工具/整轮剩余时限的较小值。每进程同一查询客户端最多一个在途请求；429 后至少冷却 30 秒，尊重更长的 Retry-After。无新增自动重试，不把限流转成无匹配。超时阈值是工程初值，并非供应商延迟承诺；完整成功链路仍待实测。
3. 工具池仍两个工作线程，新增容量 2 的有界队列；取消移除排队任务，工作执行前后检查取消和终态；显式传递截止时间，离开工作线程清理上下文。工具错误保存规范化错误码。此限流只约束本进程 B 查询，不控制其他部署、旧 A 请求或离线入库，不保证供应商配额可用。
4. 文档入库继续用原批量 transport；A、bge-m3 模型、向量维度、分块、融合权重及 TopK 均不改。
5. v4.20 提示词明确：根据知识库/项目资料归纳一类项目也属于 QUESTION；CHAT 误判时增加窄范围证据边界保护。不把普通技术概念、问候、明确不检索的话统一送入检索。补充自定义用途 goal 与功能 topic 可同时保存的规则。两个引擎共用修复；本轮是修复实验，不冒充纯框架无策略变化实验。
6. Compose 显式传递引擎及原文开关，默认仍 LEGACY / false。修改容器环境变量后必须重新创建容器，restart 只用于加载代码，不刷新环境配置。
