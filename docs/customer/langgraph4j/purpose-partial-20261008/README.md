# 用途核对输出与重试预算复测（2026-10-08）

本轮只改用途核对协议、预算与错误治理。B 索引仍为本地 bge-m3 的 generation 4；分块、融合、TopK、推荐硬条件、普通聊天思考开关不变。公开入口仍为 LEGACY。原始验收题和自动判定标准不变。

## 失败证据及修复过程

1. [原始小批](../local-m3-20261008/smoke/provider-acceptance.json)：LEGACY 的 S03 用途核对第一次输出 4,096 Token 全用于思考，随后重试网络失败；LANGGRAPH4J 同题当次成功。这不是框架质量差异的充分证据。
2. [仅预算修正的小批](../purpose-budget-20261008/smoke/provider-acceptance.json)：用途核对改为非思考后耗时约 1.8–2.1 秒，但 200 字符的英文摘录违反 180 字符上限；另一轮还生成了错误项目类型。两套编排均因整批校验失败没有推荐。
3. [增加纠正重试的小批](../purpose-output-20261008/smoke/provider-acceptance.json)：错误被提前检测、失败 Token 被记录，但模型补试仍返回超长摘录。两套编排仍为 3/4，未启动全量对照。其 checks 目录中的 exit 143 是人为停止编译中间版本，不计为通过；checks-final 的 108 项测试通过，只对应此中间实现。

最终选择：尝试纠正一次后，逐项保留严格校验通过的用途证据，避免单个坏摘录丢弃整批好结果。没有有效条目仍返回核对不可用。

## 最终实现

- `CustomerProperties`：用途核对独立配置，默认非思考、输出 2,048 Token、阶段 30 秒、预留重试 10 秒。
- `CustomerModel`：首次调用最多约 20 秒；所有尝试共用原始阶段及整轮截止时间，最多两次。普通补试至少剩余 8 秒，截断补试至少剩余 10 秒。
- 截断时：若开启用途思考，补试关闭该阶段思考；原本非思考则增加输出额度，上限 8,192。不重试审核拒绝或其他不可重试的 4xx。
- 输出身份、关系类型、摘录长度及连续原文检查在模型调用结束后执行。格式错误补试只增加服务端生成的错误码与纠正指令，原候选和用户输入不变；补充提示仍受 6,000 估算 Token 上限约束。
- 补试仍有坏条目时，仅保留已通过全部输出检查的条目。不会修改、猜测 ID，也不会截断、改写摘录。超过 12 项或全部无效的输出仍失败。
- `CustomerPurposeMemory`：部分结果只缓存通过的正向证据，其他候选保持待核对，不能缓存为不相关；既有范围、版本、TTL、硬条件检查继续有效。
- `CustomerRecommendationSteps`：部分核对结果附带明确提示，所有项目仍走现有条件、证据、事实支持和导入资格校验。
- 失败和成功尝试均记录额度、思考开关、时限、输出结束原因；失败额外记录重试决定、剩余时间及协议错误码。已返回的用量只记一次，没有用量或价格时保留未知。

## 人工复核发现的发布阻断

**自动 40/40 并不代表语义全部正确。** LEGACY 的 H12 第一轮要求 Python、检索增强生成、求职、半年，但模型返回 `changes={}`，会话没有保存主题，推荐变为 repowise、LightX2V、MLflow。该轮缺少 RAG 用途依据；原冻结自动条件只要求 Python、180 天和存在项目，因此误记通过。详见 [semantic-audit.json](full/semantic-audit.json)。不修改旧题标准来重写本轮成绩，也不将这一例隐藏在总体通过率中。

该例也解释了完整题集两套编排的两次模型调用差：LangGraph4j 同轮正确提取主题，因此多执行 QUERY_PLAN 与 PURPOSE_REVIEW。它来自本轮模型提取差异，不能据此认为图框架强制多调用两次，也不能认为旧编排更省费用就更好。其余对应案例的模型阶段顺序一致；真实生成仍有随机性。

后续需单独修复意图／条件提取的漏项防线，并在新的独立语义验收中明确要求主题、用途匹配；同时核对事实支持及完整历史详情／比较（H18/H19 本次只有空历史追问）。服务重启、生产负载、固定响应百轮编排开销和服务器观察期也不能由本轮报告替代。
