# v4.18 来源用途证据优先

用户报告“按当前条件查找项目”在 PURPOSE_REVIEW 阶段返回 HTTP 400 / CONTENT_EXISTS_RISK。v4.17 能准确解释失败，但新会话没有用途缓存，整批在线核对仍会阻塞推荐。

## 本次实现

- 新增 `CustomerPurposeCatalog` 和 `customer/purpose-evidence.json`。这是可审核、随版本发布的公开项目用途证据账本，不是根据任意关键词自动放行，也不是把聊天记录共享给其他用户。
- 首批逐句核对五个公开项目：LangChain、LangGraph、Dify、Quivr、AxisAgentic。记录短原文、仓库身份、来源字段 SHA-256、文档版本（适用时）及经过核对的方向关系。标注方法为 CODEX_SOURCE_REVIEW，不能宣称人工验收。
- 使用前检查当前仓库、来源内容、文档版本、连续原文以及原始主题范围。只覆盖明确的 AI 应用开发、Agent、RAG 及代码中列出的等价表达。未覆盖的自由主题继续走已有语义核对；多主题、额外使用对象、否定或更细场景不会自动继承宽泛方向许可。
- 在已执行硬条件筛选的候选池内，用有效用途证据补充提名，避免受初始向量前 20 个片段的截断完全限制；最多补入三个，整体提名仍不超过十二个。
- 将符合当前主题的离线证据写入本会话受约束的用途记忆，保持当前源指纹与后续硬条件复查。来源账本版本加入策略签名，更新或撤销账本会使旧会话判断失效。
- 已有至少三个通过当前条件检查的项目时，不再为了核对其他候选等待整批模型结果；部分未核对内容保持未知并明确标记结果不完整。若只有一个或两个已有依据的项目，在未处于审核暂停时仍可补充核对；核对失败时保留有依据的结果。
- 审核拒绝后的五分钟内，同主题的在线核对暂停，即使离线依据使待核对列表发生变化，也不裁剪原拒绝批次重发。允许交付独立核实的本地结果；没有有效依据时仍明确不可用。
- 在线核对前记录候选 key 与请求哈希，便于审查定位；不把候选原文、账号画像或令牌放进新增审计字段。
- 不改变生成、引用、硬条件、账号权限或正式方案导入门槛。用途有依据不等于语言、周期、资源条件全部满足，也不等于所有细节已经得到引用支持。

## 维护与回退

来源账本是首批五项，不能声称全库已经离线加工。扩展时需阅读功能原文及上下文、核对关系并增补证据；不能把模型失败或关键词命中写成批准。`scripts/build_customer_purpose_catalog.py` 只冻结显式批准清单，已有来源内容或版本变化会报错，必须重新审查，不能自动刷新许可。`scripts/export_customer_purpose_fixture.py` 导出公开项目到忽略目录 `.tmp`，供离线回归。

无数据库迁移、A/B 索引变化或用户会话删除。需要回退时使用上一版应用及资源文件。关闭全部离线用途许可可将账本 facts 设为空列表并重新部署；账本哈希变化会自动失效相应会话缓存，恢复在线核对路径。不要通过原样反复重试、混淆或替换被拒内容来规避供应商审核。

剩余工作：拓展经过审查的用途证据覆盖；建立后台离线加工与人工复核入口；提高项目语言/周期字段覆盖；独立模型生成与引用评测；真实持续容量测试。当前不是全自动离线标签生产系统。

本地部署验收：后端已加载 `customer-v4.18-source-purpose-evidence`。新建合成测试会话的三轮 HTTP 检查通过（流程解释、失败诊断、查询条件），验证登录归属、条件保持、幂等与历史；外部模型调用0次，测试会话已软删除，详见 `http-smoke.json`。不包含真实模型推荐卡片生成验收。
