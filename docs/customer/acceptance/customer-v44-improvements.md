# 多目标与推荐卡片改进验收

2026-10-03，本地 OrangeJD。提示词版本 `customer-v4.4-multi-goal-cards`。

## 原因与修改

1. 客服提示词与 Java 校验都把 goal 限定为学习、求职。现在支持最多 6 项目标，可使用预设或用户明确原话；兼容原有单字符串会话。SET 替换、ADD 追加、REMOVE 移除、CLEAR 取消。账号画像只补充未指定且未取消的目标。预设目标由模型做语义归一化，Java 检查结构、原话来源和边界，不再次按关键词拒绝“挣点外快”等表达。目标是偏好，不直接限制来源分类。
2. 用户可以在“目标设置”多选学习、求职、赚钱/接单/创业、探索技术兴趣，填写自定义目的。保存走现有用户消息与运行链路，保留鉴权、请求去重和条件来源记录；不绕过状态校验直接写库。
3. 原新手加分只识别中文，数据库实际包含 BEGINNER/EASY/MEDIUM/ADVANCED。现在统一难度，并结合新手评分、仓库规模；大型仓库降低新手排序分并提示应限定小任务。语言、资源、显式难度与周期的已知冲突仍排除。
4. 原排序先按缺失字段数量排序，容易把周期明确的高级项目排在适合新手但周期缺失的项目前。现在综合相关性、基础、目标、资料质量与不确定惩罚排序。未知字段仍不宣称满足条件，也不允许凭这类候选导入方案。
5. 原推荐理由固定为主语言和技术栈，没有使用现有分析。现在卡片附带已有学习/职业分析、改造方向、资源前置、风险、能力证明和通过本轮验证的证据说明。已有分析与本轮引用核对分别标注，不把数据库中的模型分析视为已验证引用。
6. 客服和智能分析共用 `ProjectRecommendationCard`，统一编号、标题、难度、评分、说明和方案入口。客服显示的“资料评分”来自现有项目质量数据，不是个性化匹配概率；没有质量分时不伪造数字。原来源核对提示与安全链接仍保留。
7. 新回答保存与旧回答显示均处理重复转义段落。Markdown 代码片段、路径、原始证据引文不改写。

## 使用与边界

打开客服右上“目标设置”；也可以说“既想学习又想求职”“还想接单”“求职先不考虑”“想给家里的店做库存管理”。直接问“目前支持哪些目标”时返回服务端能力事实。

已有历史卡片不会重新计算排名，需发起新一轮推荐。旧回答中的转义换行会在显示时修复。
新目标不自动成为长期画像，也不会自动放宽其他硬条件。没有足够证据的项目仍可探索，不能导入正式方案。原数据库里的难度、周期和已有分析质量仍需逐步校准；此次没有修改这些原始资料，也没有证明每个自定义目标都已有足够项目或引用支持。

本次为本地代码交付，不删除 A、不迁移旧推荐入口、不执行生产发布。
