# OrangeJD 项目推荐客服实施与验收

最新的通过项、失败项及待审批范围记录在 [ACCEPTANCE.md](ACCEPTANCE.md)。本地构建通过不代表全部阶段出口通过，也不代表当前运行容器已加载最后的修复。

本模块保留 A 版旧入口，客服使用 B 版。功能默认关闭；本地白名单验收仅授权账号 5 和 admin（账号 1）。普通用户不开放、不扣额度。实现是受控 Java 状态机，不引入 Python 在线服务。

## 代码与数据

- `orange-server/.../customer/`：会话、运行、条件、工具、证据、模型调用、同步与导入校验。
- `AppCustomerController`：独立 `/app/customer` 接口，账号由鉴权上下文注入。
- V41：新增客服会话、消息、运行、步骤和执行互斥表；不复用 `trend_history`。
- `orange-web/src/components/CustomerChat.vue`：独立 `/customer` 页面和左侧“项目客服”导航。参考本地 DeepSeek Harness 的会话布局、上下文预算和用量面板，保留 Java 执行及 MySQL 会话存储；不引入 Node 在线运行时。过程通过 SSE 展示，完整结果在服务端校验后展示；断线查询原运行。
- `cases-v1.json`：60 个分层用例，40 个开发案例、20 个独立验收案例。规则说明不等于已经通过。
- 平台 FAQ 草稿在 `platform-faq-draft.md`；管理员核对后通过 `POST /admin/customer/knowledge/faq` 以 key/title/content 发布，进入 B 版本与索引任务。未发布的平台政策不能用项目 README 代替。

## 一轮执行

1. 验证白名单与会话归属；在真实 MySQL 事务锁内执行请求去重与并发限制。
2. 读取确认画像与会话状态，模型只提出带原文依据的意图、条件变更；服务端校验后更新条件。临时条件不写长期画像。
3. 知识问题使用 B 检索；项目请求先检查真实业务库中发布状态、主语言、明确资源限制、难度及周期。未知资源和周期不能当成满足硬条件。
4. 按历史项目列表解析位置指代，获取相关 B 章节；截断工具结果与历史，满足输入预算。
5. 服务端给引用子片段编号，每段上限约 400 字符。模型选择编号并返回中文解释，服务端恢复原文；入库仍沿用结构分块策略。先校验编号与原文，再用独立评分请求核对事实支持；不支持的解释被删除，全被删除时拒答。
6. 保存结果、条件、原始消息、步骤与全部模型尝试。取消、超时后的迟到回答不能覆盖终态。
7. 带入方案编辑器前，再校验本人成功运行中的项目、当前发布状态与条件、证据版本；服务端产生草稿，用户仍在原方案编辑器确认与生成。

## 固定边界

同账号一个运行，全局最多两个；每轮最多 5 次业务工具，其中知识检索最多两次。整轮 90 秒，单模型调用最多 45 秒且受剩余期限约束。仅 429、5xx 或传输异常最多重试一次。输入按 Unicode 字符数保守估算，预算 6000；输出 1500。此估算不是模型精确 tokenizer。

当前注册四个只读业务工具：`searchKnowledge`、`searchProjects`、`getProjectDetail`、`getConfirmedProfile`。模型的原生函数只提交受校验的 `customerAction`，业务执行路径由 Java 决定。没有开放任意工具、SQL 或自主多 Agent 循环。

工具分别限制知识检索 15 秒、项目查询 10 秒、详情及画像 5 秒，且不得超过整轮剩余期限。独立工具线程池最多两个，不无限创建后台任务。外部连接取消未必立即结束，迟到用量仍需保存。

B 索引必须是 `bge-m3`、`STRUCTURE_M3_512_768_64_V1`、`HNSW_HYBRID`；检索异常不回退 A。检索参数分别为每路候选 128、融合候选 80、最终证据最多 8；客服再限制 4200 字符证据，单片段最多 1600 字符。未引入模型 Rerank。项目初选仍以严格业务条件和既有资料质量分排序，语义推荐及个性化权重需要后续对照实验验证。

## 验收口径

`acceptance/` 保存实际测试输出，不能把 HTTP 成功或有引用编号当成质量通过。

- 后端确定性测试覆盖归属、请求重放、条件校验、供应商有限重试、证据、导入和工具边界。
- 隔离 MySQL 实测先建立 V40，再升 V41，并验证事务去重、并发和取消；不修改旧业务资料。
- 浏览器模拟验收覆盖界面与恢复，但不代表真实登录和真实回答通过。
- 真实供应商探测只发送合成输入。DeepSeek V4 客服调用关闭思考模式；Schema 与原生动作协议均已实测。失败且未返回用量的请求费用标记未知。
- 真实 HTTP 测试采用短期签名测试身份通过现有鉴权，不能代替交互登录验收。
- Python 报告保留未人工核对项；金额未知时不填 0。独立验收两轮至少 36/40，任一关键失败阻止发布。

## 配置、运行与回退

2026-10-03：客服模型独立配置为 `CUSTOMER_MODEL=deepseek-flash`，共用现有文本供应商端点与凭据；其他平台文本调用仍保留原模型。官方说明旧名 `deepseek-v4-flash` 已转到 V4.1 Flash，因此使用推荐名称。客服理解、生成、支持性核对统一用 Flash，不自动升级 Pro。默认关闭思考模式，保障结构化结果预算与时限；Flash 的实际质量和费用需重新验收，不能沿用 Pro 结果。依据：https://api-docs.deepseek.com/quick_start/pricing-details-cny/

已完成合成开关对照，见 [FLASH-THINKING-COMPARISON.md](FLASH-THINKING-COMPARISON.md)。当前 `CUSTOMER_THINKING=false`；配置 true 可开启，仍受 1500 输出 Token 和 45 秒模型调用预算约束。该合成实验不等于客服独立案例验收通过。

补充（2026-10-03 用户试用）：按用户要求，本地 `.env.local` 已持久配置 `CUSTOMER_THINKING=true`；修复思考模式的指定工具参数兼容。原合成报告的关闭思考建议保留为历史结论，本地实际开关以最新配置为准。半年问题与单样本补测见 [CHAT-V3.md](CHAT-V3.md)。

默认 `CUSTOMER_ENABLED=false`。本地试用配置 `CUSTOMER_ENABLED=true`、`CUSTOMER_ALLOWED_ACCOUNTS=5,1`；已验证的 DeepSeek 可设 `CUSTOMER_NATIVE_ACTIONS=true`，其他供应商先探测，不支持时使用 Schema 动作。

关闭 `CUSTOMER_ENABLED` 并按既有发布流程重启，独立客服页显示不可用原因；原自由提问页签已移除，现有项目推荐等旧入口继续保留。客服数据和 V41 表保留；不删除 A 数据、旧索引或会话。运行关闭后工具检查会阻止继续执行，未完成运行在下次开启服务时标记中断。

生产发布前必须备份数据库并核对 Flyway 版本、SSE 代理关闭缓冲、容量与费用记录。执行器和重启恢复目前按单实例设计；多实例部署必须先增加实例租约与归属恢复，不能直接扩大副本数。

初次真实容量测试：20 轮、两账号，P95 7563 毫秒，5 轮引文校验失败；全部在 90 秒内进入终态，归属、去重、SSE 首次事件和取消检查通过。已修正为服务端恢复编号原文，但修正后的真实评测尚需外发授权，不能沿用初次结果宣称通过。

冻结时旧库共 572 条记录，203 条有非空 `original_content`。活跃 B 代际记录模型 bge-m3/1024 维、219 文档、6227 片段；代际计数不应当作后续增量入库的实时数量。发布学习项目 39 个，没有 Java，Python 4 个、TypeScript 21 个、JavaScript 13 个、Rust 1 个。资源字段非空只能说明数据库有记录，来自仓库信号的推断还需要抽样核对，不能宣称全部经过人工确认。
