## 设计复核要点

- 指代消解输出对象引用和来源，不仅是一句改写文本；改写不创造新要求。
- 当前已有位置解析，改造是前置与增强，不重复搭建另一套不一致的身份规则。
- 需求版本、会话并发版本、候选列表版本、单轮运行状态各自有职责。
- PRESENTED 不等于 COMPLETED；SELECT_PROJECT 不等于导入成功。
- 任意需求未知不等于满足；部分满足硬要求不能被评分掩盖。
- 搜索扩展有前提和预算；不能保证找到项目，故障不能冒充缺知识。
- 候选差异追问在本阶段使用合成资料，真实收益仍待验证。

## 验证执行方式

在仓库根目录运行：

```powershell
& .\docs\customer\workflow-v2\validate-contract.ps1
```

脚本只读取此设计包和所列代码路径，并在设计目录写入 validation-report.json。结构检查失败会返回非零退出码。需要人工按 route 和 serviceFixture 审阅语义，不能以 JSON 合法代替业务正确。
