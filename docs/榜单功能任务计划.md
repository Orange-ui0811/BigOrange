-- 全时段
SELECT w.id, w.title, w.summary, w.cover_url, w.owner_id,
       u.username AS owner_name, c.name AS category_name,
       COUNT(f.id) AS favorite_count
FROM work w
LEFT JOIN account u ON w.owner_id = u.id
LEFT JOIN category c ON w.category_id = c.id
LEFT JOIN favorite f ON f.target_type = 'WORK' AND f.target_id = w.id
WHERE w.audit_status = 'APPROVED' AND w.visibility_status = 'PUBLIC'
  AND (c.id = #{categoryId} OR #{categoryId} IS NULL)
GROUP BY w.id
ORDER BY favorite_count DESC
LIMIT #{limit}

-- 本周（f.create_time >= 本周一 00:00）
-- 同上，增加: AND f.create_time >= #{weekStart}

### Step 2.3 — 创建 `AccountMapper` 新查询

// 本周

**SQL 逻辑**：
```sql
SELECT a.id, a.username, up.avatar_url, up.bio,
       COUNT(f.id) AS total_favorites,
       COUNT(DISTINCT w.id) AS work_count
FROM account a
LEFT JOIN user_profile up ON a.id = up.account_id
LEFT JOIN work w ON a.id = w.owner_id AND w.audit_status = 'APPROVED'
LEFT JOIN favorite f ON f.target_type = 'WORK' AND f.target_id = w.id
WHERE a.role = 'USER'
  AND (f.create_time >= #{weekStart} OR #{weekStart} IS NULL)
GROUP BY a.id
HAVING total_favorites > 0
ORDER BY total_favorites DESC
LIMIT #{limit}
```

### Step 2.5 — 创建 `LeaderboardServiceImpl`

**目标**：实现四大榜单查询逻辑

**输入**：`ILeaderboardService`、Mapper、`RestTemplate`、Redis

**新增文件**：`orange-server/src/main/java/com/orangejd/server/service/impl/LeaderboardServiceImpl.java`

**核心逻辑**：

| 方法 | 逻辑 |
|------|------|
| `getWorks` | period=week → 计算本周一 → 调 Mapper weekly；否则调全时段 Mapper |
| `getCreators` | 同上 |
| `getGithubRepos` | period=week → `created:>本周一` + `topic:xxx` → 拼 GitHub API URL → RestTemplate 调 → 缓存到 Redis 30min |
| `getGiteeRepos` | `q=分类名` + `sort=stars_count` → 拼 Gitee API URL → RestTemplate 调 → 缓存到 Redis 30min |

**GitHub API 调用**：
```
GET https://api.github.com/search/repositories
  ?q=topic:{topicName}+created:>{isoDate}
  &sort=stars&order=desc&per_page={limit}&page={page}
Header: Authorization: Bearer {githubToken}
```

**缓存 Key 设计**：
```
leaderboard:github:{topicName}:{period}:page{page}
leaderboard:local:works:{categoryId}:{period}:page{page}
leaderboard:local:creators:{period}:page{page}
```

**降级策略**：
- GitHub API 超时 5 秒 → 返回缓存数据 + `msg: "外部数据获取失败，展示缓存数据"`
- 无缓存 → 返回 `msg: "外部数据暂不可用，请稍后重试"` + 空列表

**输出**：1 个 Service 实现类

## Phase 1：图谱数据 API

### Step 1.1 — 创建 `KnowledgeGraphService`

**目标**：从 `leaderboard_snapshot` 读取数据，构建 Topic 级图谱节点和边

**输入**：`leaderboard_snapshot` 表、Category 表

**新增文件**：`orange-server/.../service/KnowledgeGraphService.java`

**核心逻辑**：

```
1. 查本周快照: SELECT topic_name, data_json FROM leaderboard_snapshot
   WHERE source='github' AND period='all' AND snapshot_date = 本周一

2. 对每个 topic 的 data_json 解析:
   - total_stars = sum(repo.stars)
   - repo_count = count(repos)
   - top_languages = repo.language 的 TOP 3 分布
   - top_repos = 前 5 个仓库（name, stars, htmlUrl）

3. 构建节点:
   { id, name(中文名), topicName, group(四大领域), totalStars, repoCount,
     topLanguages: [{name, count}], topRepos: [{name, stars, url}] }

4. 构建边（topic 对之间有边当且仅当共享语言数 ≥ 2）:
   遍历所有 topic 对 → 计算 sharedLanguages → ≥ 2 则建边
   { source(topicName), target(topicName), weight(共享语言数) }

5. 返回: { nodes: [...], edges: [...] }
```

**分两个方法**：
- `buildGraph(String snapshotDate)` → 单周图谱
- `buildCompareGraph()` → 本周 + 上周双图谱（返回 `{ thisWeek: {...}, lastWeek: {...} }`）

**输出**：`{ nodes: [15个], edges: [~20条] }`

**验证**：curl 返回 15 个 node，每个含 `totalStars/repoCount/topRepos`

### Step 1.4 — 创建 `TrendAnalysisService`

**目标**：组装 prompt + 调大模型 + 返回结果

**新增文件**：`orange-server/.../service/TrendAnalysisService.java`

**核心逻辑**：

```
1. 接收 {apiKey, endpoint, model, question}
2. 调用 KnowledgeGraphService.buildCompareGraph() 获取双周数据
3. 组装 system prompt:
   "你是开源趋势分析师。基于以下 15 个技术方向的真实 GitHub 数据，
    分析趋势、识别蓝海机会。不编造不存在的数据。"
4. 组装 user prompt:
   "本周数据: {topicStats} \n 上周数据: {topicStats} \n 用户问题: {question}
    请用 Markdown 格式回复，包含必要的数据支撑。"
5. 调大模型: POST {endpoint} /chat/completions
   Header: Authorization: Bearer {apiKey}
   Body: { model, messages: [{role:"system", content}, {role:"user", content}] }
6. 返回: { content: "Markdown文本", model, usage: {promptTokens, completionTokens} }
```

**安全措施**：
- apiKey 不落盘、不记日志
- 超时 30 秒
- 异常时返回友好错误消息，不暴露 Key

**输出**：1 个 Service 类

**验证**：curl POST → 返回 Markdown 分析报告
