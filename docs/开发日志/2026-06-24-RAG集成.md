## 2. 架构设计

### 技术栈

```
                     用户请求
                         │
    ┌────────────────────┼────────────────────┐
    │                    │                    │
    ▼                    ▼                    ▼
 AppTrendController  KnowledgeController  LeaderboardRefreshTask
    │                    │                    │
    ▼                    ▼                    ▼
TrendAnalysisService DocumentService    fetchAndIndexReadme()
    │                    │                    │
    │              ┌─────┴─────┐              │
    │              │           │              │
    ▼              ▼           ▼              │
 VectorStore ← RedisStackVectorStore          │
    │                                          │
    ▼                                          │
 GiteeAiEmbeddingModel ────────────────────────┘
 (HTTP → Gitee AI /v1/embeddings)
```

### 借鉴 tjxt-javaai02 的设计模式

| 借鉴 | 落地 |
|------|------|
| `@ConfigurationProperties` 属性类 | `AiEmbeddingProperties`，前缀 `orange.ai-embedding` |
| 集中式配置类 | `AiConfig.java` |
| `@ConditionalOnBean` 降级 | VectorStore 不可用时不影响启动 |
| Service 接口 + Impl | DocumentService / DocumentServiceImpl |

### 不照搬的部分

| tjxt 模式 | 原因 |
|-----------|------|
| Agent 多智能体路由 | OrangeJD 趋势分析是单次调用，无需路由 |
| ChatMemory 多轮对话 | 趋势分析非对话式 |
| Nacos 动态配置 | OrangeJD 用 YAML 配置 |
| SSE 流式输出 | 趋势分析返回完整 JSON |

## 5. RAG 检索流程

### 分维检索策略

```
用户四维画像：
  ① 方向 (topics) ──→ 检索 Top 2
  ② 目的 (purpose) ──→ 检索 Top 2
  ③ 基础 (experience) ──→ 检索 Top 2
  ④ 时间 (timeCommitment) ──→ 检索 Top 2
                        │
          合并去重 → Top 3（按多样性排列）
                        │
          格式化为 prompt ──→ DeepSeek V4 Pro
```

### 降级策略

| 场景 | 行为 |
|------|------|
| Redis Stack 不可用 | `vectorStore == null`，分析正常返回，不加知识库参考 |
| 检索全部低于阈值 0.6 | 仍返回 Top 3（取最高分） |
| Embedding API 调用失败 | 记录日志，跳过增强 |
| AI API 调用失败 | 与现有逻辑一致，返回错误提示 |

### 文档切片参数

| 参数 | 值 |
|------|-----|
| 切片大小 | 500 字/段 |
| 重叠 | 50 字 |
| 最大切片数 | 100 段/文档 |
| embedding 安全截断 | 400 字/段（bge-small-zh-v1.5 512 token 限制） |
| 过滤规则 | 去除纯符号/代码块标记，保留 ≥10 有效字符的片段 |

## 6. 数据库

```sql
CREATE TABLE knowledge_document (
    id           BIGINT       NOT NULL AUTO_INCREMENT,
    title        VARCHAR(256) NOT NULL COMMENT '文档标题',
    source       VARCHAR(16)  NOT NULL DEFAULT 'MANUAL' COMMENT 'MANUAL / GITHUB',
    source_ref   VARCHAR(512)          COMMENT 'GitHub full_name（幂等键）',
    chunk_count  INT          NOT NULL DEFAULT 0,
    file_size    BIGINT,
    create_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_source_ref (source_ref),
    KEY idx_source (source)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 8. 已知问题

### 🔴 向量删除失败

**现象**：`DELETE /app/knowledge/document/{id}` 删除 MySQL 记录成功，但 Redis 向量残留。

**根因**：Spring AI 1.0.0 的 `RedisVectorStore` 在 `initializeSchema=true` 时，`afterPropertiesSet()` 创建 FT.INDEX，但此时尚无文档，metadata 字段（`docId`、`docTitle` 等）未被索引。导致 `vectorStore.delete("docId == '3'")` 的 filter 语法无法匹配。

**影响**：向量数据极小（<10KB/doc），孤儿向量不影响搜索结果（不会被检索到）。

**修复方向**：升级 Spring AI 到 1.1.x（metadata 字段索引改善），或手动通过 Jedis 扫描清理。

### 🟡 大 README embedding 部分失败

**现象**：`awesome-selfhosted/awesome-selfhosted`（321KB）等超大 README 切出 100 片段，部分超大片段 embedding 失败。

**已修**：`sanitizeChunks()` 截断到 400 字 + 过滤纯符号片段。
