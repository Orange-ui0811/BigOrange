# 2026-06-30：邮箱验证码注册 + New API 项目对比分析

> **会话摘要**：将注册方式从手机号/身份证改为邮箱验证码；参考 New API 项目进行安全与架构对比。

---

## 1. 注册改造：手机号 → 邮箱验证码

### 改动背景

原注册需要手机号 + 身份证号，短信服务只有空实现（`ConsoleSmsServiceImpl` 打印到控制台）。改用邮箱验证码后无需任何第三方服务资质，个人 QQ 邮箱开 SMTP 就能用。

### 改动的文件

| 文件 | 改动 |
|------|------|
| `orange-server/pom.xml` | 加 `spring-boot-starter-mail` |
| `account` 表 | `id_card` → `email VARCHAR(128)` |
| `Account.java` | 删 `idCard`，加 `email` |
| `AccountMapper.xml` | INSERT/SELECT 替换 idCard 为 email |
| `RegisterDTO.java` | 手机号+身份证 → 邮箱+验证码 |
| `MailService.java` | 新建：邮箱验证码发送接口 |
| `SmtpMailServiceImpl.java` | 新建：JavaMailSender 实现 |
| `AppAuthController.java` | `sendCode` 改邮箱；注册校验 Redis 验证码 |
| `AuthServiceImpl.java` | 注册时校验验证码 + 存邮箱 |
| `application-dev.yml` | 加 `spring.mail.*` 配置 |
| `Login.vue`（前端） | 邮箱输入框 + 验证码 + 60s 冷却按钮 |

### 注册流程

```
① 用户输入邮箱 → 点"发送验证码"
② POST /app/auth/send-code {email}
   → 校验格式 → Redis 限流（60s）→ 调 SMTP 发信
   → Redis 存 code（5min TTL）

③ 用户输入验证码 + 用户名 + 密码 → 注册
④ POST /app/auth/register {email, code, username, password}
   → 校验 Redis 验证码 → 创建 account + user_profile
   → 删除 Redis 验证码 → 返回 JWT 登录态
```

### 邮箱配置

QQ 邮箱 → 设置 → 账户 → POP3/SMTP → 生成授权码：

```bash
$env:MAIL_USERNAME="your-email@qq.com"
$env:MAIL_PASSWORD="授权码"
```

## 2. New API 项目探索

### 项目概况

| 项目 | 路径 | 大小 | 技术栈 |
|------|------|------|--------|
| New API | `D:\new-api` | 74 MB | Go + React（TanStack Router + Zustand） |
| Sub2API | `D:\sub2api` | 114 MB | Go + Node.js |

New API：AI 模型接口管理与分发系统，基于 One API 二次开发。将多种大模型统一转为 OpenAI 格式调用，支持 API Key 分发、计费、速率限制。

Sub2API：订阅制 API 中转平台，将 Claude/OpenAI/Gemini 订阅账号转为 API 端点，支持拼车共享。

### 可借鉴的安全措施

| 措施 | New API | OrangeJD |
|------|---------|---------|
| SSRF 防护 | 355 行完整模块（内网 IP 拦截、域名白名单） | 无——AI 审核调外部图片 URL 无校验 |
| 管理审计日志 | 所有 admin 操作自动记录（谁/做了什么/IP） | 只有内容审核的 AuditRecord |
| 敏感配置保护 | API 返回时过滤含 Secret/Token 的 key | Swagger 裸奔 |
| Request ID | 每个请求分配唯一 ID（日志 + 响应头） | 无 |
| API Key 前缀 | `sk-` 前缀方便 GitHub 自动扫描泄露 | JWT 裸 Base64 无法识别 |
| 请求去重 | 并发 GET 自动去重 | 快速双击会发两个 AI 请求 |
| 优雅关闭 | Graceful shutdown | `pkill -9` 强杀 |

### 不适用 OrangeJD 的部分

- Go 后端（技术栈不同）
- 多模型路由/Channel 系统（OrangeJD 只接 DeepSeek）
- 计费/充值系统（OrangeJD 已有订单系统）
