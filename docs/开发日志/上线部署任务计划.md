| 未部署到服务器 | 仅本机可访问 |

## 阶段一：安全加固（优先级 1）

> 目标：消除最紧急的安全风险，所有改动可回滚，不依赖服务器。

### Step 1.1 — JWT 密钥随机化

**输入**：`application.yml` 明文密钥、`JwtProperties.java`

**产出物**：
- `application-prod.yml` 中 `admin-secret-key` 和 `app-secret-key` 改为 `${JWT_ADMIN_SECRET}` 和 `${JWT_APP_SECRET}`
- `application-dev.yml` 保留固定值（本地开发用）
- 生成随机密钥：`openssl rand -base64 48`

**验证方式**：启动时 `export JWT_ADMIN_SECRET=随机值 && export JWT_APP_SECRET=随机值` → 登录成功 → 用旧密钥伪造的 token 访问 → 401。

### Step 1.2 — 密码强度校验

**输入**：`RegisterDTO.java`、`AuthServiceImpl.register()`

**改动**：
1. `RegisterDTO` 加 `@Size(min=6, message="密码至少6位")`
2. `AuthServiceImpl.register()` 加正则校验：必须含字母和数字

**验证方式**：`curl /app/auth/register -d '{"password":"123"}'` → `"密码长度至少6位且必须包含字母和数字"`。

### Step 1.3 — 文件上传安全校验

**输入**：`LocalFileUploadServiceImpl.java`

**改动**：
1. 校验 MIME 类型，仅允许 `image/png`、`image/jpeg`、`image/gif`、`image/webp`
2. 校验文件大小 ≤ 10MB（服务端，前端拦截可绕过）

**验证方式**：`curl -F "file=@test.txt" /app/common/upload` → 400；`curl -F "file=@11mb.jpg" /app/common/upload` → 400。

### Step 1.4 — 关键操作日志

**输入**：`pom.xml` 已有 lombok

**改动**：在以下 Service 方法加 `log.info`：
- `AuthServiceImpl.register()` → "用户注册 username={}"
- `WorkServiceImpl.create()` → "作品发布 id={}"
- `AuditServiceImpl.auditWork()` → "审核作品 id={} result={}"
- `OrderServiceImpl.payDeposit()` → "支付定金 orderId={}"
- `OrderServiceImpl.payFinal()` → "支付尾款 orderId={}"

**验证方式**：执行上述操作 → 控制台日志有对应 `INFO` 输出。

### Step 1.5 — 健康检查端点

**输入**：无

**改动**：
1. 新建 `HealthController.java`：`GET /health` → `{"status":"UP"}`
2. `WebMvcConfiguration` 放行 `/health`

**验证方式**：`curl /health` → HTTP 200，`{"status":"UP"}`。

### Step 1.6 — 数据库备份脚本

**输入**：MySQL 连接信息

**产出物**：`backup.sh`
```bash
#!/bin/bash
DIR="backup/$(date +%Y-%m-%d)"
mkdir -p $DIR
mysqldump -u orangejd_user -p"$MYSQL_PASSWORD" orangejd | gzip > $DIR/orangejd_$(date +%H%M).sql.gz
find backup/ -mtime +7 -delete  # 保留最近7天
```

**验证方式**：手动执行 → `ls backup/` 有 `.sql.gz` 文件。

### 阶段一验收清单

- [ ] JWT 密钥通过环境变量注入，旧密钥失效
- [ ] 弱密码注册被拒绝
- [ ] 非图片文件上传被拒绝
- [ ] 大文件上传被拒绝
- [ ] `/health` 返回 200
- [ ] 日志有注册/审核/下单事件
- [ ] 备份脚本可执行

## 阶段二：部署适配（优先级 2）

> 目标：让项目代码支持从本地切换到云服务器部署。

### Step 2.1 — 前端 API 地址环境变量化

**输入**：前端多处硬编码 `http://127.0.0.1:8080`

**改动**：
1. `orange-web/.env`：`VITE_API_BASE_URL=http://127.0.0.1:8080`
2. `orange-admin/.env`：`VITE_API_BASE_URL=http://127.0.0.1:8080`
3. `request.js` 中 `baseURL` 改为 `import.meta.env.VITE_API_BASE_URL`
4. 所有 `<el-upload action="http://127.0.0.1:8080/...">` 改为动态读取

**验证方式**：`npm run build` 后 `grep -r "127.0.0.1" dist/` 返回空。

### Step 2.2 — WebSocket 地址环境变量化

**输入**：`Chat.vue` 硬编码 `ws://127.0.0.1:8080`

**改动**：
1. `.env` 加 `VITE_WS_URL=ws://127.0.0.1:8080`
2. `Chat.vue` 中 `new WebSocket(...)` 改为 `import.meta.env.VITE_WS_URL + '/ws/' + uid`

**验证方式**：build 后搜索不到 `127.0.0.1`。

### Step 2.3 — 生产环境配置确认

**输入**：`application-prod.yml`

**改动**：确认所有敏感值都走 `${ENV_VAR}`，无硬编码：
- [ ] `spring.datasource.password` → `${MYSQL_PASSWORD}`
- [ ] `spring.redis.password` → `${REDIS_PASSWORD}`
- [ ] `orange.jwt.admin-secret-key` → `${JWT_ADMIN_SECRET}`
- [ ] `orange.jwt.app-secret-key` → `${JWT_APP_SECRET}`
- [ ] `orange.upload.path` → `${UPLOAD_PATH:/data/orangejd/uploads}`

**验证方式**：`grep -E "change-me|123456|admin" application-prod.yml` 返回空。

### Step 2.4 — Nginx 配置模板

**输入**：域名、服务器路径

**产出物**：`nginx.conf`
```nginx
server {
    listen 80;
    server_name 你的域名;

    # 前端静态文件
    location / {
        root /data/orangejd/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 上传文件
    location /uploads/ {
        alias /data/orangejd/uploads/;
    }
}
```

**验证方式**：`nginx -t` 通过。

### 阶段二验收清单

- [ ] 前端 build 后无硬编码地址
- [ ] `application-prod.yml` 无明文密码
- [ ] `nginx -t` 配置校验通过

## 阶段三：部署上线（优先级 3）

> 目标：服务器环境搭建 + 部署 + 全链路验收。

### Step 3.1 — 服务器环境搭建

**输入**：服务器 IP + SSH 账号

**产出物**：
- JDK 17+ 安装
- MySQL 8.0 安装 + `orangejd` 库创建 + `orangejd_user` 授权
- Redis 安装 + 密码设置 + bind 127.0.0.1
- Nginx 安装 + 配置引用 Step 2.4 的 `nginx.conf`

**验证方式**：`systemctl status mysql redis nginx` 均为 running。

### Step 3.2 — 数据库迁移

**输入**：本地 `mysqldump orangejd`

**改动**：
1. 本地导出：`mysqldump orangejd > orangejd.sql`
2. 服务器导入：`mysql orangejd < orangejd.sql`
3. 验证 admin 可登录

**验证方式**：`curl /admin/auth/login` → 200，返回 token。

### Step 3.3 — 应用部署

**输入**：jar 包 + 前端 dist/

**改动**：
1. 后端：`java -jar orange-server.jar --spring.profiles.active=prod`
2. 前端：Nginx 指向 `dist/`
3. 确认 `/health` 可访问

**验证方式**：`curl http://服务器IP/health` → `{"status":"UP"}`。

### Step 3.4 — HTTPS + 域名

**输入**：域名 DNS 解析到服务器 IP

**改动**：
1. Let's Encrypt 申请免费 SSL 证书
2. Nginx 加 443 监听
3. 80 端口强制跳转 443

**验证方式**：浏览器访问 `https://域名` → 小锁图标。

### Step 3.5 — 全链路验收

**输入**：两个测试账号

**操作**：
1. 注册新用户（弱密码被拒 → 强密码成功 → 登录）
2. 发布作品（上传封面图 → 填演示链接 → 提交审核）
3. 管理员登录 → 审核通过
4. 市场可见该作品（封面图 + 收藏数 + 评论数）
5. 另一个用户联系作者 → 聊天 → WebSocket 实时收到
6. 发报价 → 接受 → 下单 → 付定金 → 交付 → 付尾款 → 完成
7. 管理后台审核/用户/统计均可操作

**验证方式**：全链路无 500/404，每个操作后日志有记录。

### Step 3.6 — 备份 + 日志确认

**输入**：Step 1.6 的备份脚本

**改动**：
1. 备份脚本部署到服务器
2. crontab 配置：`0 3 * * * /data/scripts/backup.sh`
3. 日志按天切割（logback 配置）

**验证方式**：第二天检查 `backup/` 有新 `.sql.gz`。

### 阶段三验收清单

- [ ] 公网可通过域名访问
- [ ] HTTPS 小锁正常
- [ ] 全链路 12 步全部走通
- [ ] 备份文件存在
- [ ] 日志有输出

## 3. 全局约定

### 3.1 改动原则

- 阶段一只改配置文件和 Service 校验逻辑，不动 Controller 签名和 API 路径
- 阶段二只改前端构建配置，不动后端
- 阶段三只做部署和运维操作，不动代码

### 3.2 回滚策略

| 阶段 | 回滚方式 |
|------|---------|
| 阶段一 | 每个 Step 独立 commit，有问题 `git revert` 即可 |
| 阶段二 | `.env` 改回 `127.0.0.1` 即恢复本地开发 |
| 阶段三 | 旧 jar 包 + 旧 nginx.conf 保留备份 |

### 3.3 环境区分

| 配置 | dev | prod |
|------|-----|------|
| JWT 密钥 | `change-me-admin` | `${JWT_ADMIN_SECRET}` |
| MySQL 密码 | `123456` | `${MYSQL_PASSWORD}` |
| Redis 密码 | 空 | `${REDIS_PASSWORD}` |
| 日志级别 | `info` | `warn` |
| 文件上传路径 | `D:/Orangejd/uploads` | `/data/orangejd/uploads` |

## 8. 风险与规避

| 风险 | 概率 | 规避 |
|------|------|------|
| R1 不知道域名/服务器 | 高 | 阶段一只做不依赖服务器的事 |
| R2 前端 API 地址写死 | 高 | 阶段二统一提取为环境变量 |
| R3 WebSocket 地址写死 | 高 | 阶段二同前端一起提取 |
| R4 安全加固后自己登不上 | 中 | 先改配置→重启验证→再改密码 |
| R5 Nginx 挡 WebSocket | 中 | 配置 Upgrade 头 |
| R6 备份脚本 Windows/Linux 不兼容 | 低 | 用纯 shell 写，Git Bash 测试 |
