# OrangeJD 上线安全任务清单

> 基于项目现状 + 网络安全标准，按优先级排列。每项标注状态、影响、实施难度。

---

## 一、立即修复（🔴 高风险，1 天内完成）

### 1.1 JWT 密钥修改

**现状**：`application-prod.yml` 中 `admin-secret-key` 和 `app-secret-key` 使用默认值 `change-me-admin` / `change-me-app`，公开在 GitHub 仓库。

**风险**：任何人可伪造 JWT Token，以任意用户身份登录。

**修复**：
```bash
# 生成随机密钥
openssl rand -base64 48
```
将生成的值写入 `start.sh` 环境变量：
```bash
export JWT_ADMIN_SECRET=生成的随机值
export JWT_APP_SECRET=生成的随机值
```

**影响**：所有已登录用户 Token 失效，需重新登录。

---

### 1.2 管理员密码修改

**现状**：admin / 123456 写在 README 和 schema-v1.sql 中，公开可见。

**修复**：登录管理后台 → 修改密码 → 设置为 12 位以上强密码。

---

### 1.3 数据库密码加固

**现状**：MySQL root 密码为 `Az919800.`，且 root 账号同时用于应用连接。

**修复**：
```sql
-- 创建专用业务账号
CREATE USER 'orangejd_app'@'127.0.0.1' IDENTIFIED BY '新的强密码';
GRANT SELECT,INSERT,UPDATE,DELETE ON orangejd.* TO 'orangejd_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```
然后修改 `start.sh` 中 `MYSQL_USER` 为 `orangejd_app`。

---

### 1.4 关闭生产环境调试输出

**现状**：`application-dev.yml` 中 MyBatis SQL 日志 `StdOutImpl` 会打印所有 SQL 到控制台。

**修复**：确认 `application-prod.yml` 中 `log-impl` 不输出 SQL（当前已配置 `logging.level.com.orangejd: warn`，确认有效）。

---

### 1.5 配置文件安全

**现状**：`application-prod.yml` 已提交到 Git，GitHub 上可见数据库连接方式。

**修复**：
1. 确认所有敏感值都走 `${ENV_VAR}` 环境变量
2. `start.sh` 权限设为 600：`chmod 600 /root/start.sh`
3. 后续在前端构建时排除 `.env.production` 中的无用变量

## 二、本周完成（🟡 中风险，3 天内）

### 2.1 HTTPS + SSL 证书

**现状**：全站 HTTP 明文，登录密码、JWT Token 可被中间人截获。

**修复**：
```bash
# 宝塔面板 → 网站 → 设置 → SSL → Let's Encrypt 申请
# 开启强制 HTTPS
```
Nginx 增加：
```nginx
server {
    listen 443 ssl;
    # 80 端口强制跳转
    if ($scheme = http) { return 301 https://$host$request_uri; }
}
```

---

### 2.2 安全响应头

**现状**：Nginx 未配置任何安全响应头。

**修复**：在 Nginx `server` 块中添加：
```nginx
add_header Strict-Transport-Security "max-age=63072000" always;
add_header X-Frame-Options "DENY" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
server_tokens off;  # 隐藏 Nginx 版本号
```

---

### 2.3 防火墙 + 端口管控

**现状**：未确认阿里云安全组规则和服务器防火墙状态。

**修复**：
```bash
# 阿里云控制台 → 安全组 → 仅放行 80/443
# 服务器防火墙
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
# SSH 仅允许内网或指定 IP
```

---

### 2.4 接口频率限制

**现状**：仅趋势分析接口有 Redis 限流，登录/注册/发消息等无限制。

**修复**：在后端拦截器或 Controller 层增加基于 IP 的限流：
- 登录：同一 IP 每分钟最多 5 次
- 注册：同一 IP 每小时最多 3 次
- 发消息：同一用户每秒最多 1 次

使用 Redis + 自定义注解实现。

---

### 2.5 文件上传安全加固

**现状**：前端文件上传有类型限制，但需确认服务端校验完善。

**修复**：
1. 确认 `LocalFileUploadServiceImpl` 校验 MIME 类型（已实现）
2. 增加文件头魔数校验（不仅依赖后缀名）
3. Nginx 限制上传目录执行脚本：
```nginx
location /uploads/ {
    alias /root/uploads/;
    location ~* \.(php|jsp|py|sh|exe)$ { return 403; }
}
```

## 三、两周内完成（🟠 重要保障）

### 3.1 XSS 防护

**现状**：前端使用了 `v-html` 渲染详情字段（作品描述、评论），存在 XSS 攻击面。

**修复**：
1. 前端渲染前使用 DOMPurify 过滤恶意 script 标签
2. 后端存储前对 HTML 做白名单过滤（仅允许 p/br/img/a/b/i 等安全标签）
3. 对所有输出到页面的用户内容做 HTML 转义

---

### 3.2 SQL 注入排查

**现状**：MyBatis XML 中大部分使用 `#{}` 参数化查询，但需排查是否有 `${}` 拼接。

**修复**：
```bash
# 排查所有 MyBatis XML 中的 ${} 使用
grep -rn '\${' orange-server/src/main/resources/mapper/ | grep -v '#{' 
```
所有 `${}` 改为 `#{}`，确实需要动态字段名的使用白名单校验。

---

### 3.3 敏感数据脱敏

**现状**：用户手机号、身份证号在接口返回中直接暴露明文。

**修复**：
1. 手机号返回：`138****1234`
2. 身份证返回：`320***********1234`
3. 在 VO 层或 Jackson 序列化时统一处理

---

### 3.4 RBAC 权限最小化

**现状**：管理员和普通用户权限体系已建立（双通道 JWT），但个别接口可能存在越权。

**修复**：
1. 审查所有 `/app/` 接口是否校验 `ownerId` 或 `accountId`
2. 审查所有 `/admin/` 接口是否仅管理员可访问
3. 数据库账号改用专用低权限账号（见 1.3）

---

## 四、上线前检查（基础验证）

### 4.1 备份恢复验证

**现状**：`backup.sh` 已创建，但从未验证恢复流程。

**验证**：
```bash
# 手动执行备份
bash /root/backup.sh
# 验证备份文件完整性
gzip -t /root/backup/$(date +%Y-%m-%d)/*.sql.gz
```

---

### 4.2 第三方组件漏洞扫描

**现状**：Spring Boot 2.7.18 及依赖库版本。

**排查**：
1. 检查 Spring Boot 是否有已知 CVE（2.7.18 已 EOL，注意安全公告）
2. 检查 Fastjson/Jackson/Log4j 版本是否有漏洞
3. Maven 依赖分析：`mvn dependency:tree | grep -E "log4j|fastjson|snakeyaml"`

---

### 4.3 日志审计

**现状**：已使用 Logback，关键操作有日志（注册/发布/审核/支付）。

**确认**：
1. 日志不包含明文密码、Token、身份证号
2. 日志留存 ≥ 180 天
3. 日志文件禁止通过 URL 访问
```nginx
location ~* \.log$ { return 403; }
```
