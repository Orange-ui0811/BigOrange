## Step 1：后端风险消除（P0）

> 目标：消除一阶段遗留的生产风险，确保数据和资金安全。

### Step 1.1 — 订单超时自动取消

**输入**：`OrderTimeoutTask.java`（当前空壳）、`OrderStatus.java`（已有常量）

**改动**：
1. `OrderMapper.xml` 加 `selectTimeoutOrders` 查询（`DEPOSIT_PAID` + `create_time < now-7天`）
2. `OrderTimeoutTask.processTimeoutOrders()` 取消超时订单并发送双方通知
3. 加入 Cron：`0 0 2 * * ?`（每天凌晨 2 点执行）

**验证**：手动构造一条 8 天前的订单 → 等待任务执行 → 订单状态变 `CANCELLED` + 通知双方。

### Step 1.2 — 通知定期清理

**输入**：`NotificationMapper.java`（已有）

**改动**：
1. `NotificationMapper.xml` 加 `deleteOldRead(long days)`——删除 `is_read=1` 且 `create_time < now-30天` 的通知
2. 新建 `NotificationCleanupTask.java`，每天凌晨 3 点执行

**验证**：手动构造一条 31 天前的已读通知 → 等待任务执行 → 通知被删除。

### Step 1.3 — JWT 退出黑名单

**输入**：`RedisConfiguration.java`（已有）、`JwtUtil.java`（已有）

**改动**：
1. 新增 `TokenBlacklistService`：退出时将 token 写入 Redis `blacklist:token:{token}`，TTL = token 剩余有效时间
2. `JwtTokenAdminInterceptor` / `JwtTokenAppInterceptor` 的 `preHandle` 在解析 JWT 前先查 Redis 黑名单
3. Redis 不可用时降级放行（记日志），不阻塞登录

**验证**：登录 → 退出 → 用同一 token 访问 `/app/work/my` → 返回 401。

## Step 2：基础设施补齐（P1）

> 目标：为前端开发和后续维护搭建基础设施。

### Step 2.1 — Swagger / Knife4j API 文档

**输入**：现有 14 个 Controller

**改动**：
1. `pom.xml` 加 `knife4j-spring-boot-starter` 依赖（版本 3.0.3，兼容 Spring Boot 2.7）
2. 新建 `SwaggerConfig.java`
3. `WebMvcConfiguration` 加 `excludePathPatterns`：`/doc.html`、`/v3/**`、`/swagger-resources/**`
4. 每个 Controller 方法加 `@ApiOperation` 注解

**验证**：访问 `http://localhost:8080/doc.html` → 展示全部端点 → 可在页面内在线调试。

### Step 2.2 — DTO 参数校验

**输入**：6 个 DTO 类（`RegisterDTO`、`WorkCreateDTO`、`CommentCreateDTO`、`MessageSendDTO`、`QuoteCreateDTO`、`OrderCreateDTO`）

**改动**：
1. 加 `@NotBlank`、`@NotNull`、`@Positive`、`@Size` 注解
2. 每个 Controller 方法参数加 `@Valid`
3. `GlobalExceptionHandler` 加 `MethodArgumentNotValidException` 处理，返回 `400 + 具体校验失败字段`

**验证**：POST 空标题 → 返回 `400` + `{"msg":"作品标题不能为空","field":"title"}`。

### Step 2.3 — WebSocket 消息推送

**输入**：`WebSocketConfiguration.java`（已有骨架）、`WebSocketServer.java`（已有骨架）

**改动**：
1. `WebSocketServer` 落地：维护 `Map<Long, Session>`（userId → WebSocket 连接）
2. `WebMvcConfiguration` 加 `excludePathPatterns`：`/ws/**`
3. `JwtTokenAppInterceptor` 放行 OPTIONS 已有，WebSocket 握手通过 URL 参数 `?token=xxx` 鉴权
4. `MessageServiceImpl.send()` 发送消息后，通过 `WebSocketServer` 向接收方推送（在线则推送，离线则仅写通知）
5. `INotificationService.send()` 后同样推送

**验证**：两个浏览器窗口各登录一个账号 → A 发消息给 B → B 窗口 2 秒内出现新消息 → 切回 A 窗口 → 点「通知」也能看到。

### Step 2.4 — Service 层单元测试

**输入**：`pom.xml`（已有 `spring-boot-starter-test`）

**改动**：
1. `WorkServiceImplTest`：测 `submitForReview` 状态校验（非 DRAFT 不能提交）、`delete` 权限校验（非本人不能删）
2. `AuditServiceImplTest`：测 `auditWork` 状态校验（非 PENDING_REVIEW 不能审）
3. `OrderServiceImplTest`：测 `payDeposit` 状态校验（非 WAITING_DEPOSIT 不能支付）

**验证**：`mvn test` → 至少 6 条测试通过，覆盖审核状态机 + 订单状态机 + 权限校验。

## Step 3：管理后台前端（P0）

> 目标：管理员可通过浏览器完成审核、治理、查看统计数据。
> 技术栈：Vue 3 + Element Plus + Vite | 项目名：`orange-admin`

### Step 3.1 — 项目初始化 + 登录

**输入**：后端 `/admin/auth/login` 接口

**输出**：
- `orange-admin/` 项目目录（Vite + Vue 3 + Element Plus）
- 登录页（用户名 + 密码 → 获取 token → 存储 localStorage → 跳转控制台）
- 路由守卫（无 token 重定向登录页）
- axios 封装（拦截器自动带 `Admin-Token` 头）

### Step 3.2 — 控制台首页

**输入**：后端 `/admin/statistics/dashboard`、`/admin/statistics/top-works`、`/admin/statistics/top-creators`

**输出**：
- 6 个概览卡片（用户总数 / 作品总数 / 需求总数 / 待审核数 / 订单总数 / 交易额）
- 热门作品 Top5 表格
- 活跃创作者 Top5 表格

### Step 3.3 — 审核管理

**输入**：后端 `/admin/audit/works`、`/admin/audit/requirements`、`/admin/audit/work/{id}/approve`、`/admin/audit/work/{id}/reject`

**输出**：
- 待审作品/需求 Tab 切换
- 列表展示（标题/作者/提交时间）
- 通过按钮（可选填原因）、拒绝按钮（必填原因）

### Step 3.4 — 内容管理

**输入**：后端 `/admin/work`、`/admin/requirement`、`PUT /admin/work/{id}/offline`

**输出**：
- 作品列表（所有状态，支持下架操作）
- 需求列表（同上）

### Step 3.5 — 用户管理 + 订单管理

**输入**：后端 `/admin/users`、`/admin/users/{id}/status`、`/admin/orders`

**输出**：
- 用户列表（用户名 / 角色 / 状态 / 禁用/启用按钮）
- 订单列表（买方 / 卖方 / 金额 / 状态 / 时间）

## Step 4：用户端前端（P1）

> 目标：创作者和需求方可通过浏览器使用平台全部功能。
> 技术栈：Vue 3 + Element Plus / Vant + Vite | 项目名：`orange-web`

### Step 4.1 — 项目初始化 + 注册登录

**输入**：后端 `/app/auth/register`、`/app/auth/login`

**输出**：
- `orange-web/` 项目目录
- 注册页（用户名 + 密码 + 昵称）
- 登录页（用户名 + 密码 → 获取 token）
- axios 封装（`App-Token` 拦截器）

### Step 4.2 — 市场首页

**输入**：后端 `/app/work/public`、`/app/requirement/public`、`/app/category`

**输出**：
- 作品/需求 Tab 切换
- 分类筛选下拉
- 关键词搜索
- 分页列表（封面 / 标题 / 作者 / 价格 / 收藏数）
- 点卡片进入详情

### Step 4.3 — 作品/需求详情 + 发布

**输入**：后端 `/app/work/{id}`、`/app/work`、`/app/work/{id}/submit`、`/app/requirement/{id}`、`/app/requirement`

**输出**：
- 详情页（标题 / 详情 / 作者 / 售卖项 / 状态）
- 发布页（表单填写 → 提交草稿 → 提交审核）
- 我的内容页（列表 + 状态标签 + 操作按钮：编辑/提交/删除/私密）

### Step 4.4 — 聊天

**输入**：后端 `/app/conversation`、`/app/conversation/list`、`/app/message`、WebSocket

**输出**：
- 会话列表（对方名 / 最后消息 / 未读数 / 时间）
- 聊天窗口（消息列表 + 输入框 + 发送按钮）
- WebSocket 实时接收新消息
- 聊天内发起报价入口

### Step 4.5 — 交易

**输入**：后端报价/订单相关 15 个端点

**输出**：
- 报价卡片（价格 / 状态 / 接受/拒绝按钮 / 下单入口）
- 订单流程页（展示当前状态 → 下一步操作按钮）

### Step 4.6 — 个人中心 + 通知

**输入**：后端通知、收藏、评论、浏览历史、作者主页端点

**输出**：
- 通知列表（类型图标 / 内容 / 时间 / 已读/未读）
- 我的收藏 / 我的评论 / 浏览历史
- 作者主页（查看他人公开资料和作品）

## Step 5：文件上传（P2）

> 目标：头像和作品封面可通过表单上传。

### Step 5.1 — 本地上传

**输入**：`OssProperties.java`（已有）、`FileUploadService`（计划预留）

**改动**：
1. `orange-common` 下新建 `FileUploadService` 接口，默认实现为本地磁盘存储（`D:/Orangejd/uploads/`）
2. Controller：`POST /admin/common/upload`（参考苍穹外卖 `CommonController`）
3. 前端作品发布页、头像编辑页加上传组件

**验证**：管理后台 / 用户端上传一张图片 → 返回 URL → 页面显示上传的图片。

### Step 5.2 — OSS 切换槽位

**输入**：`OssProperties.java`（已有配置类）

**改动**：
1. `FileUploadService` 增加 `OssFileUploadServiceImpl`，读取 `OssProperties` 配置
2. 通过 `@ConditionalOnProperty` 切换本地/OSS 实现

**验证**：改 `application.yml` 中 `orange.oss.active=true` → 重启 → 上传文件到 OSS。
