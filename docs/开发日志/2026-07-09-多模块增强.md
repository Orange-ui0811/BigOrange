## 2. GitHub 榜单抓取策略升级 — 三段式 Period

### 2.1 背景

原有 `period='week'` 只抓 `created:>上周一`——仅展示本周新创建的仓库，忽略了"上个月创建、本周突然涨了 1 万星"的真热门项目。

### 2.2 三段式设计

| Period | 前端标签 | GitHub 查询条件 | 含义 |
|--------|---------|---------------|------|
| `all` | 全时段 | `topic:xxx stars:>1 sort:stars` | 累计星数最高的项目 |
| `new` | 本周新增 | `topic:xxx created:>上周一 sort:stars` | 本周新创建的仓库 |
| `week` | 本周涨星 | `topic:xxx pushed:>上周一 stars:>10 sort:stars` | 近期有代码推送的活跃+高星仓库 |

### 2.3 爬取规则

```
refreshAll() → 每个 topic 执行：
  ① all   (stars:>1)
  ② new   (created:>DATE)         ← 先爬新增
  ③ week  (pushed:>DATE stars:>10) ← 再爬涨星，防限流

每次 API 调用间隔 6 秒
触发：@PostConstruct 30s 延迟 + 每周一凌晨 2:00
```

### 2.4 之前尝试过的方案（已废弃）

**差值对比方案**：取当前 Top 20 → 对比上周快照 star 数 → 计算差值排序。被否决——用户要求直接通过 GitHub API 爬取，不用差值计算。

### 2.5 RAG 联动

| Period | README 采集 | 数量 | 过期 |
|--------|-----------|------|------|
| `all` | ✅ 原有 | Top 20 | 永久 |
| `new` | ✅ 原有 | Top 3 | 30 天 |
| `week` | ✅ 本次新增 | Top 5 | 30 天 |

### 改动文件

| 文件 | 改动 |
|------|------|
| `LeaderboardRefreshTask.java` | `refreshAll()` 加 `period='new'` + `refreshWeekStars()` 涨星爬取方法；`parseStarMap()` 已移除（不再需要） |
| `Leaderboard.vue` | 时间选择器加「本周涨星」「本周新增」两个 radio-button；GitHub 专属显示「本周新增」；空态文案更新 |
| `fetchAndIndexReadme` | `sourceRef` 适配 `new`/`week` period |

### 线上数据验证

```
MySQL> SELECT period, COUNT(*) FROM leaderboard_snapshot
       WHERE source='github' AND snapshot_date='2026-07-09' GROUP BY period;

period  cnt
all     16   ← 15 topic + NULL
week    16   ← 新爬取（pushed>2026-07-06）
new     16   ← 新爬取（created>2026-07-06）
```

DNS 问题：当天上午 `api.github.com` 临时解析失败，下午恢复。原因是 Java 进程缓存了早期失败的 DNS 查询。`nslookup` 验证三个 DNS 服务器（默认/8.8.8.8/114.114.114.114）均可解析到 `20.205.243.168`。

## 4. 邮件验证码修复

### 4.1 SMTP 配置

**问题**：`application-dev.yml` 中 `MAIL_USERNAME`/`MAIL_PASSWORD` 使用 `${}` 环境变量占位，均未设置实际值。QQ SMTP 空账号 → 拒绝连接 → 「邮件发送失败，请检查邮箱地址」。

**修复**：直接填入 QQ 邮箱 SMTP 账号和授权码。

```yaml
spring:
  mail:
    host: smtp.qq.com
    port: 587
    username: 1281748852@qq.com
    password: leywbeyvheyeghcj    # QQ邮箱 SMTP 授权码（非QQ密码）
```

### 4.2 忘记密码

新增完整密码重置流程：

```
登录表单
  └─ 点击「忘记密码？」
      ├─ Step 1: 输入注册邮箱 → 发送验证码（Redis 60s 限流）
      ├─ Step 2: 输入验证码 + 新密码 → 确认修改
      └─ Step 3: ✅ 修改成功 → 返回登录
```

| 端点 | 方法 | 鉴权 | 说明 |
|------|------|------|------|
| `/app/auth/send-reset-code` | POST | ❌ | 校验邮箱已注册 → 发 6 位验证码 |
| `/app/auth/reset-password` | POST | ❌ | 验证码校验 → BCrypt 更新密码 |

### 4.3 密码格式放宽

**问题**：`RegisterDTO` 正则 `[A-Za-z\d]{6,}$` 不允许标点符号，注册带 `!@#$` 的密码显示「密码至少6位且必须包含字母和数字」。

**修复**：`regexp` 从 `[A-Za-z\d]{6,}$` → `.{6,}$`（允许任意字符）。

### 4.4 错误提示优化

**问题**：`catch { ElMessage.error('网络连接失败') }` 掩盖了后端返回的真实错误（如"验证码错误""用户名已存在""密码格式不对"）。

**修复**：`catch(e) { ElMessage.error(e?.response?.data?.msg || '网络连接失败') }`。

### 4.5 邮箱唯一性绑定

**问题**：注册只检查用户名重复，同一邮箱可注册多个账号。侵权追溯时无法定位。

**修复**：
- `AuthServiceImpl.register()` 增加 `accountMapper.selectByEmail()` 检查
- 数据库 `ALTER TABLE account ADD UNIQUE KEY uk_email (email)`
- `AdminUserController.list()` 返回 `email` 字段（`AccountVO` 新增 `email`）

## 5. Cloudflare Turnstile 注册防护

### 5.1 动机

注册页 `send-code` 端点没有任何人机验证，脚本可无限调用刷邮件额度。

### 5.2 实现

**后端**：
- `TurnstileService.java`：调用 `https://challenges.cloudflare.com/turnstile/v0/siteverify` 验证 token
- `AppAuthController.register()` 先调用 `turnstileService.verify()`，失败返回「人机验证失败，请刷新页面重试」
- 未配置 `secretKey` 时自动放行（开发友好）

**前端**：
- `Login.vue` 注册表单加入 `<div ref="turnstileRef">` 容器
- 切换到注册 Tab 时 `window.turnstile.render()`，token 回填到 `regForm.turnstileToken`
- 目前使用测试 site key `1x00000000000000000000AA`（永远通过）

### 5.3 配置

```yaml
orange:
  turnstile:
    secret-key: ${TURNSTILE_SECRET_KEY:}   # 生产环境必须设置真实 key
```

前端 `.env`：
```
VITE_TURNSTILE_SITE_KEY=你的sitekey
```

### 改动文件

| 文件 | 说明 |
|------|------|
| `TurnstileService.java` | 新增 — Cloudflare Turnstile token 验证 |
| `application-dev.yml` | 新增 `orange.turnstile.secret-key` |
| `RegisterDTO.java` | 新增 `turnstileToken` 字段 |
| `AppAuthController.java` | register 方法加 Turnstile 校验 |
| `Login.vue` | Turnstile widget + 初始化 + token 提交 |
| `index.html` | 引入 Turnstile SDK |
