# OrangeVC 架构治理实施说明

## 1. 治理目标

OrangeVC 采用模块化单体和渐进治理路线，当前继续使用一套 Spring Boot 应用、MySQL、Redis、OSS、两个 Vue 前端和现有服务器部署形态。治理优先解决错误审批、配额不一致、后台任务丢失、发布不可追踪和缺少自动测试，不以拆微服务或重写技术栈为目标。

适用规模为 2-5 人开发团队和数千活跃用户。只有模块出现独立扩容、故障隔离或团队所有权需求时，才评估拆分服务。

## 2. 本轮已经建立的基线

### 安全与审核

- 新签发 JWT 使用 `orangevc` issuer；在一个 Token 有效期内继续接受 `orangejd` issuer。
- App、Admin 和 Agent 的公开路径集中维护，避免控制器增加后忘记更新多处白名单。
- 登录、验证码、注册、上传、AI、投稿和设备接口增加 Redis 限流。
- V1 不再创建固定默认管理员；空库仅在显式提供一次性 bootstrap 环境变量时创建首位管理员。
- 岗位 AI 审核开关只影响未来投稿，不再批量直接通过历史投稿。
- AI 审核必须返回 `APPROVE`、`REJECT` 或 `MANUAL_REVIEW`、置信度和依据。
- 只有达到阈值的决策可以自动执行，其余保留在人工审核队列。
- 审核状态、审核证据和投稿奖励处于同一事务；只允许从 `PENDING` 首次审批，防止重复奖励。

### 数据库与后台任务

- `db/migration` 是唯一可执行数据库结构来源。
- `V1__baseline_schema.sql` 可以在空库建立历史基础表，V2-V16 继续完成增量升级。
- `schema-v1.sql` 不再作为手工初始化脚本；结构快照通过脚本从数据库导出。
- 已在临时 MySQL 8.0 空库顺序执行 V1-V16，结果为 39 张表、416 个字段。
- 新增 `system_task` 持久化任务中心，包含幂等键、状态、进度、重试、下次执行时间、锁、结果和错误。
- 榜单、Issue 刷新和岗位 AI 审核已接入任务中心。
- 原“无限重试直到翻译成功”变为 `RETRY_WAIT`：每次调用有边界，失败后释放线程并持久化等待下次重试。
- 使用数据库原子抢占任务，为未来多实例运行避免重复执行。

### 工程质量

- 后端引入 ArchUnit，先约束 `foundation`、`contribution`、`security` 的依赖方向和构造器注入。
- 用户端和管理端增加 ESLint、渐进式 TypeScript、Vitest、Vue Test Utils 和构建体积预算。
- 两个前端的生产依赖高危漏洞已清零。
- CI 覆盖 `V2`、`main` 和 Pull Request，执行后端测试、架构规则、空库迁移、前端质量检查、构建、依赖审计和密钥扫描。
- Actuator 和 Prometheus 指标已启用；生产管理端口默认绑定 `127.0.0.1:8081`。

### 发布与回滚

- `scripts/build-release.sh` 是唯一发布包构建入口。
- 发布包包含 Git SHA、分支、构建时间、核心文件 SHA256、迁移文件和迁移清单。
- `scripts/install-release.sh` 在服务器执行校验、备份、文件切换、服务启动、健康检查和失败文件回滚。
- 根目录旧 `deploy.sh`、`start.sh` 已移除，禁止恢复手工 `pkill/nohup` 发布方式。

## 3. 模块边界

目标模块如下：

| 模块 | 业务职责 |
| --- | --- |
| `identity` | 账号、认证、管理员、设备绑定 |
| `content` | 作品、需求、分类、评论、收藏、头像 |
| `marketplace` | 会话、报价、订单、交付、支付 |
| `ai` | 趋势分析、方案设计、上线体检、RAG |
| `contribution` | 榜单、Issue、岗位、比赛、贡献指南 |
| `quota` | 配额、奖励、充值、定价 |
| `media` | OSS、本地文件、上传、删除和清理 |
| `agent` | 小智设备动作和语音工作流 |
| `admin` | 管理端用例和审计 |
| `foundation` | 任务、异常、日志、时间和外部客户端基础能力 |

新模块内部按 `api/application/domain/infrastructure` 组织。旧代码不一次性搬迁；只有在修改对应功能时才迁入目标模块，并通过适配层保留原 URL、JSON 字段和 MCP 工具名。

禁止：

- 模块直接调用其他模块的 Mapper。
- Controller 直接编排跨表事务。
- 新增裸 `Thread`、公共 `CompletableFuture` 或无限占用线程的重试循环。
- 新增 `Map<String,Object>` 作为稳定对外接口。
- 在 `orange-common` 和 `orange-pojo` 继续堆放只属于单一业务的类型。

## 4. 尚未完成的渐进工作

以下项目是明确的治理队列，不应被描述为已完成：

- 将现有 MVC Token 拦截器逐步迁移到 Spring Security 认证链；迁移前继续保持现有协议兼容。
- 将方案生成、趋势分析、知识库重建和清理任务接入 `system_task`。
- 为 AI、GitHub、OSS、Turnstile、邮件和飞书统一外部客户端、超时、错误分类和调用成本记录。
- 按业务修改范围逐步迁移旧包，并扩大 ArchUnit 规则。
- 将现有 JavaScript 页面逐步迁移到 TypeScript，拆分超大趋势分析页面和公共依赖包。
- 清理 ESLint 现有警告，优先消除吞异常的空 `catch`。
- 增加完整 Playwright 测试和轻量压测；目前仅建立了单元测试与构建门禁。
- 为任务中心增加管理端任务积压、失败重试和审计页面。
- 正式域名、HTTPS、公网入口锁紧和云监控告警仍按生产上线清单完成。

## 5. Definition of Done

每个功能或治理改动完成前必须满足：

1. 兼容现有 URL、响应字段、数据库数据、OSS 对象和 MCP 工具，或提供明确迁移步骤。
2. 数据库变更只能新增版本化 Flyway 迁移，禁止修改已经在生产执行的 V2-V16。
3. 配额、奖励、支付和任务具有幂等键，并覆盖重复请求或并发场景。
4. 后端测试和 ArchUnit 通过。
5. 两个前端相关应用完成 lint、typecheck、测试和构建。
6. 日志、测试数据和发布包不包含 Token、Key、密码或个人信息。
7. 提供生产验证方式和应用文件回滚方式。
