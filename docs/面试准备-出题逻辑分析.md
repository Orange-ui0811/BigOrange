# 面试官出题逻辑分析

> 基于 tjxt-javaai02 项目完整面试题库（76 题）反向推导，总结 AI 项目面试的 6 层递进出题框架。

---

## 六层递进出题逻辑

面试官的出题不是随机的，它遵循从浅到深的递进逻辑。每一层都是下一层的入场券——前一层答不上来，后一层不会出现。

### L1：概念验证

**出题意图**：筛掉完全没做过的人。

| 出题规律 | 示例 |
|----------|------|
| 核心技术的定义/原理 | 什么是 RAG？ToolCalling 怎么调用？ |
| 框架/工具的基本认知 | Spring AI 有哪些内置 Advisor？Ollama 是什么？ |
| 协议/格式的特性与限制 | SSE 有什么限制？message 分哪四类？ |

**判断标准**：能说出准确的定义、核心步骤就算过。不需要太深。

---

### L2：技术选型推理

**出题意图**：筛掉只会调 API 的人。要你说出"为什么选 A 不选 B"。

| 出题规律 | 示例 |
|----------|------|
| A vs B 横向对比 | MCP 和 ToolCalling 有什么区别？ |
| 框架选型 | 为什么选 Spring AI Alibaba 而不是原生 Spring AI？ |
| 多方案并存 | 为什么同时用本地 Ollama + 云端千问 max？ |
| 模型选型 | 为什么选千问而不是 DeepSeek？ |

**判断标准**：能讲清楚 trade-off——性价比、中文能力、生态兼容性、维护成本。

---

### L3：实现细节验证

**出题意图**：筛掉简历造假的人。考察你是否真的亲手写过代码。

| 出题规律 | 示例 |
|----------|------|
| 具体实现流程 | RAG 的 4 步具体怎么做？ |
| 技术参数的选择依据 | 向量库用的什么模型？为什么这个维度？ |
| 代码层面的实现 | ChatMemory 的 Redis/MySQL 分别存了什么？ |
| 配置文件细节 | 怎么从 Nacos 加载系统提示词？ |

**判断标准**：能说出具体的类名、方法名、配置 key、SQL 语句。这里编不了。

---

### L4：问题解决与优化

**出题意图**：筛掉只做 demo 的人。有生产级经验的人必然遇到过坑。

| 出题规律 | 示例 |
|----------|------|
| debug 经历 | AI 项目遇到了哪些问题？怎么解决的？ |
| 性能优化 | token 超限怎么处理？准确率怎么改进？ |
| 数据质量 | 知识库怎么做数据清洗？不准确的预测怎么处理？ |
| 运维问题 | 长对话 token 溢出、SSE 连接不关闭怎么排查？ |

**判断标准**：能还原问题→定位→验证的完整闭环。不是"我改了一下配置就好了"。

---

### L5：架构设计思维

**出题意图**：筛掉只会执行功能的人。考察你是否能独立设计系统。

| 出题规律 | 示例 |
|----------|------|
| 全局架构 | AI 智能体如何设计的？为什么这样分层？ |
| 组件协作 | Maxkb 和 Ollama 怎么协作？数据怎么同步？ |
| 数据流设计 | 从用户提问到 AI 回复，经过哪些环节？ |
| 设计原则 | 分层隔离（SSE vs HTTP）、降级策略、解耦设计 |

**判断标准**：能从业务目标反推架构，而不是从框架功能正推。

---

### L6：深度拓展与前瞻

**出题意图**：拉开分差。考察广度、深度、技术敏感度。

| 出题规律 | 示例 |
|----------|------|
| 业务价值 | 为什么接 AI 客服？ROI 是什么？ |
| 规模化 | 从 1000 篇扩到 10 万篇怎么处理？ |
| 模型原理 | 为什么需要微调？DDPM/DDIM 有什么区别？ |
| 前沿跟踪 | 了解 MCP 吗？Coze/Dify/FastGPT 用过吗？ |

**判断标准**：不是"我听说过"，而是能讲清楚应用场景和你的判断。

---

## 补充层次（基于 OrangeJD 项目面试题反推）

原 6 层框架来自 tjxt（教育领域 AI 项目），OrangeJD（交易平台 + AI）的项目特质暴露出原框架的不足。以下是补充的出题逻辑：

### L+1：安全与容错设计

**出题意图**：考察你是否意识到"崩了怎么办"。个人项目最容易忽略的一层。

| 出题规律 | OrangeJD 示例 |
|----------|-------------|
| 外部 URL 校验 | SSRF 防护：AI 审核调用户提交的图片 URL，怎么防止访问内网地址？ |
| 鉴权防绕过 | 趋势分析是公开端点，JWT 拦截器不生效，怎么让登录用户扣费？ |
| 接口防刷 | IP 限流怎么实现？Redis key 的 TTL 为什么恰好是限流窗口？ |
| 降级设计 | Redis 不可用时，JWT 黑名单/RAG 检索/兑换码功能怎么办？ |
| 敏感信息保护 | JWT secret、AI key 怎么存储？Swagger 在 prod 关了吗？ |

**判断标准**：不是"我加了限流"，而是能说出限流的 key 设计、TTL 选择、降级策略。

---

### L+2：数据模型设计

**出题意图**：考察你是否能在"多列 vs JSON"、"唯一索引 vs 应用层校验"之间做正确的工程决策。

| 出题规律 | OrangeJD 示例 |
|----------|-------------|
| JSON 列 vs 多列 | 榜单快照为什么用 JSON 存而不是建 20 列？ |
| 幂等键设计 | 知识库为什么用 `source_ref` 做 unique key？`owner/repo` 和 `owner/repo\|week` 怎么共存的？ |
| 软删除 vs 硬删除 | 订单为什么用状态机（CANCELLED）而不是真删？ |
| 金额类型 | 为什么所有金额用 `DECIMAL(12,2)` 而不是 `float/double`？ |

**判断标准**：能说出"当时为什么这样设计"而不是"我就这样写的"。

---

### L+3：状态机设计

**出题意图**：考察你能否处理业务流程的复杂性——订单 10 个状态、报价 5 个状态、审核 3 个状态，不是"增删改查"能解决的。

| 出题规律 | OrangeJD 示例 |
|----------|-------------|
| 状态流转规则 | 订单从 CREATED → COMPLETED 要经过哪些状态？为什么分定金和尾款两段？ |
| 状态校验 | 怎么防止已取消的订单被再次支付？是在 Service 层还是 Controller 层做的？ |
| 超时处理 | 7 天未交付的订单自动取消怎么实现？定时任务的 SQL 怎么避免全表扫描？ |
| 状态机表达方式 | 为什么用 String 常量而不是 Enum？如果重来会怎么改？ |

**判断标准**：能画出完整状态流转图，能说出每个状态转换的 guard condition。

---

### L+4：降级与容错

**出题意图**：考察你是否认识到自己项目的脆弱点并做了处理。这是"demo 项目"和"生产项目"的分界线。

| 出题规律 | OrangeJD 示例 |
|----------|-------------|
| Redis 降级 | `@Autowired(required=false)` 在哪些地方用了？为什么这样设计？ |
| AI 容错 | AI 审核图片分析失败后降级为纯文本——这个降级链是怎么实现的？ |
| READM，拉取隔离 | 榜单刷新中 README 采集失败为什么不能影响榜单数据写入？ |
| RAG 不可用降级 | Redis Stack 连不上时，趋势分析还能正常返回吗？怎么做到的？ |
| 事务边界 | 注册时 account + user_profile 怎么保证一致性？如果 profile 插入失败，account 会留下吗？ |

**判断标准**：能说出"如果 X 挂了，Y 会怎样"——不是你设计的时候全挂了跑路。

---

### L+5：产品演进与工程化

**出题意图**：考察你是否理解"好的代码是逐步长出来的，不是一次性写对的"。

| 出题规律 | OrangeJD 示例 |
|----------|-------------|
| V1→V2 演变 | 趋势分析 V1（用户自备 Key）→ V2（服务端调用+RAG），为什么这样迭代？ |
| 功能开关 | 交易模式怎么用一个 Redis key 控制全局显隐？前后端怎么联动的？ |
| 技术栈升级 | Spring Boot 2.7→3.3.5 升级经历了什么？javax→jakarta 迁移改了哪些？ |
| 充值码 → 在线支付 | 为什么先做充值码而不是直接接支付宝？两条路径怎么汇到一个 `recharge()`？ |
| RAG 开关 | 知识库增强的 `useRag` 参数怎么设计成可选的？默认值为什么是 true？ |

**判断标准**：能说出"第一版做了什么、为什么不够、第二版改了什么"。

---

## 核心洞察

1. **面试官不在乎你知道多少概念，在乎你遇到的问题有多真实。** L4（问题解决）是分水岭——能讲出具体的 bug、排查过程、修复方案，才是生产级经验的标志。

2. **"为什么这样选"比"怎么做的"更重要。** L2（技术选型）考的不是你的偏好，是你做决策的思维框架。

3. **可以不会，不能乱说。** L6 的拓展题是加分项不是扣分项。诚实说"没深入用过但了解原理"比瞎编强十倍。

4. **每个项目都有独特的出题切入点。** 参考项目的重点是多智能体路由和流式对话，你的项目的重点是 RAG 跨语言检索和知识库管理——面试官会围绕你最核心的代码路径追问。

5. **安全/容错/降级是个人项目的加分利器。** OrangeJD 项目区别于 tjxt 的最大亮点——你在一个没人指导的个人项目中，主动做了 SSRF 防护、Redis 降级、`FOR UPDATE` 并发控制、RAG 不可用自动回退。这些不是功能而是**工程意识**。

6. **状态机 + 数据模型是交易类项目的独有考题。** tjxt 偏 AI 问答，OrangeJD 偏交易闭环——面试官问订单状态机不是因为好奇，是因为这是交易系统的核心复杂点。能讲清 10 个状态的流转规则 = 证明你处理过比 CRUD 更复杂的业务。

7. **产品演进思维对初级岗是加分项、高级岗是必需项。** V1→V2 的迭代逻辑、功能开关的设计、充值码→在线支付的扩展路径——这些展示了你不是"接需求写代码"，而是"理解业务做决策"。
