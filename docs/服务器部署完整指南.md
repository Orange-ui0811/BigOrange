## 2. 全新服务器初始化

### 2.1 安装 Redis Stack

```bash
# 停掉系统自带 Redis（如有）
systemctl stop redis
systemctl disable redis

# Docker 安装 Redis Stack
docker pull redis/redis-stack-server:latest
docker run -d --name redis-stack -p 6379:6379 --restart always redis/redis-stack-server:latest

# 验证
docker ps | grep redis-stack
redis-cli PING
redis-cli MODULE LIST | grep search
```

> ⚠️ Redis Stack 必须用 Docker，原生 Redis 6.x 不支持 `FT._LIST`（RediSearch 模块），RAG 向量检索会崩溃。

### 2.2 创建数据库

```bash
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS orangejd DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

## 4. 服务器部署

### 4.1 上传文件

将 `D:\Orangejd\deploy\` 下全部文件上传到服务器 `/root/tmp/deploy/`：

- `orange-server-1.0.0-SNAPSHOT.jar`
- `schema-v1.sql`
- `orangejd_backup.sql`
- `web/`（整个文件夹）
- `admin/`（整个文件夹）

**上传方式**：
- 宝塔面板 → 文件 → `/root/tmp/deploy/` → 上传
- 或 scp：`scp -r D:/Orangejd/deploy/* root@服务器IP:/root/tmp/deploy/`

### 4.2 导入数据库

> 🔴 **关键规则：日常更新绝不能用全量导入！**
>
> `orangejd_backup.sql` 是你本机的完整数据库快照。导入它会把服务器上积累的用户数据、作品、订单**全部覆盖掉**。
>
> | 场景 | 用哪个文件 | 为什么 |
> |------|-----------|------|
> | **首次部署**（服务器是空的） | `orangejd_backup.sql` | 需要完整数据 |
> | **日常更新**（服务器有用户在用） | `schema-v1.sql` | 只加新表/字段，不影响已有数据 |
> | **新增了字段/表** | `schema-v1.sql` | `CREATE IF NOT EXISTS` + `INSERT IGNORE` 安全 |

```bash
# 首次部署：完整导入
mysql -uroot -p'密码' orangejd < /root/tmp/deploy/orangejd_backup.sql

# 日常更新：只加新表/字段（对已存在的表无影响）
mysql -uroot -p'密码' orangejd < /root/tmp/deploy/schema-v1.sql
```

> ⚠️ 如果提示 `Duplicate entry 'admin'`，忽略即可（admin 用户已存在）。

### 4.3 创建 start.sh

```bash
cat > /root/start.sh << 'EOF'
#!/bin/bash
export PATH=/www/server/java/jdk-版本号/bin:$PATH

# 数据库
export MYSQL_USER=root
export MYSQL_PASSWORD='你的MySQL密码'
export MYSQL_DB=orangejd

# Redis
export REDIS_HOST=localhost
export REDIS_PORT=6379
export REDIS_PASSWORD=''

# 文件上传路径
export UPLOAD_PATH=/root/uploads

# AI — Gitee AI（DeepSeek V4 Pro + Embedding）
export AI_AUDIT_ENDPOINT=https://ai.gitee.com/v1
export AI_AUDIT_KEY=你的GiteeAIKey
export AI_AUDIT_MODEL=DeepSeek-V4-Pro
export AI_TREND_ENDPOINT=https://ai.gitee.com/v1
export AI_TREND_KEY=你的GiteeAIKey
export AI_TREND_MODEL=DeepSeek-V4-Pro
export AI_EMBEDDING_KEY=你的GiteeAIKey
export AI_EMBEDDING_MODEL=bge-small-zh-v1.5

# 邮件 — QQ邮箱 SMTP
export MAIL_HOST=smtp.qq.com
export MAIL_PORT=587
export MAIL_USERNAME=你的QQ邮箱@qq.com
export MAIL_PASSWORD=你的QQ邮箱SMTP授权码

# Cloudflare Turnstile — 注册人机验证
export TURNSTILE_SECRET_KEY=你的TurnstileSecretKey

# JWT 密钥 — 必须随机生成
export JWT_ADMIN_SECRET=$(openssl rand -base64 48)
export JWT_APP_SECRET=$(openssl rand -base64 48)

# 飞书通知
export FEISHU_WEBHOOK_URL=你的飞书Webhook地址

java -jar /root/orange-server-1.0.0-SNAPSHOT.jar --spring.profiles.active=prod
EOF
chmod +x /root/start.sh
```

### 4.4 替换文件

```bash
# 后端
pkill -9 -f orange-server
\cp -f /root/tmp/deploy/orange-server-1.0.0-SNAPSHOT.jar /root/

# 前端
rm -rf /data/www/orangejd/web/*
cp -r /root/tmp/deploy/web/* /data/www/orangejd/web/
rm -rf /data/www/orangejd/admin/*
cp -r /root/tmp/deploy/admin/* /data/www/orangejd/admin/

# 创建上传目录
mkdir -p /root/uploads/{cover,detail,avatar}
chmod -R 755 /root /root/uploads

# ⚠️ 日常更新不要执行下面这行！只在首次部署或确定要覆盖服务器数据时使用
# mysql -uroot -p'密码' orangejd < /root/tmp/deploy/orangejd_backup.sql
```

### 4.5 启动

```bash
nohup /root/start.sh > /root/app.log 2>&1 &
sleep 25
curl http://127.0.0.1:8080/health
```

返回 `{"status":"UP"}` 即成功。

## 5. Nginx 配置

### 5.1 完整站点配置

```nginx
server {
    listen 80;
    server_name 你的IP或域名;
    root /data/www/orangejd/web;

    # 前端 SPA
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 300s;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # WebSocket
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 管理后台
    location ^~ /admin {
        alias /data/www/orangejd/admin;
        index index.html;
        try_files $uri /admin/index.html;
    }

    # 上传文件 — 必须用 ^~ 覆盖正则
    location ^~ /uploads/ {
        alias /root/uploads/;
    }
}
```

### 5.2 关键坑

- **`/uploads/` 必须加 `^~`**：Nginx 的图片正则 `~ .*\.(png)$` 优先级高于普通前缀 `/uploads/`，不加 `^~` 的话图片请求被正则拦截 → 404
- **`/root` 目录必须有其他用户读权限**：`chmod 755 /root`，否则 Nginx（nginx 用户）无法读取 `/root/uploads/`

## 7. 换 AI 大模型

当前模型通过配置文件指定，修改 `application-prod.yml` 或 start.sh 环境变量即可：

```bash
# start.sh 中修改这些变量：
export AI_AUDIT_MODEL=新模型名       # 审核用
export AI_TREND_MODEL=新模型名       # 趋势分析 + 榜单翻译用
export AI_EMBEDDING_MODEL=新模型名   # RAG 向量化用

# 如果接口地址变了：
export AI_AUDIT_ENDPOINT=新的API地址
export AI_TREND_ENDPOINT=新的API地址
export AI_EMBEDDING_ENDPOINT=新的API地址
```

重启后端即生效，无需重新打包。

## 8. 常见问题排查

### 8.1 后端启动失败

```bash
# 查看日志
tail -100 /root/app.log

# 常见错误
# "JavaMailSender bean not found" → start.sh 缺少 MAIL_USERNAME/MAIL_PASSWORD
# "FT._LIST unknown command" → Redis 不是 Stack 版本
# "Table doesn't exist" → 数据库没导入 schema-v1.sql
# "JedisConnectionFactory destroyed" → 其他错误导致的连锁关闭，查前面的错误
```

### 8.2 图片上传/显示失败

```bash
# 1. 检查目录权限
ls -la /root/uploads/
chmod -R 755 /root/uploads && chmod 755 /root

# 2. 检查 Nginx 配置：/uploads/ 前是否有 ^~
grep -A2 "uploads" /www/server/panel/vhost/nginx/你的IP.conf

# 3. 测试文件是否可访问
curl -s -o /dev/null -w '%{http_code}' http://你的IP/uploads/cover/任意文件.png
# 200 = 正常，403 = 权限，404 = Nginx 路由问题
```

### 8.3 前端更新不生效

```bash
# 清浏览器缓存，或强制刷新 Ctrl+Shift+R
# 确认文件已复制到正确位置
ls /data/www/orangejd/web/index.html
ls /data/www/orangejd/admin/index.html
```

### 8.4 榜单内容一直显示英文

周一凌晨 2:00 自动爬取 + 翻译。翻译只在每周一触发一次。其他时间不做翻译。
