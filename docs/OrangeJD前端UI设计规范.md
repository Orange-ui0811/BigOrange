# OrangeJD 前端 UI 设计规范

> 版本：v0.1  
> 适用范围：OrangeJD 用户端 `orange-web` 与管理端 `orange-admin`  
> 技术栈：Vue 3 + Vite + Element Plus  
> 目标：先形成可复用设计系统与样板页方向，暂不直接修改项目代码

---

## 1. 产品视觉定位

OrangeJD 是一个面向 vibe coding 创作者与需求方的平台，核心场景包括作品展示、源码/使用权/部署服务交易、需求定制接单、聊天协商、审核与后台运营。

整体视觉方向：

- 用户端：创作者集市、温暖橙色、轻像素品牌元素、可信交易感。
- 管理端：清晰、高效、审核工作台、数据看板。
- 品牌记忆：橙色、像素橙子、代码/创作/交易三类视觉语义。
- 设计原则：用户端有氛围，管理端重效率；不要把两端做成同一种后台模板风格。

不建议的方向：

- 不要整站大面积高饱和橙色。
- 不要把像素风做成厚重卡通风。
- 不要只改颜色，不重构信息层级。
- 不要在管理端加入过多装饰，影响审核效率。

## 2. 色彩系统

### 2.1 品牌主色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 品牌橙 | `#F37021` | 主按钮、品牌强调、激活态 |
| 深橙强调 | `#EA580C` | CTA hover、价格、重要操作 |
| 奶油背景 | `#FFF7ED` | 用户端页面背景 |
| 浅橙背景 | `#FFEDD5` | 标签背景、浅强调区 |
| 浅橙边框 | `#FED7AA` | 卡片边框、输入框 focus 弱边框 |

### 2.2 中性色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 卡片白 | `#FFFFFF` | 卡片、表单、弹窗 |
| 正文深灰 | `#1F2937` | 主文本 |
| 次级文本 | `#6B7280` | 描述、辅助信息 |
| 弱文本 | `#9CA3AF` | 占位、说明、次要时间 |
| 页面边框 | `#E5E7EB` | 分割线、表格线 |
| 后台背景 | `#F8FAFC` | 管理端页面背景 |

### 2.3 状态色

| 状态 | 色值 | 用途 |
| --- | --- | --- |
| 成功绿 | `#16A34A` | 已通过、已完成、支付成功 |
| 警告黄 | `#F59E0B` | 审核中、待处理、风险提示 |
| 危险红 | `#DC2626` | 已拒绝、删除、下架、支付失败 |
| 信息蓝 | `#2563EB` | 链接、系统通知、辅助说明 |

### 2.4 使用规则

- 主按钮只使用品牌橙或深橙强调。
- 用户端背景优先使用奶油暖橙，不使用纯白大背景。
- 管理端背景使用冷静浅灰，橙色只用于强调和主操作。
- 状态色必须固定，不允许同一状态在不同页面使用不同颜色。
- 文本对比度要满足 WCAG AA，普通正文至少 4.5:1。

## 3. 字体与排版

### 3.1 字体建议

| 场景 | 字体 |
| --- | --- |
| 品牌 Logo / 技术感标题 | Fira Code 或 JetBrains Mono |
| 中文正文 / 表单 / 后台 | Noto Sans SC 或 Fira Sans |
| 价格 / 数字 / 数据看板 | 使用 tabular-nums 等宽数字特性 |

### 3.2 字号层级

| 层级 | 桌面端 | 移动端 | 用途 |
| --- | --- | --- | --- |
| H1 | 40-48px | 28-32px | 首页主标题 |
| H2 | 28-32px | 24px | 分区标题 |
| H3 | 20-24px | 18-20px | 卡片/详情标题 |
| Body | 16px | 16px | 正文 |
| Small | 14px | 14px | 描述、标签 |
| Caption | 12px | 12px | 时间、弱提示 |

### 3.3 排版规则

- 正文行高建议 `1.6`。
- 卡片标题最多两行，超出显示省略号。
- 详情页长文本最大宽度控制在 720px 左右。
- 价格和订单金额使用更强字重，但不要过度放大。
- 后台表格正文以 14px 为主，避免过密。

## 4. 间距与布局

### 4.1 间距系统

使用 4px / 8px 作为基础单位。

| Token | 值 | 用途 |
| --- | --- | --- |
| `space-1` | 4px | 极小间距 |
| `space-2` | 8px | 图标与文字间距 |
| `space-3` | 12px | 表单内部间距 |
| `space-4` | 16px | 常规组件间距 |
| `space-5` | 20px | 卡片内边距 |
| `space-6` | 24px | 页面模块间距 |
| `space-8` | 32px | 区块间距 |
| `space-12` | 48px | 大区块间距 |
| `space-16` | 64px | 首页视觉区块间距 |

### 4.2 页面容器

- 用户端桌面最大内容宽度：`1200px - 1280px`。
- 管理端内容区跟随布局，不做过窄居中。
- 用户端页面左右留白：移动端 16px，平板 24px，桌面 40px 以上。
- 管理端页面留白：24px 为主，表格页可以 20px。

---

## 5. 组件规范

### 5.1 卡片

用户端卡片：

- 白底，16px 圆角。
- 轻阴影，避免厚重立体效果。
- 可使用浅橙色像素角标或顶部细线增强品牌感。
- 作品卡片必须包含封面、标题、作者、类型、价格/预算、收藏数、状态。

管理端卡片：

- 白底，12px 圆角。
- 边框优先于阴影。
- 指标卡突出数字和趋势，不使用过多插画。

### 5.2 按钮

| 类型 | 样式 | 用途 |
| --- | --- | --- |
| 主按钮 | 橙色实心、白字 | 发布、想要、提交、通过 |
| 次按钮 | 白底、橙色文字/边框 | 收藏、取消、次要跳转 |
| 文字按钮 | 无边框 | 查看详情、更多 |
| 危险按钮 | 红色或红色文字 | 删除、拒绝、下架 |

规则：

- 每个页面只保留一个视觉最强的主 CTA。
- 按钮最小高度：桌面 36px，移动端 44px。
- 异步操作必须有 loading 状态。
- 删除/拒绝等危险操作必须二次确认。

### 5.3 表单

- 输入框必须有可见 label，不只依赖 placeholder。
- 错误提示显示在对应字段下方。
- 长表单需要分组，例如“基础信息 / 售卖方式 / 演示链接 / 交付说明”。
- 发布作品/需求页面建议支持草稿保存。
- 密码输入框提供显示/隐藏切换。

### 5.4 标签

状态标签固定语义：

| 状态 | 建议样式 |
| --- | --- |
| 草稿 | 灰色 |
| 审核中 | 黄色 |
| 已通过 | 绿色 |
| 已拒绝 | 红色 |
| 已下架 | 灰黑色 |
| 交易中 | 蓝色 |
| 已完成 | 绿色 |
| 待支付 | 橙色 |

类型标签：

- 作品类型、技术栈、交易方式使用浅橙或浅灰胶囊标签。
- 技术栈标签不要过多抢占主标题。

### 5.5 列表

用户端：

- 作品/需求优先使用卡片网格。
- 支持筛选、排序、分页。
- 列表空状态必须给下一步操作，例如“去发布第一个作品”。

管理端：

- 审核、用户、订单使用表格。
- 表格必须支持状态筛选、关键字搜索、分页。
- 审核场景建议支持多选和批量操作。
- 表格在移动端可改为卡片列表或横向滚动。

## 6. 用户端样板页方案

### 6.1 首页 / 作品广场

目标：让用户快速发现作品、需求，并理解平台是一个可信的创作者交易集市。

页面结构：

1. 顶部导航：Logo、作品、需求、榜单/AI、消息、发布按钮、头像。
2. Hero 区：一句话定位 + 大搜索框 + 热门搜索词。
3. 切换区：作品 / 需求双 Tab。
4. 分类筛选：技术方向、交易方式、价格区间、排序。
5. Featured 区：精选作品、热门需求或推荐创作者。
6. 卡片列表：作品卡片/需求卡片网格。
7. 信任区：交易保障、审核机制、定金/尾款说明。

视觉重点：

- 背景使用奶油暖橙渐变。
- 搜索框是首屏最重要 CTA。
- 卡片用白底轻阴影，让作品封面成为视觉主角。
- 像素橙子只作为品牌点缀，不要铺满页面。

### 6.2 作品详情页

目标：让需求方快速判断作品价值，并自然进入聊天/购买/定制。

页面结构：

1. 顶部返回与面包屑。
2. 左侧主内容：封面、演示图/视频、作品介绍、技术栈、交付内容、评论。
3. 右侧交易栏：作者卡片、售卖方式、价格、想要/聊天按钮、收藏按钮。
4. 保障说明：源码、使用权、部署服务分别说明。
5. 推荐区：同类作品或作者其他作品。

交易方式展示：

- 源码：适合开发者接手二次开发。
- 使用权：适合快速使用产品能力。
- 部署服务：适合商家直接上线。

移动端规则：

- 详情内容单列。
- 底部固定 CTA：想要 / 聊天 / 收藏。
- 交易栏折叠为底部抽屉。

---

## 7. 管理端样板页方案

### 7.1 审核工作台

目标：帮助管理员高效处理作品、需求、评论、岗位等审核任务。

页面结构：

1. 顶部统计卡：待审核作品、待审核需求、今日通过、今日拒绝、风险项。
2. 筛选区：内容类型、审核状态、分类、关键词、时间范围。
3. 主表格：封面/标题、作者、类型、提交时间、风险提示、状态、操作。
4. 右侧详情抽屉：完整内容、图片、链接、AI 审核建议、人工审核操作。
5. 批量操作栏：批量通过、批量拒绝、导出。

交互规则：

- 点击行打开详情抽屉，不强制跳新页面。
- 通过/拒绝必须保留审核理由。
- 拒绝操作要提供常用理由模板。
- 高风险内容用警告标签，但不要只靠颜色表达。

视觉规则：

- 管理端背景使用浅灰。
- 表格密度中等，避免太松散。
- 橙色只用于主要操作，不作为大面积背景。
- 数据看板可使用橙色、蓝色、绿色搭配，但保持克制。

---

## 8. 后台表格规范

表格基础：

- 表头固定在滚动区域顶部。
- 重要字段靠左，状态和操作靠右。
- 操作列不超过 3 个直接按钮，其余放入更多菜单。
- 支持空状态、加载状态、错误状态。

筛选规则：

- 常用筛选直接展示。
- 高级筛选折叠。
- 筛选条件改变后保留在 URL query，方便刷新和分享。

移动端：

- 审核后台如需要移动端支持，表格转卡片。
- 卡片必须保留标题、状态、提交人、时间、主操作。

---

## 9. 移动端规则

断点建议：

| 设备 | 宽度 |
| --- | --- |
| 小手机 | 375px |
| 手机 | 430px |
| 平板 | 768px |
| 小桌面 | 1024px |
| 桌面 | 1440px |

规则：

- 移动端优先保证搜索、筛选、列表、详情 CTA。
- 不允许出现横向滚动，除后台表格特殊容器外。
- 触控目标至少 44px 高。
- 移动端正文不小于 16px。
- 固定底部按钮不能遮挡内容，需要预留安全区。

---

## 10. 动效规则

- 动效只服务于层级、反馈和状态变化。
- 常规 hover / active：150-200ms。
- 页面模块进入：200-300ms。
- 避免超过 500ms 的慢动画。
- 优先使用 `opacity` 和 `transform`，避免动画影响布局。
- 支持 `prefers-reduced-motion`，用户关闭动效时应降级。

---

## 11. 可访问性与质量检查

上线前检查：

- 所有按钮和图标按钮有可理解文本或 aria-label。
- 键盘 Tab 顺序符合视觉顺序。
- focus 状态清晰可见。
- 文本对比度满足 4.5:1。
- 表单错误提示靠近字段。
- 颜色不是唯一的信息表达方式。
- 图片有合理 alt。
- 列表加载使用骨架屏或明确 loading。

---

## 12. 落地建议

第一批重构页面：

1. 用户端登录/注册页。
2. 用户端首页 / 作品广场。
3. 用户端作品详情页。
4. 管理端审核工作台。

落地顺序：

1. 先把颜色、字体、间距抽成 CSS 变量。
2. 再建立通用卡片、标签、按钮、空状态规范。
3. 然后重构 3 个样板页。
4. 样板页稳定后，再批量推广到其他页面。

不要一开始全站同时改，否则容易风格失控，也难以回归测试。
