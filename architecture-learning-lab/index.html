                Maven 模块边界

                为什么 server、common、pojo 不放在同一个目录

                orange-commonResult、JWT、上下文、公共工具普通 jar
                orange-pojoEntity、DTO、VO、校验模型普通 jar
                编译依赖进入
                orange-serverController、Service、Mapper、Redis、AI、任务与启动类Spring Boot 可执行 jar

                它不是微服务

                根 pom 同时构建三个模块，server 依赖 common 和 pojo。部署时仍然只有一个 Spring Boot 进程。

                为什么值得分开

                编译依赖只能从 server 指向通用模块，避免模型和公共契约反向依赖 Web、数据库和 AI 基础设施。

                当前真实边界

                common 仍依赖 Spring、JWT、POI 和 Jackson，因此它是项目公共模块，不是完全无框架的纯领域核心。

                故障与容量推演

                组件坏掉后，系统到底怎样

                选择一个事故场景，区分受影响能力、仍能工作的部分、第一排查入口和真正值得做的扩展。

                理解自检

                把概念落回代码和状态

                答题后阅读解释。真正的完成标准是能从问题指出对应组件、表、失败路径和源码。
